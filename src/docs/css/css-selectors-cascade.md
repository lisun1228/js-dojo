## Q6 · 选择器的分类与写法

> 合并原题：30（CSS 选择器有哪些？哪些属性可以继承？——本体只答选择器部分，继承见 Q4）

**一句话答案**：CSS 选择器分五类——基础选择器（通配、标签、类、ID、属性）、组合选择器（后代、子代、相邻兄弟、通用兄弟）、伪类、伪元素、以及逻辑/关系型选择器（`:not`、`:is`、`:where`、`:has`）。日常写得最多的是类选择器和后代/子代组合。

### 答题思路

1. 按"五大类"过一遍，每类给 1–2 个例子即可，不要背全表。
2. 重点展示 CSS3 之后的新选择器（属性选择器、`:has`、`:where`），这部分能体现知识更新。
3. 结尾落到工程实践：为什么项目里主要用类选择器 + BEM。

### 核心要点

**1. 基础选择器**

```css
*            /* 通配，优先级 0，性能敏感场景慎用 */
div          /* 标签/类型选择器 */
.card        /* 类选择器，最常用 */
#header      /* ID 选择器，权重高，样式层不建议用 */
[type="text"]         /* 属性选择器 */
a[href^="https"]      /* 前缀 */
a[href$=".pdf"]       /* 后缀 */
a[href*="example"]    /* 包含 */
[class~="btn"]        /* 词列表包含 */
[lang|="zh"]          /* 等于或以 zh- 开头 */
```

**2. 组合选择器**

```css
.a .b     /* 后代，含任意层级 */
.a > .b   /* 子代，仅直接子元素 */
.a + .b   /* 相邻兄弟，紧邻的下一个 */
.a ~ .b   /* 通用兄弟，后面所有同级 */
.a.b      /* 交集：同时有 a 和 b 两个类 */
```

**3. 伪类**（状态/结构/逻辑）：`:hover`、`:focus`、`:active`、`:visited`、`:first-child`、`:nth-child(2n+1)`、`:not()`、`:is()`、`:where()`、`:has()`、`:checked`、`:disabled`、`:root`、`:empty`

**4. 伪元素**：`::before`、`::after`、`::first-line`、`::first-letter`、`::selection`、`::placeholder`、`::marker`、`::file-selector-button`

**5. 关系型新选择器（加分项）**

```css
/* :has() 反向选择：有图片的卡片 */
.card:has(img) { padding: 0; }
/* :where() 优先级恒为 0，适合写可被覆盖的基础样式 */
:where(h1, h2, h3) { margin-block: 0; }
/* :is() 取参数中最高优先级 */
:is(#app, .app) .title { color: #333; }
```

- `:where()` 与 `:is()` 的唯一区别就是**优先级**：`:where()` 恒为 0，`:is()` 取括号内最高值。写设计系统/重置样式用 `:where()`，业务覆盖时才不会被卡住。
- 性能提示：选择器匹配是**从右往左**的，最右侧的"关键选择器"越具体越好。`div.container ul li a` 这种写法会先匹配所有 `a` 再逐层回溯，比 `.container a` 慢；`*` 在深层结构里尤其贵。现代浏览器的样式匹配已经很快，性能问题主要出现在超大 DOM（几千个节点）上，面试按这个口径回答即可。

### 口述回答（约 60 秒）

> 我会分五类来说。
>
> 第一类是基础选择器：通配符、标签、类、ID，还有属性选择器，属性选择器支持 `^` 开头、`$` 结尾、`*` 包含这几种匹配。
>
> 第二类是组合选择器：后代用空格，子代用 `>`，相邻兄弟用 `+`，通用兄弟用 `~`，还有两个类写在一起表示"同时具备"。
>
> 第三类是伪类，描述状态或者结构位置，比如 hover、focus、`nth-child`。
>
> 第四类是伪元素，用来生成或选中虚拟的部分，比如 `::before`、`::after`、`::selection`。
>
> 第五类是 CSS3 之后的关系型选择器：`:not`、`:is`、`:where`、`:has`。`:has` 是"父选择器"，可以按子元素反向选父级，比如卡片里有图片就改内边距；`:where` 的优先级恒为 0，适合写基础样式，方便业务覆盖。
>
> 工程上我们主要用类选择器配合 BEM 命名，尽量不用 ID 和标签选择器写样式，把优先级压在同一个层级，避免后面要靠 `!important` 打架。

### 可能被追问

| 追问 | 回答要点 |
|---|---|
| `:is()` 和 `:where()` 的区别？ | 优先级不同，`:where()` 恒为 0；功能一致 |
| `:has()` 兼容性如何？ | Chrome/Safari/Firefox 新版本均已支持（2023 年起全面可用），老项目需降级 |
| 选择器是从左往右还是从右往左匹配？ | 从右往左，所以最右侧关键选择器决定匹配成本 |
| `nth-child` 和 `nth-of-type` 区别？ | 前者按所有同级元素排序，后者按同类型标签排序 |
| `+` 和 `~` 区别？ | `+` 只匹配紧邻的下一个兄弟，`~` 匹配后面所有同级兄弟 |
| 后代选择器和子代选择器的性能差异？ | 子代少一层回溯，理论上更快，但实际差异可忽略；用哪个取决于语义 |

## Q7 · 选择器优先级与权重计算

> 合并原题：13（选择器优先级）、27（优先级怎么排）、35（同 13）

**一句话答案**：优先级是一个四元组 `(行内, ID, 类/属性/伪类, 标签/伪元素)`，逐位比较、不进位；`!important` 单独一档，高于所有普通声明；权重相同时后声明的覆盖先声明的（同源顺序）。

### 答题思路

1. 背出四元组，强调"逐位比较、不进位"——这是最常见的错误点（很多人以为 11 个类等于 1 个 ID）。
2. 说明两个例外：`!important` 和 `@layer`。
3. 说明"同权重看顺序"，以及继承来的值优先级最低。
4. 给工程建议：把优先级压平（BEM / CSS Modules / `:where()`），避免层层加码。

### 核心要点

**四元组 `(a, b, c, d)`**

| 位置 | 含义 | 示例 | 权重 |
|---|---|---|---|
| a | 行内样式 | `style="color:red"` | (1,0,0,0) |
| b | ID 选择器 | `#app` | (0,1,0,0) |
| c | 类、属性选择器、伪类 | `.btn`、`[type=text]`、`:hover` | (0,0,1,0) |
| d | 标签、伪元素 | `div`、`::before` | (0,0,0,1) |
| — | 通配符、组合符 | `*`、`>`、`+`、`~` | (0,0,0,0) |

比较规则：**从左到右逐位比，某一位大的直接胜出，永不进位**。

```css
/* (0,1,0,0) */
#nav .item { }
/* (0,0,2,0) —— 输给上面那个，因为 b 位 0 < 1 */
.nav .item { }
/* (0,0,1,1) */
.item a { }
/* 10 个类 != 1 个 ID： (0,0,10,0) 仍然输给 (0,1,0,0) */
```

**同权重的处理**：后写的覆盖先写的（同一个样式表内按源码顺序；多个样式表按引入顺序）。

**`!important`**：不是第五位，而是独立的更高一档。两个 `!important` 之间再按四元组比较；`!important` 只有另一个 `!important`（或用户样式的 `!important`）能覆盖。

**层叠优先级总序（从高到低）**

1. 用户代理 `!important`（浏览器默认，实际极少用）
2. 用户样式 `!important`
3. 作者样式 `!important`
4. 动画（`@keyframes` 中的声明）
5. 作者普通样式（行内 > ID > 类 > 标签）
6. 用户普通样式
7. 用户代理普通样式
8. 继承值 / 初始值（不进比较）

**现代补充：`@layer` 层叠层**

```css
@layer reset, base, components, utilities;
/* 后声明的层优先级更高；未分层的样式优先级高于所有分层 */
```

在 `@layer` 里，层与层之间的顺序优先于选择器权重——这一条常用于设计系统，彻底摆脱 `!important` 军备竞赛。

**几个反直觉的点**

- `:not()`、`:is()`、`:has()` 内部取**参数中最高权重**参与计算；`:where()` 恒为 0。
- 继承来的值权重为"无"，`*` 都能覆盖它。
- 内联 `style` 的权重高于任何选择器，但低于 `!important`。
- `!important` 在 `@keyframes` 内无效（动画声明本身处于更高层级）。

### 口述回答（约 75 秒）

> 优先级我用四元组来记：行内样式、ID 个数、类和伪类及属性选择器的个数、标签和伪元素的个数。比较的时候从左往右逐位比，某一位大的直接赢，**不进位**——所以十个类选择器也打不过一个 ID，这一点很多人记错。
>
> 举几个例子：`#nav .item` 是 (0,1,0,0)，`.nav .item` 是 (0,0,2,0)，前者赢；`.item a` 是 (0,0,1,1)，还是输给 `#nav .item`。权重完全一样的时候，后写的覆盖先写的。通配符和 `>`、`+` 这类组合符不贡献权重。
>
> `!important` 不在这四位里，它是单独的一档，比所有普通声明都高，只有另一个 `!important` 才能覆盖。实际排序是：作者 `!important` > 动画里的声明 > 作者普通样式 > 用户样式 > 浏览器默认。
>
> 另外现在有了 `@layer`，层与层之间的顺序优先于选择器权重，写设计系统时用它可以把优先级彻底管住，不用再堆 `!important`。
>
> 项目里我的做法是把优先级压平：统一用类选择器、BEM 命名，组件库用 `:where()` 包一层把权重归零，这样业务侧永远能覆盖。

### 可能被追问

| 追问 | 回答要点 |
|---|---|
| `:not(.a)` 的权重是多少？ | 括号内选择器的权重，即 (0,0,1,0)；`:not()` 本身不额外加权重 |
| 行内样式能覆盖 ID 选择器吗？ | 能，(1,0,0,0) > (0,1,0,0)；但删不掉 `!important` |
| 同权重同顺序的样式谁生效？ | 后加载的样式表里后出现的声明生效 |
| 为什么 `!important` 不好？ | 破坏层叠模型，只能靠更多 `!important` 覆盖，形成军备竞赛；用 `@layer` 或 `:where()` 更可控 |
| `@import` 引入的样式优先级？ | 位置决定顺序，`@import` 必须在样式表最前面；引入内容按插入位置参与层叠 |
| 伪元素和伪类的权重一样吗？ | 不一样，伪类算 c 位，伪元素算 d 位 |
| 动画（`@keyframes`）和 `!important` 谁赢？ | `!important` 声明赢（作者 `!important` 位于动画之上） |

## Q8 · 伪类与伪元素

> 合并原题：11

**一句话答案**：伪类（单冒号）用于选中处于某种**状态或结构位置**的真实元素，比如 `:hover`、`:first-child`；伪元素（双冒号）用于创建或选中**原本不存在的虚拟元素/片段**，比如 `::before`、`::first-line`。CSS3 用双冒号区分二者，为兼容 IE8 部分伪元素仍可写单冒号。

### 答题思路

1. 一句话讲本质区别：伪类是"选元素"，伪元素是"造盒子/选片段"。
2. 各给 3–5 个常用例子。
3. 讲 `::before` / `::after` 的三个必答点：必须有 `content`、默认是行内元素、不可被 JS 选中操作（能通过 `getComputedStyle(el, '::before')` 读样式）。
4. 讲优先级差异（伪类 (0,0,1,0)，伪元素 (0,0,0,1)）和 `:hover` 顺序（LVHA）。

### 核心要点

**伪类分类**

| 类别 | 例子 |
|---|---|
| 交互状态 | `:hover`、`:active`、`:focus`、`:focus-visible`、`:focus-within`、`:visited`、`:link` |
| 结构位置 | `:first-child`、`:last-child`、`:nth-child(n)`、`:nth-of-type(n)`、`:only-child`、`:empty`、`:root` |
| 表单状态 | `:checked`、`:disabled`、`:enabled`、`:required`、`:valid`、`:invalid`、`:placeholder-shown` |
| 逻辑组合 | `:not()`、`:is()`、`:where()`、`:has()` |
| 其他 | `:target`、`:lang()`、`:scope`、`:defined` |

**伪元素分类**

| 伪元素 | 作用 |
|---|---|
| `::before` / `::after` | 在元素内容前后插入生成内容，**必须写 `content`**（哪怕是空字符串） |
| `::first-line` / `::first-letter` | 选中首行/首字母（只能用于块级容器） |
| `::selection` | 选中文本时的高亮样式 |
| `::placeholder` | 表单占位符 |
| `::marker` | 列表项符号 |
| `::file-selector-button` | 文件上传按钮 |
| `::backdrop` | dialog / 全屏元素的背景层 |

**必答细节**

- `::before` / `::after` 的默认 `display` 是 `inline`，做图标/遮罩要显式设 `display: block` 或 `inline-block`，或给宽高。
- 生成的伪元素**不在 DOM 里**，JS 无法 `querySelector` 到，但可以用 `window.getComputedStyle(el, '::before').content` 读取。
- 图片、`input`、`img`、`br` 等**替换元素不支持 `::before`/`::after`**（它们没有内容盒，无法插入生成内容）。
- 伪元素上可以继续加伪类：`.btn:hover::after { }`。
- 优先级：伪类算 c 位（类级），伪元素算 d 位（标签级）。

**LVHA 顺序**：`:link` → `:visited` → `:hover` → `:focus` → `:active`。写反了会被后面的同权重规则覆盖（都打在同一元素上时，后写优先）。

**伪类的常见用途（体现工程经验）**

```css
/* 表单校验反馈 */
input:invalid:not(:placeholder-shown) { border-color: #e5484d; }

/* 容器内任意子元素聚焦时高亮整卡 */
.card:focus-within { box-shadow: 0 0 0 2px #4c8dff; }

/* 列表项之间加分隔线（不污染第一个） */
li + li::before { content: '·'; margin: 0 8px; }
```

### 口述回答（约 70 秒）

> 本质区别一句话：伪类是"选中处于某种状态的真实元素"，伪元素是"造出一个本来不存在的盒子"或者"选中元素的一部分"。
>
> 伪类常用的有三组：交互状态，像 hover、active、focus；结构位置，像 first-child、nth-child、nth-of-type；表单状态，像 checked、disabled、placeholder-shown。还有逻辑型的 not、is、where、has。
>
> 伪元素常用的是 `::before` 和 `::after`，用来插入生成内容，必须写 `content`，哪怕写空字符串；它们的默认 display 是 inline，所以要设宽高得先改成 block 或者 inline-block。另外 img、input 这类替换元素是不支持 before/after 的。还有 `::first-line`、`::first-letter`、`::selection`、`::marker` 这些选片段的。
>
> 写法上 CSS3 规定伪类单冒号、伪元素双冒号，为了兼容 IE8，before/after 这些还能写单冒号。优先级上伪类算类级别，伪元素算标签级别，所以 `::before` 的权重比 `:hover` 低。
>
> 实际用得比较多的是用伪元素做清除浮动、做小图标、做分隔线，不需要额外标签；用 `:focus-within` 做表单聚焦整块高亮。

### 可能被追问

| 追问 | 回答要点 |
|---|---|
| 伪元素能被 JS 选中吗？ | 不能进 DOM，`querySelector` 拿不到；只能用 `getComputedStyle(el,'::before')` 读样式 |
| `content` 能放变量吗？ | 能，`content: attr(data-label)` 或 `content: counter(x)`，CSS 变量需 `content: var(--x)`（部分浏览器限制） |
| 为什么 `:hover` 要给 `.btn:hover` 而不是 `:hover`？ | 后者会命中所有 hover 元素，性能和语义都不对 |
| `::first-line` 为什么有时不生效？ | 只能用于块级容器，且内部有行内块/图片时表现受限 |
| `:visited` 能改什么样式？ | 出于隐私限制，只能改颜色类属性（color/background-color/border-color 等），且 `getComputedStyle` 会返回未访问状态的值 |
| `::before` 能加动画吗？ | 可以，伪元素可正常应用 transition/animation |
| `:nth-child(2n+1)` 和 `:nth-child(odd)`？ | 等价；`an+b` 形式还支持 `:nth-child(-n+3)` 取前三个 |

## Q9 · 层叠上下文、层叠顺序与 z-index

> 合并原题：20（哪些属性会创建层叠上下文）、21（层叠上下文与层叠顺序）、28（对 z-index 的理解）、29（对层叠上下文的理解）、48（元素的层叠顺序）

**一句话答案**：层叠上下文是一个独立的 3D 层级，内部元素的 `z-index` 只在**同一个上下文内**比较；页面从底到顶的绘制顺序是：背景边框 → 负 z-index → 块级 → 浮动 → 行内 → `z-index: 0/auto` 的定位元素 → 正 z-index。`z-index` 只在定位元素或 flex/grid 子项上生效。

### 答题思路

1. 先定义层叠上下文（独立层级 + 隔离）。
2. 列出创建条件（能说 6–8 个就够，重点：根元素、定位 + z-index、opacity < 1、transform、flex 子项、isolation）。
3. 背出 7 层层叠顺序。
4. **必须讲失效场景**——这是本题唯一的实战价值：父级层叠上下文把子元素"锁死"，子元素 `z-index: 9999` 也压不过父级之外的兄弟。
5. 给解法：提升父级、去掉父级上下文、`isolation: isolate` 显式隔离。

### 核心要点

**定义**：层叠上下文（stacking context）是 HTML 元素按 3D 层级排列的独立区域。上下文内部的元素再怎么设置 `z-index`，都不能跑到上下文的"外部兄弟"之上——这就是常说的**层叠上下文隔离**。

**创建条件（记忆版）**

| 类别 | 具体条件 |
|---|---|
| 根 | `html` 元素（根层叠上下文） |
| 定位 + z-index | `position` 为 `relative/absolute` 且 `z-index` 不为 `auto` |
| 固定/粘性 | `position: fixed` / `sticky`（新规范下即使 `z-index: auto` 也创建） |
| Flex/Grid 子项 | 父级是 flex/grid 容器，且子项 `z-index` 不为 `auto` |
| 透明度 | `opacity` < 1 |
| 变换/滤镜 | `transform`、`filter`、`perspective`、`backdrop-filter`、`clip-path` 不为 `none` |
| 隔离 | `isolation: isolate` |
| 混合模式 | `mix-blend-mode` 不为 `normal` |
| 性能相关 | `will-change` 指定了上述任一属性；`contain: layout` / `paint` / `content` |
| 其他 | `-webkit-overflow-scrolling: touch`（iOS） |

**层叠顺序（从下到上，7 层）**

1. 层叠上下文的**背景和边框**（该元素自身的）
2. **负 z-index** 的子元素（`z-index: -1` 等）
3. **块级**（非定位）子元素
4. **浮动**元素
5. **行内**（inline）子元素
6. `z-index: 0 / auto` 的**定位**元素
7. **正 z-index** 的子元素（按数值，大的在上；同值后写在上）

关键结论：**定位元素的 z-index 是 0 时，也在普通行内元素之上**；而**负 z-index 会沉到父级背景之上、父级内容之下**，所以常被用来做背景层。

**z-index 生效条件**

- 元素必须是**定位元素**（`position` 非 `static`），或 flex/grid 容器的子项。
- `z-index` 支持负值和 `auto`；`auto` 表示"不创建新上下文、与父级同层参与排序"。

**z-index 失效排查清单（工程师视角，很有说服力）**

1. 元素没定位 → 加 `position: relative`。
2. 祖先创建了层叠上下文（`opacity`、`transform`、`filter`、`will-change` 最常见）→ 子元素被锁在祖先内部，需提升**祖先**的 z-index。
3. 兄弟元素的父级层级不同 → 比较的是**祖先**的 z-index，不是自己的。
4. 父级 `overflow: hidden` → 超出部分被裁剪，看起来像被盖住。
5. `z-index` 写在 flex 子项上但父级不是 flex 容器。
6. 有 `!important` 或层叠层（`@layer`）参与，权重被别的规则覆盖。

```css
/* 典型修复：不要给子元素加 z-index，而是提升祖先 */
.modal-wrapper { position: relative; z-index: 100; }
```

### 口述回答（约 90 秒）

> 层叠上下文可以理解成一个独立的 3D 层，页面是由很多这样的层组成的树。核心规则是：`z-index` 只在同一个层叠上下文内部比较，子元素设置再大的 z-index，也压不过父级上下文外面的兄弟元素。
>
> 创建层叠上下文的条件我一般记这几类：根元素 html；定位元素并且 z-index 不是 auto；fixed 和 sticky 即使 z-index 是 auto 也会创建；flex 或 grid 的子项设了 z-index；opacity 小于 1；有 transform、filter、perspective、backdrop-filter 这些；还有 isolation: isolate、mix-blend-mode、contain 这些比较偏的。日常最容易踩的是给元素加了一个 `transform` 或者 `opacity: 0.99`，无意中创建了上下文。
>
> 层叠顺序从下往上七层：自身背景和边框、负 z-index 的子元素、块级元素、浮动元素、行内元素、z-index 为 0 或 auto 的定位元素、正 z-index 的子元素。所以负 z-index 会沉到父级背景上面、内容下面，常用来做背景装饰。
>
> 实战里 z-index 不生效，我按顺序排查：一看有没有定位；二看祖先是不是不小心创建了层叠上下文，把子元素锁住了；三看比较的对象其实是祖先而不是自己。修法通常是提升祖先的 z-index，或者用 `isolation: isolate` 显式声明层级边界。

### 可能被追问

| 追问 | 回答要点 |
|---|---|
| 为什么给子元素 `z-index: 9999` 还是被盖住？ | 父级创建了层叠上下文，子元素只能在该上下文内排序；要提升父级 z-index |
| `z-index: 0` 和 `auto` 的区别？ | `0` 创建新上下文并参与排序；`auto` 不创建上下文，与父级同层，子元素可以"穿透"参与外层比较 |
| 负 z-index 会跑到父元素背景下面吗？ | 不会跑到父元素背景之下，但会跑到父元素内容之下；父元素若有背景会遮住它 |
| `opacity: 0.99` 会创建上下文吗？ | 会，小于 1 即创建。这是排查时的经典坑 |
| 如何避免 `z-index` 数值军备竞赛？ | 用 CSS 变量定义层级阶梯（`--z-modal: 100`），或用 `isolation` 划边界，别用 9999 |
| flex 子项没定位，z-index 生效吗？ | 生效，规范规定 flex/grid 子项的 z-index 非 auto 时生效并创建上下文 |
| 浮动元素和块级元素谁在上？ | 浮动在上（顺序里浮动在块级之后），但浮动不脱离文字，会发生文字环绕 |
