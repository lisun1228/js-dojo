## 0. 先看：19 题到底在考什么

### 0.1 这 19 题其实只有 5 类

```
                    算法 19 题
                        │
   ┌────────────┬───────┴────────┬─────────────┬──────────────┐
   │            │                │             │              │
 复杂度/递归   排序(10题)      线性结构       缓存设计        概率/字符串
   │            │                │             │              │
 题 8 复杂度   基础 4 题        题 7 链表+堆   题 18 LRU      题 5 洗牌
 题 2 尾递归   进阶 3 题        题 19 双指针    （Map/链表）   题 1 最优停止
 题 6 尾调用   线性 3 题        题 3 哈希计数                  题 3 哈希计数
```

**关键事实：19 题里 10 题是排序**。这意味着：

- 排序题不可能全部手写完。**面试只会抽 1~2 个**，且大概率是「快排 + 归并 + 堆排」中的一到两个，或「冒泡/插入/选择」挑一个当热身。
- 剩下 5 种（希尔、计数、桶、基数）**考的是"你知不知道有这些东西、什么时候用"**，而不是默写。能说出「非比较排序 + 稳定性 + 适用条件」就够。
- 所以准备策略是：**三大 O(n log n) 必须能默写并对答如流；基础三种必须能秒写；线性三种必须能讲清原理和适用边界。**

### 0.2 面试官在算法题里到底看什么

很多人以为算法题是「写出来 = 过关，写不出 = 挂」。实际评分权重大概是这样：

| 维度 | 权重 | 具体表现 |
|---|---|---|
| **边界处理** | ★★★★★ | 空数组、单元素、全相同元素、负数、已排序、超大数、`null` 入参 |
| **复杂度自觉** | ★★★★☆ | 写完主动报「时间 O(?) 空间 O(?)」，并能解释为什么 |
| **思路表达** | ★★★★☆ | 先说思路和数据结构选择，再动手；不闷头写 |
| **代码正确性** | ★★★☆☆ | 变量名、off-by-one、循环边界、返回值 |
| **优化意识** | ★★★☆☆ | 从暴力解 → 更优解，能说清每一步省了什么 |
| **工程习惯** | ★★☆☆☆ | 不修改入参（或明确说明会改）、不用 `var`、合理命名 |

**最容易被扣分的一句话**：写完就停，等面试官问「复杂度多少」。这是把主动权交出去。正确做法是收尾时自己补一句：

> "这里是 O(n log n) 时间、O(n) 空间；边界上我处理了空数组和全相同元素；如果想省空间可以把归并换成原地快排，代价是失去稳定性。"

这一句话的信息量，抵得上多写 20 行代码。

### 0.3 答题五步法（所有题通用）

```
① 澄清 ──→ ② 说思路 ──→ ③ 写代码 ──→ ④ 手算验证 ──→ ⑤ 报复杂度 + 边界
   30 秒      1 分钟        3-5 分钟       30 秒           30 秒
```

**① 澄清**（30 秒，但能救你一命）

不要一上来就写。先确认三件事：

- 输入规模多大？（决定能不能用 O(n²)）
- 数据有没有特性？（整数？负数？有重复？已排序？范围多大？）
- 要不要稳定？能不能改入参？返回新数组还是原地？

例：面试官说「写个快排」，你问一句「数组里可能有大量重复元素吗」，就能顺势引出三路快排——这是加分的对话，不是浪费时间。

**② 说思路**（1 分钟）

用「数据结构 + 算法」两个词把方案钉死：

> "我用最小堆。先把 k 个链表头入堆，每次弹最小的接到结果尾部，再把它的 next 入堆，直到堆空。时间 O(N log k)，空间 O(k)。"

**③ 写代码**（3-5 分钟）

边写边念关键行。命名要有意义（`left`/`right`/`pivot`/`slow`/`fast`），不要 `a`、`b`、`temp1`。

**④ 手算验证**（30 秒）

**必须**用一个小例子（5~7 个元素）跑一遍，尤其是排序和双指针题。这一步能抓出 80% 的 off-by-one。

**⑤ 报复杂度 + 边界**

主动说，别等问。

### 0.4 复杂度速查表

**量级排序**（从快到慢）：

```
O(1) < O(log n) < O(√n) < O(n) < O(n log n) < O(n²) < O(n³) < O(2ⁿ) < O(n!)
```

**换算成实际时间**（JS，1 亿次简单操作 ≈ 1 秒）：

| 复杂度 | n = 10 | n = 100 | n = 10⁴ | n = 10⁶ | n = 10⁸ |
|---|---|---|---|---|---|
| O(log n) | 3 | 7 | 13 | 20 | 27 |
| O(n) | 10 | 100 | 10⁴ | 10⁶ | 10⁸ ✅ 1s |
| O(n log n) | 33 | 664 | 1.3×10⁵ | 2×10⁷ ✅ | 2.7×10⁹ ❌ |
| O(n²) | 100 | 10⁴ | 10⁸ ✅ 1s | 10¹² ❌ | — |
| O(2ⁿ) | 1024 | ❌ | — | — | — |

**这张表的用法**：面试官说「n 是 10⁵」，你就知道 O(n²) 会超时，必须 O(n log n) 或 O(n)。这是「澄清输入规模」的真正目的。

**空间复杂度怎么算**：

| 占用来源 | 例子 |
|---|---|
| 递归调用栈 | 快排 O(log n)、归并 O(log n)、DFS O(深度) |
| 辅助数组/对象 | 归并的 temp O(n)、计数的 count O(k) |
| 隐式创建 | `arr.slice()`、`[...arr]`、`arr.concat()` 都是 O(n) |

⚠️ **最容易算错的就是"我以为这是 O(1) 空间"**。`arr.slice(0, mid)` 每次都新建数组，空间就是 O(n)，不是 O(log n)。

### 0.5 排序算法总表（必须背下来）

| 算法 | 平均 | 最好 | 最坏 | 空间 | 稳定 | 一句话定位 |
|---|---|---|---|---|---|---|
| 冒泡 | O(n²) | O(n) | O(n²) | O(1) | ✅ | 教学用，工程不用 |
| 选择 | O(n²) | O(n²) | O(n²) | O(1) | ❌ | 交换次数最少（n-1 次） |
| 插入 | O(n²) | O(n) | O(n²) | O(1) | ✅ | **小数组 / 接近有序的最优解** |
| 希尔 | O(n^1.3)~ | O(n log n) | O(n²) | O(1) | ❌ | 插入排序的"分组加速版" |
| 归并 | O(n log n) | O(n log n) | O(n log n) | O(n) | ✅ | **要稳定 / 链表 / 外部排序** |
| 快排 | O(n log n) | O(n log n) | O(n²) | O(log n) | ❌ | **通用最快（常数小、缓存友好）** |
| 堆排 | O(n log n) | O(n log n) | O(n log n) | O(1) | ❌ | **要 O(1) 空间 + 最坏可控 / TopK** |
| 计数 | O(n+k) | O(n+k) | O(n+k) | O(k) | ✅ | 整数且范围小 |
| 桶 | O(n+k) | O(n) | O(n²) | O(n+k) | ✅* | 均匀分布的浮点 |
| 基数 | O(d(n+k)) | O(d(n+k)) | O(d(n+k)) | O(n+k) | ✅ | 定长整数 / 定长字符串 |

\* 桶排序的稳定性取决于桶内用的排序算法。

**三句话记住选型**：

1. **通用场景 → 快排**（但注意 V8 从 7.0 起把 `Array.prototype.sort` 换成了 TimSort，因为 ES2019 要求稳定排序；旧版是「≤22 用插入排序、>22 用快排」）
2. **要稳定或数据在链表上 → 归并**
3. **数据范围小且是整数 → 计数/基数**（能突破 O(n log n) 下界，因为它们不比较）

**为什么比较排序有 O(n log n) 下界？**

n 个元素有 n! 种排列，每次比较只产生 1 bit 信息，决策树高度至少 log₂(n!) ≈ n log n。所以任何**基于比较**的排序都不可能更快。计数/基数/桶能更快，是因为它们**用值本身当下标/地址**，绕开了比较。
