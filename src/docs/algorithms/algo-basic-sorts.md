## 2.0 先把四个概念钉死

这四个词会在本册反复出现，先统一：

| 概念 | 定义 | 怎么快速判断 |
|---|---|---|
| **稳定（Stable）** | 排序后，**值相等**的元素保持原来的相对顺序 | 看有没有「跨距离交换」或「跨组移动」 |
| **原地（In-place）** | 只用 O(1) 额外空间（几个临时变量） | 看有没有 `slice` / `new Array(n)` |
| **比较排序** | 通过两两比较确定顺序 | 看有没有 `a < b` |
| **自适应（Adaptive）** | 输入越接近有序，越快 | 看有没有「提前退出」或「天然利用有序性」 |

**为什么「稳定」重要？** 举个真实场景：

```js
// 商品列表先按销量排序，再按价格排序
// 如果第二次排序是稳定的，同价格的商品仍按销量降序（第一次的顺序被保留）
list.sort((a, b) => b.sales - a.sales);
list.sort((a, b) => a.price - b.price);
//                 ↑ 稳定排序 → 同价位内仍是销量高的在前
```

如果是**不稳定**排序，同价位的商品顺序就被打乱了，需要「价格 + 销量」做二级比较才能补救。

## 2.1 冒泡排序

### 一句话结论

相邻两两比较，大的往后「冒」。每轮把当前未排序区间的最大值推到末尾。**稳定、原地、O(n²)，但加两个优化后「接近有序」时能到 O(n)。**

### 2.1.1 基础版

```js
function bubbleSort(arr) {
  const n = arr.length;
  for (let i = 0; i < n - 1; i++) {          // 需要 n-1 轮
    for (let j = 0; j < n - 1 - i; j++) {    // 每轮末尾 i 个已经有序
      if (arr[j] > arr[j + 1]) {
        [arr[j], arr[j + 1]] = [arr[j + 1], arr[j]];
      }
    }
  }
  return arr;
}
```

**内层为什么是 `n - 1 - i`？**
- `-1`：要访问 `arr[j + 1]`，j 最大只能是 `n - 2`
- `-i`：最后 i 个元素已经排好，不用再看

这两个边界是**最容易写错**的地方，面试手写时错一个就是「逻辑不严谨」。

### 2.1.2 逐步推演（必须会手算）

`[5, 3, 8, 1]`：

```
i=0（要找最大值推到末尾）
  j=0: 5>3 → 交换 → [3,5,8,1]
  j=1: 5<8 → 不动 → [3,5,8,1]
  j=2: 8>1 → 交换 → [3,5,1,8]     ← 8 到位
i=1
  j=0: 3<5 → 不动
  j=1: 5>1 → 交换 → [3,1,5,8]     ← 5 到位
i=2
  j=0: 3>1 → 交换 → [1,3,5,8]     ← 3 到位
结果 [1,3,5,8]
```

### 2.1.3 优化一：提前退出（`swapped` 标记）

如果某一轮**一次交换都没发生**，说明数组已经有序，可以直接结束。

```js
function bubbleSortV1(arr) {
  const n = arr.length;
  for (let i = 0; i < n - 1; i++) {
    let swapped = false;
    for (let j = 0; j < n - 1 - i; j++) {
      if (arr[j] > arr[j + 1]) {
        [arr[j], arr[j + 1]] = [arr[j + 1], arr[j]];
        swapped = true;
      }
    }
    if (!swapped) break;      // 本轮无交换 → 已有序
  }
  return arr;
}
```

**效果**：最好情况（已有序）只需 1 轮，复杂度 **O(n)**。

> 这就是「自适应」的含义。这也是为什么题单里写「时间 O(n²)」时，**严格说要补一句「最好 O(n)」**——原题单漏了这点。

### 2.1.4 优化二：记录最后交换位置（`lastSwap`）

如果数组是 `[1, 2, 3, 4, 9, 5, 6, 7, 8]`，第一轮交换发生在 `9` 和 `5` 之间（位置 4），之后 `5~8` 都比过了没交换。那说明**位置 5 之后已经有序**，下一轮只需要比到位置 4。

```js
function bubbleSortV2(arr) {
  let n = arr.length;
  while (n > 1) {
    let lastSwap = 0;                     // 本轮最后一次交换的位置
    for (let j = 0; j < n - 1; j++) {
      if (arr[j] > arr[j + 1]) {
        [arr[j], arr[j + 1]] = [arr[j + 1], arr[j]];
        lastSwap = j + 1;                 // 记录"这个位置之后都有序了"
      }
    }
    n = lastSwap;                         // 下一轮只比到这里
    if (n === 0) break;
  }
  return arr;
}
```

**效果**：每轮收缩边界，对「局部有序」的数据提升明显。

### 2.1.5 优化三（了解即可）：鸡尾酒排序 / 双向冒泡

普通冒泡只能把最大值往后推，最小值往前的速度很慢。**鸡尾酒排序**每轮先从左往右推最大值，再从右往左推最小值。

```js
function cocktailSort(arr) {
  let lo = 0, hi = arr.length - 1;
  while (lo < hi) {
    let swapped = false;
    for (let i = lo; i < hi; i++) {          // 正向：大值右移
      if (arr[i] > arr[i + 1]) {
        [arr[i], arr[i + 1]] = [arr[i + 1], arr[i]];
        swapped = true;
      }
    }
    hi--;
    for (let i = hi; i > lo; i--) {          // 反向：小值左移
      if (arr[i - 1] > arr[i]) {
        [arr[i - 1], arr[i]] = [arr[i], arr[i - 1]];
        swapped = true;
      }
    }
    lo++;
    if (!swapped) break;
  }
  return arr;
}
```

**解决什么问题**：对 `[2,3,4,5,6,7,8,1]` 这种「只有一个最小值在末尾」的输入，普通冒泡要 n-1 轮才把 1 移到最前；鸡尾酒排序 1 轮搞定。

> 面试提一句「还有鸡尾酒排序可以处理反向有序的情况」就够，不用默写。

### 2.1.6 稳定性分析

**冒泡是稳定的。** 因为交换条件是 `arr[j] > arr[j + 1]`（**严格大于**），相等的元素不会交换。

⚠️ **如果写成 `>=` 就不稳定了**——这是最常见的「无意中破坏稳定性」的错误。

### 2.1.7 复杂度

| 情况 | 复杂度 | 说明 |
|---|---|---|
| 最好 | **O(n)** | 已有序 + `swapped` 优化，只跑 1 轮 |
| 平均 | O(n²) | 逆序对数量约为 n²/4 |
| 最坏 | O(n²) | 完全逆序 |
| 空间 | O(1) | 原地 |
| 稳定 | ✅ | `>` 而非 `>=` |

**交换次数**：等于**逆序对数量**。这让冒泡排序有个额外用途——**用冒泡的交换次数来求逆序对**（虽然 O(n²)，但概念清晰，适合讲原理；实战用归并或树状数组）。

### 2.1.8 常见坑

| 坑 | 后果 | 修正 |
|---|---|---|
| 内层写 `j < n - 1` | 多做无用比较（不影响正确性，但慢） | `j < n - 1 - i` |
| 内层写 `j < n - i` | `arr[j+1]` 越界，最后一个是 `undefined` | `j < n - 1 - i` |
| 写成 `>=` | 不稳定 | 用 `>` |
| 外层写 `i < n` | 多跑一轮（不影响正确性） | `i < n - 1` |
| 用 `arr[j] - arr[j+1] > 0` | 大数相减可能溢出（JS 是 float64，一般没事，但别养成习惯） | 直接比较 |
| 忘记 `return arr` | 返回 undefined | — |

### 2.1.9 答题模板

**30 秒版**

> 冒泡是相邻两两比较，每轮把未排序区间的最大值推到末尾，n-1 轮后整体有序。稳定、原地、平均和最坏 O(n²)，加一个 `swapped` 标记后最好情况能到 O(n)。
> 工程里基本不用，因为交换次数太多——它的交换次数等于逆序对数量，在随机数据下是 O(n²) 次交换，而选择排序只需要 n-1 次。

**2 分钟版（加分层）**

> 冒泡的核心是「每轮确定一个元素的最终位置」。内层从 0 遍历到 `n-1-i`，因为末尾 i 个已经排好了。
> 有两个常见优化。第一个是 `swapped` 标记：某一轮没发生交换就说明已经有序，直接 break，这样最好情况是 O(n)。第二个是记录本轮最后一次交换的位置，下一轮只比到那里，因为那之后的元素已经有序。还有鸡尾酒排序，双向扫描，对「最小值在末尾」的输入更友好。
> 稳定性上要注意必须用严格大于 `>`，写成 `>=` 就会把相等元素交换，破坏稳定性。
> 冒泡最大的问题是交换次数太多，等于逆序对数量。所以真实场景里即使要 O(n²) 的排序，也会用插入排序——它的移动次数更少，而且对部分有序的数据更敏感。

### 2.1.10 追问表

| 追问 | 回答要点 |
|---|---|
| 冒泡的交换次数有什么意义？ | 等于逆序对数量；可以借此理解「逆序对」概念 |
| 为什么内层是 `n-1-i`？ | `-1` 防 `j+1` 越界，`-i` 跳过已排好的末尾 |
| 冒泡稳定吗？为什么？ | 稳定。条件是 `>`，值相等不交换 |
| 加 `swapped` 后最好复杂度？ | O(n)，只跑一轮 |
| 冒泡和选择排序比，谁快？ | 比较次数一样（都是 n(n-1)/2），但冒泡交换次数远多于选择（选择最多 n-1 次） |
| 什么时候会用冒泡？ | 几乎不用。教学、或者 n 极小（<10）且代码要求极简时 |
| 还听过什么「改进冒泡」？ | 鸡尾酒排序（双向）、梳排序（gap 递减，是希尔的一种） |

## 2.2 选择排序

### 一句话结论

每轮从未排序区间里**选出最小值，和区间首位交换**。**不稳定**（因为跨距离交换）、原地、任何情况都是 O(n²)——**没有最好情况优化**。

### 2.2.1 实现

```js
function selectionSort(arr) {
  const n = arr.length;
  for (let i = 0; i < n - 1; i++) {
    let minIdx = i;
    for (let j = i + 1; j < n; j++) {
      if (arr[j] < arr[minIdx]) minIdx = j;
    }
    if (minIdx !== i) {                      // 小优化：已经在位就不用换
      [arr[i], arr[minIdx]] = [arr[minIdx], arr[i]];
    }
  }
  return arr;
}
```

### 2.2.2 逐步推演

`[5, 3, 8, 1]`：

```
i=0: 在 [5,3,8,1] 里找最小 → 1 在 index 3 → 交换 arr[0],arr[3] → [1,3,8,5]
i=1: 在 [3,8,5] 里找最小 → 3 在 index 1 → 不动           → [1,3,8,5]
i=2: 在 [8,5] 里找最小 → 5 在 index 3 → 交换             → [1,3,5,8]
结果 [1,3,5,8]
```

**注意 `i=1` 那轮**：最小值就在原位，所以不需要交换。这个判断不仅能省一次交换，还能**减少破坏稳定性的机会**（下面会讲）。

### 2.2.3 为什么选择排序不稳定（必考）

**定义上**：排序后相等元素的相对顺序变了。

**反例**：`[2a, 2b, 1]`（用 a/b 区分两个值相等的 2）

```
i=0: 最小值是 1（index 2）→ 交换 arr[0] 和 arr[2]
     [2a, 2b, 1] → [1, 2b, 2a]
                        ↑  ↑
                     2b 跑到了 2a 前面！
```

**根因**：选择排序的交换是**跨距离**的——`arr[0]` 被换到 `index 2`，直接「跳过」了中间的 `2b`，相对顺序被打乱。

**对比冒泡和插入**：它们的交换/移动都在**相邻位置**之间进行，相等元素不可能越过彼此，所以稳定。

> 一句话记忆：**「跨距离交换」是不稳定性的来源。** 快排（远距离交换）、堆排（堆顶与末尾交换）、选择排序都属于这一类；冒泡、插入、归并属于「邻近移动」类。

### 2.2.4 选择排序的唯一优势：交换次数最少

| 算法 | 比较次数 | 交换次数 |
|---|---|---|
| 冒泡 | n(n-1)/2 | 逆序对数量（最坏 n(n-1)/2） |
| **选择** | n(n-1)/2 | **最多 n-1** |
| 插入 | n(n-1)/2 | 逆序对数量（但用「移动」而非「交换」，常数更小） |

**什么时候这个优势有意义？** 当「交换」的代价远高于「比较」时——比如元素是**很大的结构体**，交换要复制很多字节。这时选择排序优于冒泡。

（在 JS 里元素是引用，交换只是换指针，所以这个优势不明显。）

### 2.2.5 为什么选择排序没有「最好情况」优化

因为它是**「先找完再决定」**：即使数组已经有序，也必须把整个未排序区间扫描一遍才能确认「最小值就是第一个」。

对比插入排序：它边扫边插，一旦发现 `arr[i] > arr[i-1]` 就立刻跳过，所以有序时是 O(n)。

> 这是三者最重要的差异之一，面试常问「哪种排序对有序数据最敏感」。

### 2.2.6 常见坑

| 坑 | 后果 | 修正 |
|---|---|---|
| 忘记 `minIdx = i` 初始化 | `minIdx` 是上一轮的残留值 | 每轮重置 |
| 内层从 `i` 开始 | 多一次自己和自己比（不影响正确性） | 从 `i + 1` |
| 外层写 `i < n` | 最后一轮无意义 | `i < n - 1` |
| 以为选择排序稳定 | 答错稳定性，直接扣分 | 不稳定，反例 `[2a, 2b, 1]` |
| 用选择排序处理大数组 | O(n²) 超时 | 用 O(n log n) 的算法 |

### 2.2.7 答题模板

**30 秒版**

> 选择排序每轮在未排序区间里找最小值，和区间首位交换，n-1 轮结束。原地、O(n²)、**不稳定**。
> 它的特点是**比较次数固定**，任何输入都是 n(n-1)/2 次，没有最好情况；但**交换次数最少**，最多 n-1 次。
> 不稳定的原因是交换是跨距离的：`[2a, 2b, 1]` 第一轮把 1 换到最前，2a 就被扔到了 2b 后面。

**2 分钟版（加分层）**

> 选择排序可以理解成「每轮做一次选择」。外层 i 表示「前 i 个已经就位」，内层在 `[i, n)` 里找最小值的下标，然后和 `arr[i]` 交换。
> 和冒泡、插入比，它有两个鲜明特点。第一是**没有自适应性**：无论输入是否有序，都必须完整扫描一遍才能确认最小值，所以永远 O(n²)。第二是**交换次数极少**，最多 n-1 次，因为每轮只交换一次——这在元素很大的场景下有优势，比如 C 里排序大结构体。
> 稳定性上它是不稳定的，反例是 `[2a, 2b, 1]`。根因是跨距离交换会「跳过」中间元素。冒泡和插入因为是相邻移动，天然稳定。
> 实际工程里选择排序几乎不用，但它的思想很重要——**「选择第 k 小」用堆可以做到 O(n log k)**，这就是堆排序和 TopK 的起点。

### 2.2.8 追问表

| 追问 | 回答要点 |
|---|---|
| 选择排序稳定吗？ | 不稳定，反例 `[2a, 2b, 1]` |
| 为什么不稳定？ | 跨距离交换，中间元素被「跳过」 |
| 有最好情况吗？ | 没有，任何输入都是 O(n²) |
| 那它有什么优点？ | 交换次数最少（n-1 次），适合元素大的场景 |
| 比较次数是多少？ | 固定 n(n-1)/2，与输入无关 |
| 怎么改成稳定？ | 把「交换」改成「整体后移 + 插入」，但那就变成插入排序了 |
| 选择排序和堆排序的关系？ | 都是「每轮选最值」，堆排序用堆把「选最值」从 O(n) 降到 O(log n) |

## 2.3 插入排序

### 一句话结论

像**整理扑克牌**：把当前元素插入到前面已排序区间的正确位置。**稳定、原地、自适应（接近有序时接近 O(n)）**，是**小数组和部分有序数据的最优选择**，也是所有工业级排序算法的「底座」。

### 2.3.1 实现

```js
function insertionSort(arr) {
  const n = arr.length;
  for (let i = 1; i < n; i++) {
    const cur = arr[i];          // 待插入的元素（先存起来，因为后面会被覆盖）
    let j = i - 1;
    while (j >= 0 && arr[j] > cur) {
      arr[j + 1] = arr[j];       // 比 cur 大的都往后挪一格
      j--;
    }
    arr[j + 1] = cur;            // 空出来的位置放 cur
  }
  return arr;
}
```

**三个必须理解的细节**：

1. **为什么要 `const cur = arr[i]`**：后面的 `arr[j + 1] = arr[j]` 会覆盖 `arr[i]`，必须先把值存下来。
2. **为什么循环条件是 `arr[j] > cur` 而不是 `>=`**：用 `>` 才能保证稳定（相等时不挪动，`cur` 插在后面）。
3. **为什么最后是 `arr[j + 1] = cur`**：循环结束时 `j` 指向「第一个 ≤ cur 的位置」，所以插入点是 `j + 1`。

### 2.3.2 逐步推演

`[5, 3, 8, 1]`：

```
i=1, cur=3: 5>3 → 5 后移 → [5,5,8,1]，j=-1 → arr[0]=3 → [3,5,8,1]
i=2, cur=8: 5<8 → 不进入循环 → arr[2]=8（原地）        → [3,5,8,1]
i=3, cur=1: 8>1 → 后移；5>1 → 后移；3>1 → 后移
            [3,3,5,8] → arr[0]=1                      → [1,3,5,8]
```

**注意 `i=2` 那轮**：一次都没进循环体。这就是「自适应」——**已经有序的部分直接跳过**。

### 2.3.3 为什么接近有序时是 O(n)

内层 `while` 的执行次数 = 该元素需要移动的步数 = **它前面比它大的元素个数**。

- **完全有序**：每个元素都只需比较 1 次（`arr[i-1] < cur`），内层立即退出 → 总比较 n-1 次 → **O(n)**
- **完全逆序**：第 i 个元素要移动 i 步 → 总移动 n(n-1)/2 次 → **O(n²)**
- **随机**：平均移动 n²/4 次 → **O(n²)**

**更精确的说法**：插入排序的移动次数**正好等于逆序对数量**。这也是「插入排序适合部分有序数据」的数学解释——逆序对少，移动就少。

### 2.3.4 为什么插入排序是「小数组之王」

这是本册最重要的一条工程结论。三个原因：

**① 常数因子极小**

插入排序的内层只有「比较 + 赋值」，没有函数调用、没有递归、没有额外数组分配。相比之下：
- 归并要 `slice` + `concat`（每次分配新数组）
- 快排有递归调用开销
- 堆排有 `siftDown` 函数调用

在 n 很小时（通常 16~64），**常数因子比渐进复杂度更重要**。

**② 缓存友好**

插入排序是**顺序访问**内存，CPU 缓存命中率极高。归并排序的 `merge` 在两个数组间来回跳，缓存不友好。

**③ 天然利用已有顺序**

真实数据往往是「部分有序」的（比如用户列表按 id 排序，新数据 append 在末尾），插入排序能直接受益。

**工业界的证据**：

| 场景 | 用法 |
|---|---|
| **V8 的 TimSort** | `minRunLength` 动态算在 **32~64** 之间，比它短的 run 用二分插入排序补齐（`binaryInsertionSort`） |
| **Java 的 `Arrays.sort`**（对象） | TimSort，run 长度 < 32 用插入排序 |
| **C++ `std::sort`** | 递归到区间长度 ≤ 16 时切换为插入排序 |
| **快排优化** | 区间 < 10 时改用插入排序收尾 |

> 面试话术：「插入排序在小数组上是最快的，因为常数因子小、缓存友好。所以工业级排序算法都会在小区间切换成插入排序，比如 V8 的 TimSort 里 `minRunLength` 会动态算在 32~64 之间，比它短的 run 用二分插入排序补齐；C++ 的 `std::sort` 递归到区间 ≤ 16 时就切插入排序收尾。」

### 2.3.5 优化一：二分插入（减少比较，不减少移动）

内层是线性查找插入位置。既然前面已经有序，可以用**二分查找**定位，把比较次数从 O(n) 降到 O(log n)。

```js
function binaryInsertionSort(arr) {
  for (let i = 1; i < arr.length; i++) {
    const cur = arr[i];
    // 在 [0, i) 里找第一个 > cur 的位置
    let lo = 0, hi = i;
    while (lo < hi) {
      const mid = (lo + hi) >> 1;
      if (arr[mid] <= cur) lo = mid + 1;   // <= 保证稳定（相等的放右边）
      else hi = mid;
    }
    // lo 就是插入位置，把 [lo, i) 整体后移
    for (let j = i; j > lo; j--) arr[j] = arr[j - 1];
    arr[lo] = cur;
  }
  return arr;
}
```

⚠️ **注意：二分插入只减少「比较」次数，不减少「移动」次数**。总复杂度仍是 O(n²)，因为移动是瓶颈。

**它的真实价值**：当**比较操作远贵于移动操作**时（比如比较是字符串/大对象的比较），二分插入有优势。这也是 V8 TimSort 里 `binaryInsertionSort` 的意义。

**稳定性**：`arr[mid] <= cur` 时才往右走，相等元素会插在后面 → 稳定。

### 2.3.6 优化二：哨兵（省掉 `j >= 0` 判断）

C 语言里常用「哨兵」技巧：把 `arr[0]` 设为 `-Infinity`，内层就可以省掉 `j >= 0` 的边界判断。

```js
// 思路示意（JS 里收益不大，因为 arr[-1] 是 undefined，比较会得到 false，天然安全）
function insertionSortSentinel(arr) {
  // 先保证 arr[0] 是最小的，后面就不用判断 j >= 0
  for (let i = arr.length - 1; i > 0; i--) {
    if (arr[i - 1] > arr[i]) [arr[i - 1], arr[i]] = [arr[i], arr[i - 1]];
  }
  for (let i = 2; i < arr.length; i++) {
    const cur = arr[i];
    let j = i - 1;
    while (arr[j] > cur) {        // 不需要 j >= 0，因为 arr[0] 一定 ≤ cur
      arr[j + 1] = arr[j];
      j--;
    }
    arr[j + 1] = cur;
  }
  return arr;
}
```

> JS 里 `arr[-1]` 是 `undefined`，`undefined > cur` 是 `false`，所以其实**天然不会越界**。但依赖这个行为不够严谨，面试提一句「C 里用哨兵省判断」即可。

### 2.3.7 稳定性分析

**插入排序稳定**，两个条件缺一不可：

1. 循环条件用 `arr[j] > cur`（不是 `>=`）——相等时不挪动
2. 元素是「逐个后移」而不是「跳跃交换」——不会跨过相等元素

如果写成 `arr[j] >= cur`，相等的元素会被挪到 `cur` 后面，就变成**不稳定**了。

### 2.3.8 复杂度

| 情况 | 比较/移动 | 复杂度 |
|---|---|---|
| 最好（已有序） | n-1 次比较，0 次移动 | **O(n)** |
| 平均 | ~n²/4 | O(n²) |
| 最坏（逆序） | n(n-1)/2 | O(n²) |
| 空间 | — | O(1) |
| 稳定 | — | ✅ |

### 2.3.9 常见坑

| 坑 | 后果 | 修正 |
|---|---|---|
| 忘了 `const cur = arr[i]` | `cur` 被后续赋值覆盖，结果错乱 | 先存值 |
| 内层写 `arr[j] >= cur` | 不稳定 | 用 `>` |
| 最后写 `arr[j] = cur` | 少移一位，插错位置 | `arr[j + 1] = cur` |
| 外层从 `i = 0` 开始 | `j = -1`，逻辑仍成立但多一次空跑 | 从 `1` 开始 |
| 用 `for` 写内层但忘记 `break` | 会继续比较，逻辑错 | 用 `while` 更清晰 |
| 在链表上套用数组版 | 链表不支持随机访问 | 链表插入排序要单独写（见下） |

**链表版插入排序**（面试可能追问）：

```js
function insertionSortList(head) {
  const dummy = { next: head, val: -Infinity };
  let cur = head;
  while (cur && cur.next) {
    if (cur.val <= cur.next.val) {   // 已有序，跳过
      cur = cur.next;
      continue;
    }
    let prev = dummy;                // 从头找插入点
    while (prev.next.val < cur.next.val) prev = prev.next;
    const tmp = cur.next;            // 摘下 cur.next
    cur.next = tmp.next;
    tmp.next = prev.next;            // 插到 prev 后面
    prev.next = tmp;
  }
  return dummy.next;
}
```

### 2.3.10 答题模板

**30 秒版**

> 插入排序像整理扑克牌，把当前元素插入前面已排序区间的正确位置，比它大的元素逐个后移。原地、稳定、O(n²)，但**接近有序时是 O(n)**，因为内层几乎不进循环。
> 它最重要的工程价值是**小数组最快**——常数因子小、缓存友好，所以 TimSort、`std::sort` 都把它作为小区间的收尾算法。

**2 分钟版（加分层）**

> 插入排序的核心是维护一个「前缀有序」的不变量。外层 i 从 1 开始，每轮把 `arr[i]` 插入到 `[0, i)` 这个有序区间的正确位置。
> 实现上有三个细节：一是必须先把 `arr[i]` 存到临时变量，因为后移会覆盖它；二是循环条件用 `arr[j] > cur` 而不是 `>=`，这样相等元素不移动，保证稳定；三是循环结束时 j 指向第一个小于等于 cur 的位置，所以插入点是 `j+1`。
> 复杂度上它是**自适应**的：移动次数正好等于逆序对数量，所以完全有序时是 O(n)、完全逆序时是 O(n²)。
> 它的工程地位比面试地位高得多。因为常数因子极小、顺序访问内存缓存友好，所有工业级排序都会在小区间切换到插入排序——V8 的 TimSort `minRunLength` 在 32~64、Java 的 TimSort `MIN_MERGE = 32`、C++ `std::sort` 是 16、CPython 是 64。另外还有一个二分插入的变体，把「找位置」从线性降到对数，但移动次数不变，所以只在比较很贵的时候才有意义。

### 2.3.11 追问表

## 2.4 希尔排序

> ⚠️ **原题单只有 3 行文字、没有代码**，这里补完整实现。

### 一句话结论

希尔排序是**插入排序的「分组加速版」**：先用较大 gap 把数组分成若干子序列分别插入排序，让元素**大步移动**、快速减少逆序对；再逐步缩小 gap 到 1，最后一遍基本有序的插入排序。**不稳定、原地，复杂度取决于 gap 序列，约 O(n^1.3)~O(n²)**。

### 2.4.1 为什么需要希尔排序：插入排序的痛点

插入排序有个致命弱点：**如果最小元素在末尾，它要一步一步挪到最前面，需要 n-1 次移动**。

```
[2, 3, 4, 5, 6, 7, 8, 1]
                        ↑ 这个 1 要挪 7 次
```

每次只挪一格，太慢。**能不能让它一次挪远一点？**

希尔排序的答案：**先按间隔 gap 分组，组内做插入排序，这样元素一次可以移动 gap 格。**

### 2.4.2 核心思想（图解）

以 `[8, 9, 1, 7, 2, 3, 5, 4, 6, 0]`、初始 `gap = 4` 为例：

```
原数组:  8  9  1  7  2 | 3  5  4  6  0
gap=4 分组（同色为一组，间隔 4）:
  组1: index 0, 4, 8  → 8, 2, 6
  组2: index 1, 5, 9  → 9, 3, 0
  组3: index 2, 6     → 1, 5
  组4: index 3, 7     → 7, 4

各组内部插入排序:
  组1: 2, 6, 8
  组2: 0, 3, 9
  组3: 1, 5
  组4: 4, 7

按原位置填回: 2 0 1 4 6 | 3 5 7 8 9
```

**关键观察**：原来是「1 在 index 2、0 在 index 9」，经过 gap=4 这一轮，0 从末尾跳到了 index 1 —— **一次移动跨了 4 格**。

再取 `gap = 2`，最后 `gap = 1`（普通插入排序）。因为此时数组已「基本有序」，最后一遍插入排序的移动次数很少。

### 2.4.3 实现（Knuth 序列）

```js
function shellSort(arr) {
  const n = arr.length;
  // 1. 生成 Knuth 序列：1, 4, 13, 40, 121...  满足 h = 3h + 1
  let gap = 1;
  while (gap < n / 3) gap = gap * 3 + 1;

  // 2. 从大到小枚举 gap
  for (; gap >= 1; gap = Math.floor(gap / 3)) {
    // 3. 对每个 gap 做「分组插入排序」
    //    注意：这里用一层循环就完成了所有组，因为 i 从 gap 开始递增，
    //    天然遍历了所有组（i, i-gap, i-2gap...）
    for (let i = gap; i < n; i++) {
      const cur = arr[i];
      let j = i - gap;
      while (j >= 0 && arr[j] > cur) {
        arr[j + gap] = arr[j];
        j -= gap;
      }
      arr[j + gap] = cur;
    }
  }
  return arr;
}
```

**为什么只用一层 `i` 循环就能处理所有组？**

因为 `i` 从 `gap` 到 `n-1` 递增，`i` 和 `i-gap` 属于同一组。当 `i` 增长时，会依次处理组 0、组 1、组 2……的所有元素。这等价于「for 每个组 → for 组内元素」，但代码更短。

**对照插入排序看差异**（只有 3 处不同）：

| 位置 | 插入排序 | 希尔排序 |
|---|---|---|
| 外层起点 | `i = 1` | `i = gap` |
| 内层跨度 | `j = i - 1`，`j--` | `j = i - gap`，`j -= gap` |
| 赋值位置 | `arr[j + 1]` | `arr[j + gap]` |

> 这个对照是理解希尔排序最快的方式：**它就是「间隔为 1 的插入排序」泛化成「间隔为 gap」**。

### 2.4.4 gap 序列怎么选（面试高频）

gap 序列的选择**直接决定复杂度**，这是希尔排序最特殊的地方——**它是唯一一个复杂度依赖参数的排序算法**。

| 序列 | 生成方式 | 最坏复杂度 | 评价 |
|---|---|---|---|
| **n/2, n/4, ..., 1**（Shell 原始） | `gap = gap / 2` | O(n²) | 最简单，但对某些输入退化严重（如 `2^k` 长度的数组） |
| **Knuth** | `1, 4, 13, 40, ...`，`h = 3h + 1` | O(n^1.5) | **最常用**，实现简单，性能好 |
| **Hibbard** | `1, 3, 7, 15, ...`，`h = 2^k - 1` | O(n^1.5) | 理论可证 |
| **Sedgewick** | `1, 5, 19, 41, 109, ...` | O(n^1.33) | 理论最优之一，但序列要硬编码 |
| **Ciura** | `1, 4, 10, 23, 57, 132, 301, 701` | 实验最优 | 经验值，实践中很快 |

**为什么原始 `n/2` 序列会退化？**

因为它会产生大量「互质因子」问题：如果 gap 序列都是偶数，那么奇数位和偶数位的元素永远不在同一组里比较，直到最后 gap=1 才比较。这会导致大量无效工作。

> 面试话术：「gap 序列影响很大。原始的 `n/2` 序列最坏还是 O(n²)，因为相邻 gap 有公因子时，元素只在自己的「模 gap 等价类」里移动。Knuth 的 `3h+1` 序列最坏 O(n^1.5)，是最常用的选择。」

### 2.4.5 为什么希尔排序比插入排序快

**核心机制：让元素「大步移动」，快速消除逆序对。**

插入排序的问题是一次只移动 1 格。希尔排序第一轮 gap 很大，一次可以移动 gap 格，把远处的逆序对快速消除。

**更精确的解释**（两个效应）：

1. **大 gap 阶段**：每个子序列很短（n/gap 个元素），插入排序的 O(k²) 里 k 很小，总代价低；同时元素位置被大幅调整。
2. **小 gap 阶段**：数组已经「基本有序」，插入排序在接近有序时是 O(n)，所以最后几轮很便宜。

**总代价**约等于「每轮 O(n) × 轮数 log n」≈ O(n log n) ~ O(n^1.3)。严格证明很难（这也是希尔排序的著名特点：**平均复杂度至今没有严格证明**，只有实验结果和部分序列的理论界）。

> 这一点很值得说：「希尔排序是少数**平均复杂度还没有被严格证明**的经典算法，只有针对特定 gap 序列的最坏情况分析。」这是显示深度的一句话。

### 2.4.6 为什么希尔排序不稳定

**反例**：`[2a, 2b, 1]`，gap = 2

```
gap=2: 组1 = index 0, 2 → 2a, 1 → 排序后 1, 2a
       组2 = index 1     → 2b
       结果: [1, 2b, 2a]
                  ↑   ↑
              2b 跑到 2a 前面了
```

**根因**：不同的 gap 分组把原本相邻的相等元素分到了不同组，组内排序后，跨组的相对顺序就可能反转。

> 这是「分组」带来的固有代价：**只要元素跨组移动，就可能跨过相等元素**。

### 2.4.7 复杂度总结

| 情况 | 复杂度 | 说明 |
|---|---|---|
| 最好 | O(n log n) | 已有序时，每轮都是 O(n)，共 log n 轮 |
| 平均 | **O(n^1.3)** 左右 | 依赖 gap 序列，无严格证明 |
| 最坏 | O(n^1.5)（Knuth）/ O(n²)（原始） | 依赖 gap 序列 |
| 空间 | O(1) | 原地，只用 `cur` 和 `j` |
| 稳定 | ❌ | 跨组移动破坏顺序 |

### 2.4.8 希尔排序的定位

**它是个「中间态」算法**：

```
O(n²) 家族                希尔               O(n log n) 家族
插入/冒泡/选择  ────────→  希尔  ────────→  归并/快排/堆排
简单、慢                   折中                复杂、快
```

**它的实际价值**：

1. **代码极短**（十几行），比归并/快排简单得多，但比插入快几倍。
2. **O(1) 空间 + 不递归**，适合**嵌入式 / 栈空间受限**的环境。
3. **对中等规模（n < 10 万）数据，性能接近 O(n log n) 算法**，是「性价比」选择。
4. **历史上重要**：它是第一个突破 O(n²) 的排序算法（1959 年），启发了后来的 Shell 改进和 gap 序列研究。

**什么时候不用**：需要稳定排序时（希尔不稳定）；数据量极大时（不如快排/归并）。

### 2.4.9 常见坑

| 坑 | 后果 | 修正 |
|---|---|---|
| `gap` 最后没到 1 | **数组没有完全排序**（致命） | 循环条件 `gap >= 1` |
| `gap = Math.floor(gap / 2)` 但初始 `gap = n` | 第一轮 gap = n/2，OK；但要保证最终到 1 | 用 `while (gap >= 1)` |
| 内层写成 `j -= 1` | 变成普通插入排序，白做 | `j -= gap` |
| 赋值写成 `arr[j+1] = cur` | 位置错（应该是 `j+gap`） | `arr[j + gap] = cur` |
| 用 `gap * 3 + 1` 生成但递减用 `/2` | 序列不一致，可能跳过某些 gap | 生成和递减要用同一套规则 |
| 以为它是稳定的 | 答错稳定性 | 不稳定 |
| 说「复杂度 O(n^1.3)」不加限定 | 不严谨 | 应说「约 O(n^1.3)，依赖 gap 序列」 |

**最容易犯的致命错误：gap 没降到 1**

```js
// ❌ 错误：gap 递减到 2 就停了
for (; gap > 1; gap = Math.floor(gap / 3)) { ... }
// 结果：数组只是「gap=2 分组有序」，整体并未排序

// ✅ 正确
for (; gap >= 1; gap = Math.floor(gap / 3)) { ... }
```

### 2.4.10 答题模板

**30 秒版**

> 希尔排序是插入排序的改进：先用大的 gap 把数组分成若干子序列分别插入排序，让元素能大步移动、快速减少逆序对；然后逐步缩小 gap，最后 gap=1 时做一次普通插入排序，此时数组已基本有序，很快。
> 它原地、**不稳定**，复杂度取决于 gap 序列，Knuth 的 `3h+1` 序列最坏 O(n^1.5)，实测平均在 O(n^1.3) 左右。
> 代码和插入排序只差三处：外层从 gap 开始、内层步长是 gap、赋值位置是 `j+gap`。

**2 分钟版（加分层）**

> 希尔排序解决的是插入排序的痛点：插入排序一次只移动一格，如果最小元素在末尾就要挪 n 次。希尔的思路是「先让它大步跳」。
> 具体做法是引入 gap，把下标相差 gap 的元素看作一组，组内做插入排序。gap 从大到小递减到 1。因为大 gap 时每组元素很少，排序很便宜，同时元素位置被大幅调整；到了小 gap 阶段，数组已经基本有序，插入排序在接近有序时是 O(n)，所以最后几轮几乎不要钱。
> 有三个点值得注意。第一，gap 序列直接影响复杂度，原始的 `n/2` 序列最坏还是 O(n²)，因为有公因子的 gap 会让元素只在固定等价类里移动；Knuth 的 `3h+1` 最坏 O(n^1.5)，是最常用的。第二，希尔排序**不稳定**，因为跨组移动会跨过相等元素，反例是 `[2a, 2b, 1]` 配 gap=2。第三，它的平均复杂度至今**没有严格证明**，只有特定序列的最坏情况分析，这在经典算法里很少见。
> 工程上它的价值是「代码短 + O(1) 空间 + 不递归」，适合栈受限的嵌入式场景，或者中等规模数据的快速实现。

### 2.4.11 追问表

| 追问 | 回答要点 |
|---|---|
| 希尔排序和插入排序的关系？ | 插入排序是 gap=1 的特例；希尔是「多轮不同 gap 的插入排序」 |
| 为什么 gap 最后一定要到 1？ | 只有 gap=1 才能保证全局有序；这是最致命的 bug 点 |
| gap 序列有哪些？ | n/2（原始）、Knuth 3h+1、Hibbard 2^k-1、Sedgewick、Ciura |
| 复杂度到底是多少？ | 依赖序列：原始 O(n²)，Knuth O(n^1.5)，实测平均 O(n^1.3)；平均情况无严格证明 |
| 稳定吗？ | 不稳定，跨组移动会跨过相等元素 |
| 为什么比插入快？ | 大 gap 阶段元素大步移动，快速消除逆序对；小 gap 阶段已基本有序 |
| 工程上还用吗？ | 用，代码短、O(1) 空间、不递归；但大数据不如快排/归并 |
| 一层 i 循环怎么处理所有组？ | i 递增时天然遍历了所有「模 gap 同余」的组 |

## 2.5 四者横向对比

### 2.5.1 总表

| | 冒泡 | 选择 | 插入 | 希尔 |
|---|---|---|---|---|
| 平均 | O(n²) | O(n²) | O(n²) | ~O(n^1.3) |
| 最好 | **O(n)** | O(n²) | **O(n)** | O(n log n) |
| 最坏 | O(n²) | O(n²) | O(n²) | O(n^1.5)~O(n²) |
| 空间 | O(1) | O(1) | O(1) | O(1) |
| 稳定 | ✅ | ❌ | ✅ | ❌ |
| 自适应 | ✅（swapped） | ❌ | ✅ | 部分 |
| 交换/移动次数 | 逆序对数 | **最少 n-1** | 逆序对数（移动更便宜） | 中等 |
| 一句话 | 教学用 | 交换最少 | **小数组之王** | 插入的加速版 |

### 2.5.2 同输入对比（`[5, 3, 8, 1]`）

| 算法 | 第 1 轮后 | 第 2 轮后 | 第 3 轮后 | 总交换/移动 |
|---|---|---|---|---|
| 冒泡 | `3 5 1 8` | `3 1 5 8` | `1 3 5 8` | 4 次交换 |
| 选择 | `1 3 8 5` | `1 3 8 5` | `1 3 5 8` | 2 次交换 |
| 插入 | `3 5 8 1` | `3 5 8 1` | `1 3 5 8` | 4 次移动 |
| 希尔(gap=2) | `1 3 5 8`（gap=2 一轮 + gap=1 一轮） | — | — | 2 次移动 |

> 注意希尔在 gap=2 时就已经把 1 从末尾（index 3）挪到了 index 0，一步跨 2 格，这就是「大步移动」的直观效果。

### 2.5.3 面试里怎么选

```
数据量 < 50？
  └─ 是 → 插入排序（常数最小）
  └─ 否 → 要稳定？
            └─ 是 → 归并排序
            └─ 否 → 内存紧张？
                      └─ 是 → 堆排序（O(1) 空间 + 最坏 O(n log n)）
                      └─ 否 → 快排（实测最快）
```

**冒泡和选择排序在这棵树上根本不出现**——这就是它们在工程里真实的位置。

## 2.6 本册速记卡

```
稳定的根因：「相邻移动」不跨过相等元素
不稳定的根因：「跨距离交换」或「跨组移动」
  → 冒泡/插入/归并 稳定（相邻）
  → 选择/快排/堆排/希尔 不稳定（跨距离/跨组）

冒泡
  每轮把最大值推到末尾；内层 n-1-i（-1 防越界，-i 跳过已排好）
  优化1：swapped → 最好 O(n)
  优化2：记录最后交换位置 → 收缩边界
  优化3：鸡尾酒（双向）
  交换次数 = 逆序对数量

选择
  每轮选最小值与首位交换；任何输入都是 O(n²)，无自适应
  不稳定： [2a,2b,1] 第一轮把 1 换到最前，2a 被扔到 2b 后面
  唯一优势：交换次数 ≤ n-1

插入
  像整理扑克牌；先存 cur；条件 > 保证稳定；插入点是 j+1
  移动次数 = 逆序对数量 → 有序时 O(n)
  小数组之王：常数小 + 缓存友好 + 无分配 → TimSort minRunLength 32~64、std::sort 16
  二分插入：降比较不降移动，只在比较很贵时有用

希尔
  插入排序 + 多轮 gap；和插入只差 3 处（起点/步长/赋值位置）
  gap 必须到 1，否则没排完（最致命 bug）
  序列：n/2（最坏 O(n²)）、Knuth 3h+1（O(n^1.5)）、Sedgewick（O(n^1.33)）
  不稳定（跨组移动）；平均复杂度无严格证明
```
