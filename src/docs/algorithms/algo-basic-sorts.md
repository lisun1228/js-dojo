## 2.0 先把四个概念钉死

| 概念 | 定义 | 判断依据 |
|---|---|---|
| **稳定（Stable）** | 排序后，值相等的元素保持原来的相对顺序 | 是否存在跨距离交换或跨组移动 |
| **原地（In-place）** | 只用 O(1) 额外空间 | 是否分配 `slice` / `new Array(n)` |
| **比较排序** | 通过两两比较确定顺序 | 是否存在 `a < b` 这类比较 |
| **自适应（Adaptive）** | 输入越接近有序，越快 | 是否有提前退出或利用已有顺序 |

稳定的用途是让两次排序可以叠加：

```js
// 先按销量降序，再按价格升序；第二次稳定时，同价位仍保持销量降序
list.sort((a, b) => b.sales - a.sales);
list.sort((a, b) => a.price - b.price);
```

不稳定排序会打乱同价位元素的销量顺序，只能把价格和销量合并成二级比较。

## 2.1 冒泡排序

> 相邻比较，每轮把未排序区间的最大值移到末尾。稳定、原地；基础版 O(n²)，加 `swapped` 后有序输入为 O(n)。

### 2.1.1 基础实现

```js
function bubbleSort(arr) {
  const n = arr.length;
  for (let i = 0; i < n - 1; i++) {          // n-1 轮
    for (let j = 0; j < n - 1 - i; j++) {    // 末尾 i 个已有序
      if (arr[j] > arr[j + 1]) {
        [arr[j], arr[j + 1]] = [arr[j + 1], arr[j]];
      }
    }
  }
  return arr;
}
```

- `-1`：要访问 `arr[j + 1]`，`j` 最大只能到 `n - 2`。
- `-i`：末尾 i 个元素已经排好，不再比较。
- 外层 `i < n - 1`：n-1 轮后只剩一个元素，天然有序。

### 2.1.2 推演

`[5, 3, 8, 1]`：

```
i=0（找最大值推到末尾）
  j=0: 5>3 → 交换 → [3,5,8,1]
  j=1: 5<8 → 不动 → [3,5,8,1]
  j=2: 8>1 → 交换 → [3,5,1,8]     ← 8 到位
i=1
  j=0: 3<5 → 不动
  j=1: 5>1 → 交换 → [3,1,5,8]     ← 5 到位
i=2
  j=0: 3>1 → 交换 → [1,3,5,8]     ← 3 到位
结果 [1,3,5,8]
```

### 2.1.3 优化：提前退出与收缩边界

`swapped`：某一轮没有发生交换，说明数组已经有序。

```js
function bubbleSortV1(arr) {
  const n = arr.length;
  for (let i = 0; i < n - 1; i++) {
    let swapped = false;
    for (let j = 0; j < n - 1 - i; j++) {
      if (arr[j] > arr[j + 1]) {
        [arr[j], arr[j + 1]] = [arr[j + 1], arr[j]];
        swapped = true;
      }
    }
    if (!swapped) break;
  }
  return arr;
}
```

已升序时只跑 1 轮，比较 `n - 1` 次，复杂度 O(n)。

`lastSwap`：记录本轮最后一次交换的位置，下一轮只比较到该位置。

```js
function bubbleSortV2(arr) {
  let n = arr.length;
  while (n > 1) {
    let lastSwap = 0;
    for (let j = 0; j < n - 1; j++) {
      if (arr[j] > arr[j + 1]) {
        [arr[j], arr[j + 1]] = [arr[j + 1], arr[j]];
        lastSwap = j + 1;
      }
    }
    n = lastSwap;
    if (n === 0) break;
  }
  return arr;
}
```

`[1,2,3,4,9,5,6,7,8]` 第一轮最后一次交换发生在 `9` 和 `5`，`lastSwap = 5`；下一轮只比较到下标 4。

### 2.1.4 鸡尾酒排序

每轮先正向把最大值推到右端，再反向把最小值推到左端。

```js
function cocktailSort(arr) {
  let lo = 0, hi = arr.length - 1;
  while (lo < hi) {
    let swapped = false;
    for (let i = lo; i < hi; i++) {          // 正向：大值右移
      if (arr[i] > arr[i + 1]) {
        [arr[i], arr[i + 1]] = [arr[i + 1], arr[i]];
        swapped = true;
      }
    }
    hi--;
    for (let i = hi; i > lo; i--) {          // 反向：小值左移
      if (arr[i - 1] > arr[i]) {
        [arr[i - 1], arr[i]] = [arr[i], arr[i - 1]];
        swapped = true;
      }
    }
    lo++;
    if (!swapped) break;
  }
  return arr;
}
```

对 `[2,3,4,5,6,7,8,1]`，基础冒泡需要 7 轮把 1 移到最前；鸡尾酒排序一次正向加一次反向扫描后有序。

### 2.1.5 稳定性与复杂度

交换条件是 `arr[j] > arr[j + 1]`，相等元素不交换，因此稳定。写成 `>=` 会交换相等元素，变成不稳定。

| 情况 | 比较次数 | 交换次数 | 复杂度 |
|---|---|---|---|
| 最好（已升序 + `swapped`） | n-1 | 0 | **O(n)** |
| 平均 | 基础版 n(n-1)/2 | 逆序对，约 n²/4 | O(n²) |
| 最坏（完全逆序） | n(n-1)/2 | n(n-1)/2 | O(n²) |
| 空间 | — | — | O(1) |

交换次数等于逆序对数量。逆序对可用归并排序或树状数组统计；冒泡只用于说明这个等价关系。

### 2.1.6 常见坑

| 坑 | 后果 | 修正 |
|---|---|---|
| 内层写 `j < n - 1` | 多做无用比较，不影响正确性 | `j < n - 1 - i` |
| 内层写 `j < n - i` | `arr[j+1]` 越界，最后一项是 `undefined` | `j < n - 1 - i` |
| 写成 `>=` | 不稳定 | 用 `>` |
| 外层写 `i < n` | 多跑一轮，不影响正确性 | `i < n - 1` |
| 忘记 `return arr` | 返回 `undefined` | 返回数组 |

### 2.1.7 口述要点

- 相邻比较，每轮确定一个最大值；内层边界是 `n - 1 - i`。
- 稳定性由严格 `>` 保证。
- `swapped` 把最好情况降到 O(n)；`lastSwap` 收缩下一轮边界。

### 2.1.8 追问

| 追问 | 回答要点 |
|---|---|
| 还有什么变体？ | 鸡尾酒排序（双向扫描）、梳排序（gap 递减的冒泡变体） |
| 什么时候用冒泡？ | 教学或 n 极小且要求代码最简；实际排序用插入排序或内置排序 |

## 2.2 选择排序

> 每轮在未排序区间选出最小值，与区间首位交换。不稳定、原地、O(n²)，无自适应。

### 2.2.1 实现

```js
function selectionSort(arr) {
  const n = arr.length;
  for (let i = 0; i < n - 1; i++) {
    let minIdx = i;
    for (let j = i + 1; j < n; j++) {
      if (arr[j] < arr[minIdx]) minIdx = j;
    }
    if (minIdx !== i) {                      // 已在位就不交换
      [arr[i], arr[minIdx]] = [arr[minIdx], arr[i]];
    }
  }
  return arr;
}
```

`minIdx !== i` 只避免原地交换，不改变不稳定的性质。

### 2.2.2 推演

`[5, 3, 8, 1]`：

```
i=0: 在 [5,3,8,1] 里找最小 → 1 在 index 3 → 交换 arr[0],arr[3] → [1,3,8,5]
i=1: 在 [3,8,5] 里找最小 → 3 在 index 1 → 不动           → [1,3,8,5]
i=2: 在 [8,5] 里找最小 → 5 在 index 3 → 交换             → [1,3,5,8]
结果 [1,3,5,8]
```

`i=1` 那轮最小值就在原位，不需要交换。

### 2.2.3 不稳定性

反例 `[2a, 2b, 1]`，a/b 只用于区分两个值相等的 2：

```
i=0: 最小值 1 在 index 2 → 交换 arr[0] 和 arr[2]
     [2a, 2b, 1] → [1, 2b, 2a]
                        ↑  ↑
                     2b 跑到了 2a 前面
```

根因是交换跨距离：`arr[0]` 被换到 `index 2`，越过了中间的 `2b`。冒泡和插入只做相邻移动；归并虽然跨数组搬运，但合并时相等元素优先取左段，因此这三者稳定。

判据：原地交换是否跨距离，或分组移动是否跨组。选择、快排、堆排、希尔会破坏稳定性。

### 2.2.4 交换次数与无自适应

| 算法 | 比较次数 | 交换/移动次数 |
|---|---|---|
| 冒泡（基础） | n(n-1)/2 | 逆序对，最坏 n(n-1)/2 |
| **选择** | n(n-1)/2（固定） | **≤ n-1** |
| 插入 | 最好 n-1，最坏 n(n-1)/2 | 逆序对（移动） |

选择排序每轮必须先扫描完整个未排序区间才能确定最小值，所以没有 O(n) 的最好情况；插入排序在 `arr[i-1] <= cur` 时一次比较就跳过。

交换成本远高于比较时（例如大结构体），选择排序优于冒泡；JS 中数组元素通常较小，交换与比较的成本接近，这个优势不明显。

### 2.2.5 常见坑

| 坑 | 后果 | 修正 |
|---|---|---|
| 忘记 `minIdx = i` 初始化 | `minIdx` 是上一轮的残留值 | 每轮重置 |
| 内层从 `i` 开始 | 多一次自己和自己比，不影响正确性 | 从 `i + 1` |
| 外层写 `i < n` | 最后一轮无意义 | `i < n - 1` |
| 以为选择排序稳定 | 稳定性判断错误 | 不稳定，反例 `[2a, 2b, 1]` |
| 用选择排序处理大数组 | O(n²) 超时 | 用 O(n log n) 算法 |

### 2.2.6 口述要点

- 每轮选最小值与区间首位交换，共 n-1 轮。
- 不稳定，反例 `[2a, 2b, 1] → [1, 2b, 2a]`；根因是跨距离交换。
- 比较次数固定 n(n-1)/2，没有自适应；交换次数最多 n-1。
- 适合交换成本高的场景；JS 中通常不用。

### 2.2.7 追问

| 追问 | 回答要点 |
|---|---|
| 怎么改成稳定？ | 把交换改成「整体后移 + 插入」，结果就是插入排序 |
| 和堆排序的关系？ | 都是每轮选最值；堆把选最值从 O(n) 降到 O(log n) |

## 2.3 插入排序

> 维护前缀 `[0, i)` 有序，把 `arr[i]` 插入正确位置。稳定、原地、自适应；升序 O(n)，随机和逆序 O(n²)。

### 2.3.1 实现

```js
function insertionSort(arr) {
  const n = arr.length;
  for (let i = 1; i < n; i++) {
    const cur = arr[i];          // 先存起来，后面会被覆盖
    let j = i - 1;
    while (j >= 0 && arr[j] > cur) {
      arr[j + 1] = arr[j];       // 比 cur 大的都后移一格
      j--;
    }
    arr[j + 1] = cur;
  }
  return arr;
}
```

1. 必须先存 `cur`：`arr[j + 1] = arr[j]` 会覆盖 `arr[i]`。
2. 条件用 `arr[j] > cur` 而不是 `>=`：相等元素不移动，保证稳定。
3. 循环结束时 `j` 指向第一个 `<= cur` 的位置，插入点是 `j + 1`。

### 2.3.2 推演

`[5, 3, 8, 1]`：

```
i=1, cur=3: 5>3 → 5 后移 → [5,5,8,1]，j=-1 → arr[0]=3 → [3,5,8,1]
i=2, cur=8: 5<8 → 不进入循环 → arr[2]=8（原地）        → [3,5,8,1]
i=3, cur=1: 8>1 → 后移；5>1 → 后移；3>1 → 后移
            [3,3,5,8] → arr[0]=1                      → [1,3,5,8]
```

`i=2` 那轮一次都没进循环体，已有序的部分直接跳过。

### 2.3.3 复杂度与逆序对

| 情况 | 比较/移动 | 复杂度 |
|---|---|---|
| 最好（已升序） | n-1 次比较，0 次移动 | **O(n)** |
| 平均 | ≈ n²/4 | O(n²) |
| 最坏（完全逆序） | n(n-1)/2 | O(n²) |
| 空间 | — | O(1) |

内层的移动次数等于该元素前面比它大的元素个数，总和**正好等于逆序对数量**。逆序对少时，移动次数少，所以部分有序数据接近 O(n)。

### 2.3.4 小数组优势

- 内层只有比较和赋值，没有递归、没有额外数组分配。
- 顺序访问数组，不跨数组跳转。
- 输入部分有序时直接受益。

工业排序通常在小区间切换插入排序（阈值多为几十个元素）；在这个范围内，常数因子比渐进复杂度更重要。

### 2.3.5 二分插入

内层用二分查找定位插入点，把每个元素的比较次数从 O(i) 降到 O(log i)。

```js
function binaryInsertionSort(arr) {
  for (let i = 1; i < arr.length; i++) {
    const cur = arr[i];
    // 在 [0, i) 里找第一个 > cur 的位置
    let lo = 0, hi = i;
    while (lo < hi) {
      const mid = (lo + hi) >> 1;
      if (arr[mid] <= cur) lo = mid + 1;   // <= 保证稳定：相等的放右边
      else hi = mid;
    }
    // lo 是插入位置，把 [lo, i) 整体后移
    for (let j = i; j > lo; j--) arr[j] = arr[j - 1];
    arr[lo] = cur;
  }
  return arr;
}
```

- 总比较次数 O(n log n)，移动次数不变，总复杂度仍是 O(n²)。
- `arr[mid] <= cur` 时 `lo = mid + 1`，相等元素插在后面，因此稳定。
- 只有比较成本远高于移动成本时才有收益。

n=10,000 随机数组实测：普通插入比较 25,114,631 次，二分插入 118,972 次；两者移动次数同为 25,104,643。

### 2.3.6 哨兵

C 语言中可在数组前留一个哨兵位，或先把最小值放到 `arr[0]`，内层就能省掉 `j >= 0` 的判断。

```js
function insertionSortSentinel(arr) {
  // 先保证 arr[0] 是最小的
  for (let i = arr.length - 1; i > 0; i--) {
    if (arr[i - 1] > arr[i]) [arr[i - 1], arr[i]] = [arr[i], arr[i - 1]];
  }
  for (let i = 2; i < arr.length; i++) {
    const cur = arr[i];
    let j = i - 1;
    while (arr[j] > cur) {        // arr[0] 一定 ≤ cur，不需要 j >= 0
      arr[j + 1] = arr[j];
      j--;
    }
    arr[j + 1] = cur;
  }
  return arr;
}
```

JS 中 `arr[-1]` 是 `undefined`，`undefined > cur` 为 `false`，不会越界；但依赖这个行为不严谨。

### 2.3.7 常见坑

| 坑 | 后果 | 修正 |
|---|---|---|
| 忘存 `cur` | `cur` 被后续赋值覆盖，结果错乱 | 先存值 |
| 内层写 `arr[j] >= cur` | 不稳定 | 用 `>` |
| 最后写 `arr[j] = cur` | 少移一位，插错位置 | `arr[j + 1] = cur` |
| 外层从 `i = 0` 开始 | `j = -1`，多一次空跑 | 从 `1` 开始 |
| 在链表上套用数组版 | 链表不支持随机访问 | 链表插入排序单独写 |

### 2.3.8 链表插入排序

```js
function insertionSortList(head) {
  const dummy = { next: head, val: -Infinity };
  let cur = head;
  while (cur && cur.next) {
    if (cur.val <= cur.next.val) {   // 已有序，跳过
      cur = cur.next;
      continue;
    }
    let prev = dummy;                // 从头找插入点
    while (prev.next.val < cur.next.val) prev = prev.next;
    const tmp = cur.next;            // 摘下 cur.next
    cur.next = tmp.next;
    tmp.next = prev.next;            // 插到 prev 后面
    prev.next = tmp;
  }
  return dummy.next;
}
```

链表找插入点是 O(n)，总体 O(n²)；需要 O(n log n) 时用归并排序。

### 2.3.9 口述要点

- 前缀有序；先存 `cur`，用 `arr[j] > cur` 后移，插入点是 `j + 1`。
- 稳定由严格 `>` 和逐个后移保证。
- 小数组优势是常数小、顺序访问、无额外分配；工业排序在小区间切插入排序。

### 2.3.10 追问

| 追问 | 回答要点 |
|---|---|
| 部分有序时为什么优于快排？ | 代价正比于逆序对，接近 O(n)；快排仍有递归和分区开销 |

## 2.4 希尔排序

> 插入排序的分组版：按 gap 分组做插入排序，gap 递减到 1。不稳定、原地；复杂度由 gap 序列决定。

### 2.4.1 问题来源

插入排序每次只移动 1 格。最小元素在末尾时要移动 n-1 次。

```
[2, 3, 4, 5, 6, 7, 8, 1]
                        ↑ 这个 1 要挪 7 次
```

希尔排序先按间隔 gap 分组，组内做插入排序，让元素一次可以移动 gap 格。

### 2.4.2 分组过程

以 `[8, 9, 1, 7, 2, 3, 5, 4, 6, 0]`、`gap = 4` 为例：

```
原数组:  8  9  1  7  2 | 3  5  4  6  0
gap=4 分组（间隔 4）:
  组1: index 0, 4, 8  → 8, 2, 6
  组2: index 1, 5, 9  → 9, 3, 0
  组3: index 2, 6     → 1, 5
  组4: index 3, 7     → 7, 4

各组内部插入排序:
  组1: 2, 6, 8
  组2: 0, 3, 9
  组3: 1, 5
  组4: 4, 7

按原位置填回: 2 0 1 4 6 | 3 5 7 8 9
```

0 从 index 9 经两次 4 格移动到达 index 1。该示例只演示 `gap = 4` 一轮；Knuth 序列对 n=10 的后续 gap 是 1。

### 2.4.3 实现（Knuth 序列）

```js
function shellSort(arr) {
  const n = arr.length;
  // 1. 生成 Knuth 序列：1, 4, 13, 40, 121...  满足 h = 3h + 1
  let gap = 1;
  while (gap < n / 3) gap = gap * 3 + 1;

  // 2. 从大到小枚举 gap
  for (; gap >= 1; gap = Math.floor(gap / 3)) {
    // 3. 对每个 gap 做分组插入排序
    for (let i = gap; i < n; i++) {
      const cur = arr[i];
      let j = i - gap;
      while (j >= 0 && arr[j] > cur) {
        arr[j + gap] = arr[j];
        j -= gap;
      }
      arr[j + gap] = cur;
    }
  }
  return arr;
}
```

`i` 从 `gap` 递增到 `n-1`，每个 `i` 只与 `i-gap`、`i-2gap`……比较，等价于对所有同余类分别做插入排序，组间交错执行。

与插入排序只有 3 处不同：

| 位置 | 插入排序 | 希尔排序 |
|---|---|---|
| 外层起点 | `i = 1` | `i = gap` |
| 内层跨度 | `j = i - 1`，`j--` | `j = i - gap`，`j -= gap` |
| 赋值位置 | `arr[j + 1]` | `arr[j + gap]` |

### 2.4.4 gap 序列

gap 序列直接决定复杂度，这是希尔排序的参数依赖所在。

| 序列 | 生成方式 | 最坏复杂度 | 特点 |
|---|---|---|---|
| **n/2, n/4, ..., 1**（Shell 原始） | `gap = gap / 2` | O(n²) | 简单，但对某些输入退化 |
| **Knuth** | `1, 4, 13, 40, ...`，`h = 3h + 1` | O(n^1.5) | 实现简单，常用 |
| **Hibbard** | `1, 3, 7, 15, ...`，`h = 2^k - 1` | O(n^1.5) | 有理论界 |
| **Sedgewick** | `1, 5, 19, 41, 109, ...` | O(n^1.33) | 序列需硬编码 |
| **Ciura** | `1, 4, 10, 23, 57, 132, 301, 701` | 实验值 | 实践经验序列 |

原始 `n/2` 序列退化的原因是相邻 gap 有**公因子**：前几轮 gap 都是偶数时，奇数位和偶数位的元素只在各自的同余类内移动，直到 `gap = 1` 才跨类比较。

### 2.4.5 为什么比插入排序快

1. **大 gap 阶段**：每个子序列很短（约 n/gap 个元素），组内插入排序的 O(k²) 中 k 很小，总代价低；同时元素一次移动 gap 格，快速消除远处的逆序对。
2. **小 gap 阶段**：数组已经基本有序，插入排序接近 O(n)，最后几轮很便宜。

每轮扫描是 O(n)，共 O(log n) 轮；总代价还包含移动次数，Knuth 序列最坏 O(n^1.5)。平均情况没有通用严格界，只有特定 gap 序列的最坏界。

### 2.4.6 不稳定性

反例 `[2a, 2b, 1]`，手动取 `gap = 2` 演示跨组移动：

```
gap=2: 组 0,2 = 2a,1 → 1,2a；组 1 = 2b
结果: [1, 2b, 2a]
              ↑   ↑
          2b 跑到了 2a 前面
```

根因是不同 gap 分组把原本相邻的相等元素分到不同组，组内排序后跨组顺序可能反转。

### 2.4.7 复杂度

| 情况 | 复杂度 | 说明 |
|---|---|---|
| 最好（已升序） | O(n log n) | 每轮 O(n)，共 O(log n) 轮；n=10,000 实测 75,243 次比较 |
| 平均 | **约 O(n^1.3)** | n 从 1,000 增至 16,000（随机种子 7），比较次数 ×33.2（指数约 1.26），移动次数 ×38.5（约 1.32） |
| 最坏 | Knuth O(n^1.5)；原始 n/2 O(n²) | 取决于 gap 序列 |
| 空间 | O(1) | 原地 |
| 稳定 | 否 | 跨组移动 |

### 2.4.8 定位与常见坑

定位介于 O(n²) 与 O(n log n) 之间：代码二十行左右、O(1) 空间、不递归，适合栈受限或中等规模数据；需要稳定或数据量极大时不选。

n=10,000 随机实测，希尔排序的比较和移动次数比插入排序少约两个数量级（见 2.5.1）。

| 坑 | 后果 | 修正 |
|---|---|---|
| `gap` 最后没到 1 | 数组没有完全排序 | 循环条件 `gap >= 1` |
| 内层写成 `j -= 1` | 步长与分组不一致 | `j -= gap` |
| 赋值写成 `arr[j+1] = cur` | 位置错 | `arr[j + gap] = cur` |
| 生成和递减规则不一致 | 可能跳过某些 gap | 用同一套规则 |
| 以为它是稳定的 | 稳定性判断错误 | 不稳定 |

最容易犯的致命错误是 gap 没降到 1：

```js
// 错误：gap 只到 2
for (; gap > 1; gap = Math.floor(gap / 3)) { ... }
// 正确
for (; gap >= 1; gap = Math.floor(gap / 3)) { ... }
```

### 2.4.9 口述要点

- 按 gap 分组做插入排序，gap 递减到 1。
- 大 gap 让元素大步移动，快速减少逆序对；小 gap 阶段数组已基本有序。
- 不稳定，跨组移动会越过相等元素。
- 复杂度由 gap 序列决定：Knuth 最坏 O(n^1.5)，平均实测约 n^1.3，无通用严格界。
- gap 必须降到 1。

## 2.5 四者横向对比

### 2.5.1 总表

| | 冒泡 | 选择 | 插入 | 希尔 |
|---|---|---|---|---|
| 平均 | O(n²) | O(n²) | O(n²) | ~O(n^1.3) |
| 最好 | **O(n)** | O(n²) | **O(n)** | O(n log n) |
| 最坏 | O(n²) | O(n²) | O(n²) | O(n^1.5)~O(n²) |
| 空间 | O(1) | O(1) | O(1) | O(1) |
| 稳定 | 是 | 否 | 是 | 否 |
| 自适应 | 是（`swapped`） | 否 | 是 | 部分 |
| 一句话 | 教学用 | 交换最少 | **小数组之王** | 插入的加速版 |

实测条件：n=10,000，随机数组（种子 42，逆序对 25,104,643）；对拍使用 10,000 个长度 0~60、含重复值的随机数组（种子 20261027），全部与 `Array.sort((a,b)=>a-b)` 一致。

| 算法（n=10,000 随机） | 比较次数 | 交换/移动次数 |
|---|---|---|
| 冒泡（基础） | 49,995,000 | 25,104,643 |
| 冒泡（`swapped`） | 49,987,250 | 25,104,643 |
| 冒泡（`lastSwap`） | 49,943,904 | 25,104,643 |
| 选择 | 49,995,000 | 9,991 |
| 插入 | 25,114,631 | 25,104,643 |
| 二分插入 | 118,972 | 25,104,643 |
| 希尔（Knuth） | 241,961 | 171,027 |

最好/最坏情况实测（n=10,000）：

| 算法 | 已升序 比较 / 交换或移动 | 完全逆序 比较 / 交换或移动 |
|---|---|---|
| 冒泡（`swapped`） | 9,999 / 0 | 49,995,000 / 49,995,000 |
| 选择 | 49,995,000 / 0 | 49,995,000 / 5,000 |
| 插入 | 9,999 / 0 | 49,995,000 / 49,995,000 |
| 希尔（Knuth） | 75,243 / 0 | 120,190 / 53,704 |

稳定性实测（`[2a, 2b, 1]`）：冒泡、插入、二分插入得到 `1, 2a, 2b`；选择、希尔（gap=2,1）得到 `1, 2b, 2a`。

### 2.5.2 同输入对比（`[5, 3, 8, 1]`）

| 算法 | 第 1 轮后 | 第 2 轮后 | 第 3 轮后 | 总交换/移动 |
|---|---|---|---|---|
| 冒泡 | `3 5 1 8` | `3 1 5 8` | `1 3 5 8` | 4 次交换 |
| 选择 | `1 3 8 5` | `1 3 8 5` | `1 3 5 8` | 2 次交换 |
| 插入 | `3 5 8 1` | `3 5 8 1` | `1 3 5 8` | 4 次移动 |
| 希尔（gap=2→1） | `5 1 8 3` | `1 3 5 8` | — | 4 次移动 |

希尔在 gap=2 一轮后是 `5 1 8 3`，1 从 index 3 移到 index 1；gap=1 一轮后有序。

### 2.5.3 选型

| 条件 | 选择 |
|---|---|
| 数据量 < 50 | 插入排序（常数最小） |
| 需要稳定 | 归并排序 |
| 内存紧张 | 堆排序（O(1) 空间，最坏 O(n log n)） |
| 其他情况 | 快排 |

冒泡和选择排序不在常规选型中。

## 2.6 本册速记卡

```
稳定性判据：相等元素是否可能跨距离/跨组移动
  → 冒泡、插入稳定；选择、希尔不稳定

逆序对等式：冒泡交换次数 = 插入移动次数 = 逆序对数量

会把「未排完」当结果交出去的边界：希尔 gap 未降到 1

二分插入只改变比较次数，不改变移动次数
```
