# 算法 · 04 线性排序：计数 / 桶 / 基数

> 本册覆盖：计数排序、桶排序、基数排序
> 这三种是**非比较排序**，能突破 Ω(n log n) 下界。但**代价是额外的假设**：值域有限、分布均匀、位数固定。
> 面试考的不是默写（这三种代码都很短），而是：**你为什么能比 O(n log n) 快？代价是什么？什么时候不能用？**

---

## 4.0 为什么它们能突破 O(n log n)

### 4.0.1 比较排序的下界

前面说过：n 个元素有 `n!` 种排列，每次比较只产生 1 bit 信息。把「比较过程」画成决策树，叶子数必须 ≥ `n!`，所以树高 ≥ `log₂(n!) ≈ n log n`。

**这个下界只对「基于比较」的算法成立。**

### 4.0.2 非比较排序的「作弊」方式

| 算法 | 绕开比较的方式 | 付出的代价 |
|---|---|---|
| **计数** | 用**值本身当数组下标**，统计出现次数 | 需要值域 `k` 有限，空间 O(k) |
| **桶** | 用**值映射到桶编号**，桶内再排序 | 需要数据**均匀分布**，否则退化 |
| **基数** | 按**每一位**分别分配收集，不比较大小 | 需要**定长**（或可提取位），多轮 O(d) |

**一句话**：它们把「比较」换成了「**用值算出一个位置**」。这需要额外的结构假设——**没有免费的午餐**。

### 4.0.3 什么时候不能用

```
数据是任意精度的浮点数？
  └─ 计数/基数 → ❌（值域无限，位数不定）
  └─ 桶 → ⚠️ 可以，但依赖分布

数据是字符串？
  └─ 计数 → ❌
  └─ 基数 → ✅（按字符位，LSD 从末尾字符开始）

数据值域极大（比如 0 ~ 10^9）但只有 10^5 个元素？
  └─ 计数 → ❌（要开 10^9 的数组，内存爆）
  └─ 快排/归并 → ✅ 反而更省
```

**判断口诀**：**「n 大、k 小（或 d 小），才用线性排序」**。如果 `k >> n`，计数排序的 O(k) 空间会直接把你拖死。

## 4.1 计数排序

### 一句话结论

**统计每个值出现了几次，然后按值从小到大「填」回结果数组。** 时间 O(n + k)（k 是值域大小），空间 O(k)，**正确实现时稳定**。适合**整数且值域小**的场景。

### 4.1.1 最直观的版本（不稳定）

```js
function countingSortSimple(arr, max) {
  const count = new Array(max + 1).fill(0);
  for (const x of arr) count[x]++;          // 1. 计数

  const res = [];
  for (let v = 0; v <= max; v++) {          // 2. 按值从小到大输出
    while (count[v]-- > 0) res.push(v);
  }
  return res;
}
```

这就是原题单给的写法。**它是对的，但有三个问题**：

| 问题 | 说明 |
|---|---|
| ① **不稳定** | 只输出了「值」，丢失了「原对象」。如果有卫星数据（比如学生记录按分数排序），同分学生的顺序无法保留 |
| ② **不支持负数** | `count[-3]` 是 `undefined`，`undefined++` 得 `NaN` |
| ③ **必须预知 `max`** | 传错了就漏数据或数组越界 |

**什么时候这个版本够用？** 只排序纯数字（没有关联数据）、且确定值域。面试可以先写这个讲思路，**然后主动说「但它是通过值直接输出的，不稳定，如果需要稳定要改成前缀和 + 逆序回填」**——这一句就是加分点。

### 4.1.2 稳定版（前缀和 + 逆序回填）

**这是计数排序的「标准答案」，也是能当基数排序子过程的唯一版本。**

```js
function countingSort(arr, min, max) {
  const range = max - min + 1;
  const count = new Array(range).fill(0);

  // 1. 计数（用 x - min 处理负数）
  for (const x of arr) count[x - min]++;

  // 2. 前缀和：count[i] 变成「值 <= i+min 的元素个数」
  //    也就等于「值为 i+min 的元素在结果数组里的"末尾下标 + 1"」
  for (let i = 1; i < range; i++) count[i] += count[i - 1];

  // 3. 逆序回填（★ 逆序是稳定性的关键）
  const res = new Array(arr.length);
  for (let i = arr.length - 1; i >= 0; i--) {
    const idx = arr[i] - min;
    res[--count[idx]] = arr[i];
  }
  return res;
}
```

**为什么是「逆序」回填？**

`count[idx]` 是「值 ≤ arr[i] 的元素个数」，也就是「arr[i] 应该放的最后一个位置 + 1」。所以 `--count[idx]` 就是它该放的位置。

如果**正序**回填，第一个遇到的元素放到最后，第二个放到倒数第二……**同值元素的顺序会被反转**。

如果**逆序**回填，最后一个遇到的元素放到最后，第一个遇到的放到最前 → **同值元素保持原顺序 → 稳定**。

**逐步推演** `[3, 1, 3, 2]`（min=1, max=3）：

```
计数:      count = [1, 1, 2]        （值 1 出现 1 次，值 2 出现 1 次，值 3 出现 2 次）
前缀和:    count = [1, 2, 4]        （≤1 的有 1 个，≤2 的有 2 个，≤3 的有 4 个）

逆序回填:
i=3, arr[3]=2, idx=1: --count[1]=1 → res[1]=2    count=[1,1,4]
i=2, arr[2]=3, idx=2: --count[2]=3 → res[3]=3    count=[1,1,3]
i=1, arr[1]=1, idx=0: --count[0]=0 → res[0]=1    count=[0,1,3]
i=0, arr[0]=3, idx=2: --count[2]=2 → res[2]=3    count=[0,1,2]

结果: [1, 2, 3, 3] ✅
```

**稳定性验证**：原数组的两个 `3` 分别在 index 0 和 index 2，结果中也在 `res[2]` 和 `res[3]`，**顺序没变** ✅。

### 4.1.3 支持负数的版本

关键是引入 `offset = -min`，把所有值平移到 ≥ 0。

```js
function countingSortAuto(arr) {
  const n = arr.length;
  if (n < 2) return arr.slice();

  let min = arr[0], max = arr[0];
  for (const x of arr) { if (x < min) min = x; if (x > max) max = x; }

  const range = max - min + 1;
  // ⚠️ 保护：值域太大时放弃，退回比较排序
  if (range > 1e7) return arr.slice().sort((a, b) => a - b);

  const count = new Array(range).fill(0);
  for (const x of arr) count[x - min]++;
  for (let i = 1; i < range; i++) count[i] += count[i - 1];

  const res = new Array(n);
  for (let i = n - 1; i >= 0; i--) {
    res[--count[arr[i] - min]] = arr[i];
  }
  return res;
}
```

**`if (range > 1e7)` 这一行很重要**——它体现了「知道算法的适用边界」。生产代码里不加这个判断，遇到 `[0, 1000000000]` 这样的输入直接内存爆炸。

### 4.1.4 复杂度

| 项目 | 复杂度 | 说明 |
|---|---|---|
| 时间 | **O(n + k)** | n 次计数 + k 次前缀和 + n 次回填 |
| 空间 | **O(k)** | count 数组；结果数组 O(n) |
| 稳定 | ✅ | 逆序回填 |

**关键**：当 `k = O(n)` 时，总复杂度是 **O(n)**，这才是「线性排序」的含义。

**当 k 远大于 n 时**：比如 n = 10⁵、k = 10⁹，空间 10⁹ 个槽 → 4GB，直接不可用。**这时候 O(n log n) 的比较排序反而是最优解**。

> 面试话术：「计数排序是 O(n+k)，只有当 k 和 n 同阶时才是真正的线性。如果值域远大于数据量，开 count 数组的代价比排序本身还大，应该退回快排。」

### 4.1.5 应用场景

| 场景 | 为什么适合 |
|---|---|
| **成绩排序（0~100）** | k = 101，极小 |
| **年龄排序（0~150）** | k = 151 |
| **字符频率统计** | k = 26 / 128 / 65536 |
| **基数排序的子过程** | 每位只有 10 个值，k = 10 |
| **位图 / 布隆过滤器的前置统计** | 值域是整数区间 |
| **「找到第一个缺失的正整数」** | 用值当索引，O(n) |
| **H 指数（LeetCode 274）** | 值域是 0~n，天然适合计数 |

**一个非排序的经典用法**：**用计数数组当「哈希表」**。

```js
// 判断两个字符串是否为字母异位词：O(n)，比 Map 更快（无哈希开销）
function isAnagram(s, t) {
  if (s.length !== t.length) return false;
  const count = new Array(26).fill(0);
  for (let i = 0; i < s.length; i++) {
    count[s.charCodeAt(i) - 97]++;
    count[t.charCodeAt(i) - 97]--;
  }
  return count.every(c => c === 0);
}
```

### 4.1.6 常见坑

| 坑 | 后果 | 修正 |
|---|---|---|
| 用 `count[x]` 不减去 min | 负数变 `NaN`，或数组巨大 | `count[x - min]` |
| 正序回填 | **不稳定** | 从 `n-1` 倒序 |
| 忘了前缀和 | `res[--count[idx]]` 位置全错 | 必须先累加 |
| 只写计数和输出（4.1.1 版） | 稳定版本做不到，不能用于基数排序 | 用前缀和版 |
| 不判断值域 | `k` 巨大时爆内存 | 加 `range` 上限保护 |
| 用 `Math.max(...arr)` 求 max | 元素超过约 10 万时 **栈溢出**（spread 参数个数上限，实测 10 万 OK、12 万抛错） | 用 `for` 循环或 `reduce` |

**关于 `Math.max(...arr)` 的坑**（很多人在大数据上踩过）：

```js
Math.max(...new Array(200000).fill(1));   // ❌ RangeError: Maximum call stack size exceeded
// 因为展开运算符把 20 万个参数压栈，超过引擎限制

// ✅ 正确写法
let max = -Infinity;
for (const x of arr) if (x > max) max = x;
```

### 4.1.7 答题模板

**30 秒版**

> 计数排序不开比较，直接用值当数组下标统计出现次数，然后按值从小到大填回结果。时间 O(n+k)，k 是值域；空间 O(k)；正确实现时稳定。
> 稳定的关键是用「前缀和 + 逆序回填」而不是直接把值 push 出来——前缀和给出每个值的末尾位置，逆序回填保证同值元素保持原顺序。
> 它只适合整数且值域小的情况，比如成绩、年龄、字符统计。值域远大于数据量时，开 count 数组反而更贵。

**2 分钟版（加分层）**

> 计数排序的思路是「用空间换比较」。三步：第一遍统计每个值出现几次；然后做前缀和，`count[i]` 表示「值 ≤ i 的元素个数」，也就等于「值为 i 的元素在结果里的末尾下标 + 1」；最后回填。
> 回填有个关键细节：必须**逆序**遍历原数组。因为同一个值的最后一个元素应该放在最靠后的位置，逆序回填正好让它先占住末尾，前面的元素依次往前放，这样同值元素的相对顺序不变，排序才是稳定的。如果正序回填，同值元素的顺序会被反转。
> 复杂度 O(n+k)。这里要强调「k 和 n 同阶才是线性」，如果值域是 10⁹ 而只有 10⁵ 个数据，开 count 数组要几 GB，这时候应该退回快排。
> 工程上它有个更常见的用法是当哈希表用——比如判断字母异位词，用长度 26 的数组代替 Map；或者「找第一个缺失的正整数」，用值当索引。这类用法比排序本身更高频。

### 4.1.8 追问表

| 追问 | 回答要点 |
|---|---|
| 计数排序为什么是稳定的？ | 前缀和 + 逆序回填，同值元素保持原序 |
| 正序回填会怎样？ | 同值元素顺序反转，不稳定 |
| 为什么能突破 O(n log n)？ | 不比较，用值当下标；代价是需要值域有限 |
| k 很大时怎么办？ | 退回比较排序，或用基数排序分位处理 |
| 支持负数吗？ | 支持，加 `offset = -min` 平移 |
| 空间复杂度？ | O(k) 的 count + O(n) 的结果数组 |
| 和 HashMap 计数有什么区别？ | 数组寻址 O(1) 无哈希开销，但要求 key 是紧凑整数 |
| 计数排序能做基数排序的子过程吗？ | 只有稳定版可以，LSD 基数排序依赖稳定性 |

## 4.2 桶排序

### 一句话结论

**把数据按值域划分成若干个桶，每个元素放进对应桶，桶内单独排序，最后按桶顺序拼接。** 平均 O(n + k)（数据均匀分布时接近 O(n)），最坏 O(n²)（全落一个桶），**稳定性取决于桶内排序算法**。

### 4.2.1 和计数排序的关系

**桶排序是计数排序的推广**：

```
计数排序：一个值 = 一个桶（桶的数量 = 值域大小 k）
桶排序：  一个区间 = 一个桶（桶的数量由你自己定）
```

所以：
- 计数排序可以看作「桶大小为 1、并且桶内不需要排序」的桶排序
- 桶排序可以处理**浮点数**（计数排序不行，因为值域无限）

### 4.2.2 实现（稳健版）

```js
function bucketSort(arr, bucketSize) {
  const n = arr.length;
  if (n < 2) return arr.slice();

  // 1. 求值域（用循环，避免 Math.max(...arr) 的栈溢出）
  let min = arr[0], max = arr[0];
  for (const x of arr) {
    if (x < min) min = x;
    if (x > max) max = x;
  }
  if (min === max) return arr.slice();       // 全部相同，直接返回（★ 原题单漏了这个）

  // 2. 定桶大小：默认让桶数量 ≈ √n
  const size = bucketSize > 0
    ? bucketSize
    : Math.max(1, Math.ceil((max - min + 1) / Math.ceil(Math.sqrt(n))));

  const count = Math.floor((max - min) / size) + 1;
  const buckets = Array.from({ length: count }, () => []);

  // 3. 分桶
  for (const x of arr) {
    const idx = Math.min(count - 1, Math.floor((x - min) / size));  // ★ 防浮点误差越界
    buckets[idx].push(x);
  }

  // 4. 桶内排序 + 拼接
  const res = [];
  for (const b of buckets) {
    if (b.length === 0) continue;
    b.sort((a, c) => a - c);        // V8 的 sort 是稳定的
    for (const x of b) res.push(x);
  }
  return res;
}
```

**三个原题单没有、但必须有的保护**：

| 保护 | 不加会怎样 |
|---|---|
| `if (min === max) return` | 全相同元素时 `(max-min)/size = 0`，`count = 1`，虽然能跑但白做一遍 |
| `bucketSize > 0` 判断 | 传 0 时 `(max-min)/0 = Infinity`，`Array.from({length: Infinity})` 直接崩 |
| `Math.min(count - 1, ...)` | 浮点除法可能算出 `count`（越界），比如 `(max-min)` 恰好整除时边界值 |

### 4.2.3 逐步推演 `[0.78, 0.17, 0.39, 0.26, 0.72, 0.94, 0.21, 0.12, 0.23, 0.68]`

`min=0.12, max=0.94`，取 5 个桶，桶宽 `(0.94-0.12)/5 ≈ 0.164`：

```
桶0 [0.12, 0.276): 0.17, 0.26, 0.21, 0.12, 0.23
桶1 [0.276, 0.44): 0.39
桶2 [0.44, 0.604): （空）
桶3 [0.604, 0.768): 0.72, 0.68
桶4 [0.768, 0.94]:  0.78, 0.94

桶内排序:
桶0 → [0.12, 0.17, 0.21, 0.23, 0.26]
桶1 → [0.39]
桶3 → [0.68, 0.72]
桶4 → [0.78, 0.94]

拼接: [0.12, 0.17, 0.21, 0.23, 0.26, 0.39, 0.68, 0.72, 0.78, 0.94] ✅
```

**注意桶0 有 5 个元素**——这就是「分布不均」的开始。如果数据全落在一个桶里，桶内排序就是 O(n²)（用插入/快排）或 O(n log n)（用归并）。

### 4.2.4 复杂度：为什么说「平均 O(n)」但「最坏 O(n²)」

**假设**：n 个元素、k 个桶、数据**均匀分布**。

每个桶的期望元素数是 `n/k`。桶内用比较排序，单桶代价 `O((n/k) log(n/k))`，k 个桶总代价：

```
k × O((n/k) log(n/k)) = O(n log(n/k))
```

当 `k ≈ n` 时，`log(n/k) = log 1 = 0` → 总代价 `O(n)`。

**这就是「桶数量要接近 n」的原因**——但桶太多又会有大量空桶（额外的 O(k) 空间和遍历开销），所以工程上取 `k ≈ √n` 或 `k ≈ n/常数`。

**最坏情况**：所有元素落在同一个桶 → 退化为「对一个桶做排序」 → O(n log n) 或 O(n²)。

| 情况 | 复杂度 | 条件 |
|---|---|---|
| 最好 | **O(n)** | 均匀分布，每桶 1 个元素 |
| 平均 | O(n + k) | 均匀分布 |
| 最坏 | **O(n²)** | 全部落一个桶 + 桶内用插入排序 |
| 空间 | O(n + k) | 桶数组 + 元素引用 |

⚠️ **注意**：桶排序并不是「任何输入都 O(n)」。它的性能**完全依赖数据分布**，这是它和计数/基数的本质区别。

### 4.2.5 稳定性

**取决于桶内用的排序算法**。

- 桶内用**插入排序**（稳定）→ 整体稳定
- 桶内用**快排**（不稳定）→ 整体不稳定
- 桶内用 `Array.prototype.sort`（V8 是 TimSort，稳定）→ 整体稳定

**前提**：分桶时按原数组顺序 `push`（本册实现满足），且拼接时按桶编号升序。

**反例**（桶内用快排）：同值的两个元素如果落进同一个桶，快排可能打乱它们的相对顺序。

> 面试话术：「桶排序的稳定性不是它自己的属性，而是继承桶内排序算法的。桶内用插入或归并就稳定，用快排就不稳定。前提是分桶和拼接都保持顺序。」

### 4.2.6 应用场景

| 场景 | 说明 |
|---|---|
| **浮点数排序** | 计数排序做不到（值域无限），桶排序可以 |
| **均匀分布的随机数** | 最理想的输入 |
| **外部排序的「分块」阶段** | 大文件按范围切块，每块单独排序 |
| **数据倾斜分析** | 桶内元素数量本身就是分布直方图 |
| **按区间分组的需求** | 比如按价格区间分档，天然就是分桶 |
| **「最大间距」类题目** | LeetCode 164 用桶排序 + 鸽巢原理做到 O(n) |

**LeetCode 164「最大间距」的思路**（面试高频，桶排序的经典应用）：

要求 O(n) 时间求排序后相邻元素的最大差。做法：
1. n 个数、值域 `[min, max]`，开 n+1 个桶，桶宽 `(max-min)/n`
2. 由鸽巢原理，**必有一个桶为空** → 最大间距一定跨越空桶
3. 只需记录每个桶的 min/max，比较「相邻非空桶」的 `后桶min - 前桶max`

**这个技巧的精髓**：不需要真的把元素排好，只需要「桶的边界信息」。

### 4.2.7 常见坑

| 坑 | 后果 | 修正 |
|---|---|---|
| 空数组调 `Math.min(...[])` | 得到 `Infinity`，后续全是 `NaN` | 先判断 `n < 2` |
| `bucketSize = 0` | 除零 → `Infinity` 个桶 | 判断 `bucketSize > 0` |
| 桶索引没做 `Math.min(count-1, ...)` | 边界值越界，`buckets[idx]` 是 `undefined` | 加上 clamp |
| `min === max` 没处理 | 桶宽为 0 | 直接返回 |
| 以为任何输入都 O(n) | 答错复杂度 | 最坏 O(n²)，依赖分布 |
| 桶内用不稳定排序还声称稳定 | 稳定性答错 | 明确说明依赖桶内算法 |
| 桶数量取 1 或 n² | 退化或空桶过多 | 取 `√n` 量级，或让桶内元素 ≈ 常数个 |

**最阴险的坑：桶索引越界**

```js
const idx = Math.floor((x - min) / size);
// 当 x === max 且 (max-min) 恰好被 size 整除时：
// (max-min)/size = count - 1（因为 count = floor((max-min)/size) + 1）
// Math.floor 后仍是 count - 1，不越界 ✅
// 但浮点误差下可能得到 count → buckets[count] 是 undefined → 崩溃
```

**所以 `Math.min(count - 1, ...)` 不是冗余，是必需的防御**。

### 4.2.8 答题模板

**30 秒版**

> 桶排序把值域切成若干个区间，每个区间一个桶，元素按值放进对应桶，桶内单独排序，最后按桶顺序拼接。
> 数据均匀分布时，每个桶约 n/k 个元素，总代价 O(n log(n/k))，当 k 接近 n 时就是 O(n)。但最坏情况是所有元素落进一个桶，退化成 O(n log n) 甚至 O(n²)。
> 它的优势是能处理浮点数（计数排序不行），稳定性取决于桶内用的排序算法。

**2 分钟版（加分层）**

> 桶排序可以看成计数排序的推广：计数排序是「一个值一个桶」，桶排序是「一个区间一个桶」，所以桶排序能处理浮点数。
> 实现四步：求 min/max 确定值域；定桶宽、开桶；按 `(x-min)/size` 算索引分桶；桶内排序后拼接。
> 复杂度要说清前提：均匀分布下每桶 n/k 个元素，桶内比较排序是 O((n/k)log(n/k))，k 个桶合计 O(n log(n/k))，k≈n 时是 O(n)。但**最坏情况全落一个桶，就退化成一次普通排序**，所以它不是「任何输入都线性」。桶数量一般取 √n 量级，太多会产生大量空桶。
> 稳定性不是它自身的属性，而是继承桶内算法的——桶内用插入或归并就稳定，用快排就不稳定。
> 工程上有两个典型用法。一是浮点数排序和外部排序的分块阶段。二是一个技巧性用法：LeetCode 164 最大间距，用 n+1 个桶配合鸽巢原理，必有一个空桶，最大间距一定跨空桶，所以只需比较相邻非空桶的边界，做到 O(n)。

### 4.2.9 追问表

| 追问 | 回答要点 |
|---|---|
| 桶排序和计数排序的关系？ | 计数是一个值一个桶，桶排序是一个区间一个桶（前者是后者的特例） |
| 桶排序的复杂度？ | 平均 O(n+k)，最坏 O(n²)，依赖分布 |
| 桶数量怎么定？ | 约 √n，或让每桶元素数为常数 |
| 桶排序稳定吗？ | 取决于桶内排序算法；分桶和拼接要保持顺序 |
| 为什么桶排序能排浮点数？ | 按区间分桶，不需要值当离散下标 |

## 4.3 基数排序

> ⚠️ **原题单的代码有两个 bug**（不支持负数、`Math.max(...arr)` 栈溢出），这里给修正版。

### 一句话结论

**按「位」排序：从最低位开始，每一位做一次稳定的计数排序，做完最高位整个数组就有序了。** 时间 O(d(n + k))（d 是位数，k 是进制，十进制时 k=10），空间 O(n + k)，**稳定**。适合**定长整数、定长字符串**。

### 4.3.1 核心思想：为什么从低位开始也行

这是基数排序最反直觉的地方。**关键在于「稳定性」**。

以 `[170, 45, 75, 90, 802, 24, 2, 66]` 为例：

```
初始:      170  45  75  90  802  24  2  66
按个位:    170  90  802  2  24  45  75  66
           （个位 0:170,90；2:802,2；4:24；5:45,75；6:66）
按十位:    802  2  24  45  66  170  75  90
           （十位 0:802,2；2:24；4:45；6:66；7:170,75；9:90）
按百位:    2  24  45  66  75  90  170  802
```

**为什么第二趟（十位）不会破坏第一趟（个位）的结果？**

因为第一趟是**稳定**的：在十位相同的一组里（比如十位为 0 的 `802, 2`），它们**保持了个位排序后的相对顺序**（802 的个位 2 < 2 的个位 2... 等一下，这里 802 和 2 个位都是 2）。

换个更清晰的例子：`[21, 11]`，个位都是 1，十位 2 > 1。
- 个位排序后：`[21, 11]`（不变，因为个位相同，稳定保持原序）
- 十位排序后：`[11, 21]` ✅
- 如果个位排序**不稳定**，可能变成 `[11, 21]`，然后十位排序变成 `[21, 11]` —— **错的**

**核心逻辑**：高位排序时，低位已经排好的顺序作为「同高位元素之间的次序」被保留下来。**这就是为什么基数排序必须稳定**——不稳定的低位排序会被后一轮完全破坏。

> 面试话术：「基数排序的正确性完全建立在稳定排序上。每一轮只按当前位排序，低位的信息靠稳定性被『携带』到后面。如果某一轮不稳定，低位做的功就白费了。」

### 4.3.2 LSD vs MSD

| | **LSD**（Least Significant Digit） | **MSD**（Most Significant Digit） |
|---|---|---|
| 顺序 | 从最低位到最高位 | 从最高位到最低位 |
| 实现 | 迭代，d 轮 | 递归（每个桶内递归下一轮） |
| 是否需要稳定 | **必须** | 不需要（因为不跨桶） |
| 适用 | 定长数据（整数、定长字符串） | 变长字符串（字典序） |
| 中途能否得到有序 | 不能，必须做完 d 轮 | 能，高位相同时才需要往下递归 |
| 典型实现 | 本册的版本 | 字符串排序、后缀数组 |

**面试一般问 LSD**，答一句「MSD 用于变长字符串的字典序」就够。

### 4.3.3 实现（修正原题单的两个 bug）

**原题单的代码**：

```js
function radixSort(arr) {
  const max = Math.max(...arr);                   // ❌ bug 1：大数组栈溢出
  for (let digit = 1; digit <= max; digit *= 10) {
    const buckets = Array.from({ length: 10 }, () => []);
    for (const num of arr) {
      buckets[Math.floor(num / digit) % 10].push(num);   // ❌ bug 2：负数取模得到负数下标
    }
    arr = [].concat(...buckets);                  // ⚠️ 每次新建数组，O(n) 分配
  }
  return arr;
}
```

| bug | 后果 |
|---|---|
| `Math.max(...arr)` | 元素超过约 10 万时 `RangeError: Maximum call stack size exceeded`（实测 10 万 OK、12 万抛错） |
| 负数没处理 | `-5 % 10 = -5`（JS 取模保留符号）→ `buckets[-5]` 是 `undefined` → `.push` 报错 |
| `[].concat(...buckets)` | 每次合并都新建数组，虽然总复杂度仍是 O(n)，但分配次数多 |

**修正版**：

```js
function radixSort(arr) {
  const n = arr.length;
  if (n < 2) return arr.slice();

  // 1. 求值域（用循环，不用 Math.max(...arr)）
  let min = arr[0], max = arr[0];
  for (const x of arr) {
    if (x < min) min = x;
    if (x > max) max = x;
  }

  // 2. 负数偏移：把所有数平移到 >= 0（JS 的 % 对负数返回负数）
  const offset = min < 0 ? -min : 0;
  let a = new Array(n);
  for (let i = 0; i < n; i++) a[i] = arr[i] + offset;
  const maxVal = max + offset;

  // 3. 从低位到高位，每轮做一次稳定的计数排序
  for (let exp = 1; Math.floor(maxVal / exp) > 0; exp *= 10) {
    a = countingByDigit(a, exp);
  }

  // 4. 还原偏移
  const res = new Array(n);
  for (let i = 0; i < n; i++) res[i] = a[i] - offset;
  return res;
}

// 按第 exp 位做稳定计数排序（k = 10）
function countingByDigit(a, exp) {
  const n = a.length;
  const count = new Array(10).fill(0);

  for (let i = 0; i < n; i++) {
    count[Math.floor(a[i] / exp) % 10]++;
  }
  for (let i = 1; i < 10; i++) count[i] += count[i - 1];

  const out = new Array(n);
  for (let i = n - 1; i >= 0; i--) {         // ★ 逆序回填 → 稳定
    const d = Math.floor(a[i] / exp) % 10;
    out[--count[d]] = a[i];
  }
  return out;
}
```

**为什么循环条件是 `Math.floor(maxVal / exp) > 0`？**

`maxVal = 802` 时：
- `exp=1`：`802/1 = 802 > 0` ✅ 处理个位
- `exp=10`：`802/10 = 80 > 0` ✅ 处理十位
- `exp=100`：`802/100 = 8 > 0` ✅ 处理百位
- `exp=1000`：`802/1000 = 0`，不 > 0 → 停止 ✅

**用 `Math.floor` 是必须的**：如果写 `maxVal / exp > 0`，那么 `802/1000 = 0.802 > 0` 也会成立，会多跑一轮（虽然不影响正确性，但白做）。

### 4.3.4 逐步推演 `[170, 45, 75, 90, 802, 24, 2, 66]`

```
第 1 轮（exp=1，个位）:
  个位: 170→0  45→5  75→5  90→0  802→2  24→4  2→2  66→6
  桶0: [170, 90]   桶2: [802, 2]   桶4: [24]   桶5: [45, 75]   桶6: [66]
  结果: [170, 90, 802, 2, 24, 45, 75, 66]

第 2 轮（exp=10，十位）:
  十位: 170→7  90→9  802→0  2→0  24→2  45→4  75→7  66→6
  桶0: [802, 2]  桶2: [24]  桶4: [45]  桶6: [66]  桶7: [170, 75]  桶9: [90]
  结果: [802, 2, 24, 45, 66, 170, 75, 90]

第 3 轮（exp=100，百位）:
  百位: 802→8  2→0  24→0  45→0  66→0  170→1  75→0  90→0
  桶0: [2, 24, 45, 66, 75, 90]  桶1: [170]  桶8: [802]
  结果: [2, 24, 45, 66, 75, 90, 170, 802] ✅
```

**观察第 2 轮的桶 0**：`[802, 2]` —— 这两个数十位都是 0，它们的顺序是「第 1 轮个位排序后的顺序」。**这就是稳定性的作用**：个位都是 2，第 1 轮保持原序（802 在 2 前面），第 2 轮也保持。到第 3 轮，802 的百位是 8，2 的百位是 0，终于区分开了，802 落到最后一个桶 → 排到最后 ✅

### 4.3.5 复杂度

| 项目 | 复杂度 | 说明 |
|---|---|---|
| 时间 | **O(d(n + k))** | d 轮，每轮一次计数排序 O(n + k) |
| 空间 | **O(n + k)** | 每轮需要 out 数组 O(n) + count O(k) |
| 稳定 | ✅ | 逆序回填保证 |

**十进制整数**：`k = 10`、`d = log₁₀(max)`。

- `max = 10⁶` → `d = 7` → `O(7n)` ≈ **线性**
- `max = 2³²` → `d = 10` → `O(10n)` ≈ 线性

**所以计算机实现里通常用更大的基数**（比如 2¹⁶ = 65536，k 大但 d 小）：

| 基数 | d（32 位整数） | 每轮代价 | 总代价 |
|---|---|---|---|
| 10 | 10 | n + 10 | 10n + 100 |
| 256 | 4 | n + 256 | 4n + 1024 |
| **2¹⁶ = 65536** | **2** | n + 65536 | **2n + 131072** |

**基数选择是「轮数」和「每轮常数」的权衡**。位宽小、d 大 → 轮数多；位宽大、k 大 → count 数组大但轮数少。**实战中常取 8 位或 16 位**。

### 4.3.6 用基数排序排字符串

**定长字符串**：把每个字符当作一位，从最后一个字符开始做 LSD。

```js
// 定长字符串数组排序（所有字符串长度相同，比如都是 6 位的编码）
function radixSortStrings(arr, len) {
  let a = arr.slice();
  for (let pos = len - 1; pos >= 0; pos--) {     // 从最后一个字符往前
    a = countingByChar(a, pos);
  }
  return a;
}
function countingByChar(a, pos) {
  const n = a.length;
  const count = new Array(128).fill(0);          // ASCII
  for (const s of a) count[s.charCodeAt(pos)]++;
  for (let i = 1; i < 128; i++) count[i] += count[i - 1];
  const out = new Array(n);
  for (let i = n - 1; i >= 0; i--) {             // 逆序回填
    out[--count[a[i].charCodeAt(pos)]] = a[i];
  }
  return out;
}
```

**变长字符串**（字典序）要用 **MSD**：先按首字符分桶，再对每个桶递归处理第二个字符。空字符串/短字符串要特殊处理（视为「比任何字符都小」）。

> 注意：变长字符串用 LSD 是错的——「ab」和「abc」在 position 2 上一个没有字符，无法对齐。

### 4.3.7 应用场景

| 场景 | 说明 |
|---|---|
| **大整数排序** | 超过 2³² 的数，按 16 位分段 |
| **定长字符串/编码** | 身份证号、订单号、车牌号 |
| **IP 地址排序** | 转成 32 位整数后基数排序，O(n) |
| **浮点数排序** | 先把浮点数的位模式转成可比较的整数（IEEE 754 技巧），再基数排序 |
| **后缀数组构造** | 倍增算法 + 基数排序，O(n log n) |
| **数据库的多列排序** | 从最后一列开始做稳定排序，等价于多级排序 |

**浮点数怎么用基数排序**（加分知识）：

IEEE 754 的浮点数不能直接当整数比较（负数部分顺序反了）。技巧：

```js
function floatToSortableInt(x) {
  const buf = new ArrayBuffer(8);
  new DataView(buf).setFloat64(0, x);
  const u = new DataView(buf).getUint32(0) * 2 ** 32 + new DataView(buf).getUint32(4);
  // 正数：翻转符号位（0→1）；负数：全部位取反
  return (u & 0x8000000000000000) ? ~u : (u | 0x8000000000000000);
}
```

> 这个技巧面试很少要求，但知道「浮点数排序可以通过位模式转换 + 基数排序做到 O(n)」很加分（Java 的 `Arrays.sort(double[])` 用的就是 dual-pivot quicksort，不是基数排序，但某些库会这么做）。

### 4.3.8 常见坑

| 坑 | 后果 | 修正 |
|---|---|---|
| 用 `Math.max(...arr)` | 大数组栈溢出 | 用循环遍历 |
| 不处理负数 | `-5 % 10 = -5` → 负下标 → `undefined.push` 崩 | 用 `offset = -min` 平移 |
| 每轮用不稳定排序 | **低位做的功被高位破坏**，结果错 | 必须用稳定的计数排序 |
| 循环条件写 `digit <= max` | 如果 max 是 100，`digit` 到 100 就停了，**漏了最高位** | `Math.floor(maxVal / exp) > 0` |
| 忘了 `Math.floor` | 多跑一轮（不影响正确性但白做） | 加 `Math.floor` |
| 最低位从 `exp=10` 开始 | 个位没排，结果错 | 从 `exp=1` 开始 |
| 用 LSD 排变长字符串 | 长度不对齐，结果错 | 变长用 MSD |
| 以为基数排序不需要额外空间 | 每轮都要 out 数组 O(n) | 空间 O(n + k) |

**最致命的坑：用不稳定排序做子过程**

```js
// ❌ 用选择排序（不稳定）做每一位
buckets → 排序时把同桶元素顺序打乱 → 低位信息丢失 → 结果错
```

**这就是为什么 4.1 节要专门讲「计数排序的稳定版」**——它是基数排序的基础。

### 4.3.9 答题模板

**30 秒版**

> 基数排序按「位」来做：从最低位开始，每一位用稳定的计数排序排一遍，做完最高位整个数组就有序了。时间 O(d(n+k))，d 是位数、k 是进制（十进制是 10），空间 O(n+k)，稳定。
> 正确性的关键是**必须用稳定排序**——低位排好的顺序要靠稳定性被高位「携带」，如果某一轮不稳定，低位做的功就白费了。
> 它适合定长整数和定长字符串。变长字符串要改用 MSD，从高位递归。

**2 分钟版（加分层）**

> 基数排序解决的是「计数排序值域太大」的问题。比如排 0 到 10⁹ 的整数，计数排序要开 10⁹ 的数组，不可能；但基数排序只要 10 个桶、做 9 轮。
> 核心是 LSD，从最低位到最高位。每一轮按当前位分配到 0~9 十个桶，然后按桶顺序收集。这里有个反直觉的点：为什么要从低位开始？因为低位的信息可以靠稳定性保留下来——高位相同的元素，它们的相对顺序就是低位排序后的顺序。所以每一轮必须是稳定排序，实现上就是计数排序加逆序回填。
> 复杂度是 O(d(n+k))。如果按十进制，32 位整数 d=10；实际实现会用更大的基数，比如 16 位，d 只有 2，虽然 count 数组变成 65536 但轮数少了很多，通常更快。
> 有两个实现坑要注意：一是负数，JS 的 `%` 对负数返回负数，直接用会得到负下标，必须先偏移到非负；二是求最大值不能用 `Math.max(...arr)`，数组超过十几万会栈溢出，要用循环。

### 4.3.10 追问表

| 追问 | 回答要点 |
|---|---|
| 为什么从低位开始？ | 低位信息靠稳定性被高位携带；从高位开始就需要递归（MSD） |
| 为什么必须稳定？ | 不稳定会破坏上一轮的低位顺序，结果错 |
| 复杂度？ | O(d(n+k))，d 是位数，k 是进制 |
| 和计数排序什么关系？ | 基数是「多轮小值域的计数排序」 |
| 支持负数吗？ | 需要先平移到非负（JS 的 % 对负数返回负数） |
| 怎么排浮点数？ | 把 IEEE 754 位模式转成可比较的整数，再基数排序 |
| LSD 和 MSD 区别？ | LSD 从低位迭代、要稳定、适合定长；MSD 从高位递归、适合变长字符串 |
| 基数取多大合适？ | 权衡轮数和 count 数组大小，常用 8 位或 16 位 |
| 什么时候不该用基数排序？ | 数据量小、值域小（不如计数）、浮点/变长（要额外处理） |

## 4.4 三者横向对比

### 4.4.1 总表

| | 计数排序 | 桶排序 | 基数排序 |
|---|---|---|---|
| 时间 | O(n + k) | 平均 O(n + k)，最坏 O(n²) | O(d(n + k)) |
| 空间 | O(k) | O(n + k) | O(n + k) |
| 稳定 | ✅（前缀和版） | 取决于桶内排序 | ✅ |
| 核心操作 | 值 → 下标 | 值 → 桶编号 | 位 → 桶编号 |
| 关键前提 | 值域 k 小 | **分布均匀** | 位数 d 小（定长） |
| 能否排浮点 | ❌ | ✅ | ✅（要转位模式） |
| 能否排字符串 | ❌ | ❌ | ✅ |
| 最脆弱的地方 | k 太大 → 爆内存 | 分布不均 → 退化 | 中途用了不稳定排序 |

### 4.4.2 三者其实是「同一家族」

```
计数排序：一个值 = 一个桶，桶内无需排序
   ↓ 把「值」换成「区间」
桶排序：  一个区间 = 一个桶，桶内需要排序
   ↓ 把「区间」限定为「某一位的取值范围」
基数排序：一个位值 = 一个桶，做 d 轮
```

**理解了这层关系，面试时就能串起来讲**：

> 「这三种其实是同一思路的不同粒度：都是把值映射到一个桶，然后按桶顺序输出。计数排序的桶最细（一个值一个），桶排序最粗（一个区间一个），基数排序是「按位分桶、做多轮」。所以计数排序能当基数排序的子过程，而桶排序是计数排序在浮点上的推广。」

### 4.4.3 选型决策树

```
要排序的是什么？
├─ 整数，值域小（k ≈ n）
│    └─ 计数排序（O(n)，最简单）
├─ 整数，值域大（k >> n）
│    ├─ 定长（≤ 64 位）→ 基数排序
│    └─ 任意精度 → 快排/归并
├─ 浮点数
│    ├─ 分布均匀 → 桶排序
│    └─ 分布未知 → 快排（快排对浮点没有特殊问题）
├─ 定长字符串 → 基数排序（LSD）
├─ 变长字符串 → 基数排序（MSD）或归并
└─ 对象/复杂数据 → 归并（稳定）或快排（快）
```

### 4.4.4 一句话记住

| 算法 | 一句话 |
|---|---|
| **计数** | 值域小就数一数，最省事 |
| **桶** | 分布均匀就分区间，能排浮点 |
| **基数** | 位数少就按位来，稳定是命门 |

## 4.5 本册速记卡

```
为什么能突破 Ω(n log n)
  不比较，用「值」算出位置；代价是需要结构假设（值域/分布/定长）
  判断口诀：n 大、k 小（或 d 小）才用线性排序

计数排序
  三步：计数 → 前缀和 → 逆序回填
  前缀和含义：count[i] = 「值 ≤ i 的元素个数」= 「值为 i 的末尾下标 + 1」
  逆序回填是稳定性来源（正序会把同值元素反转）
  负数：offset = -min
  范围保护：range > 1e7 就退回 sort
  复杂度 O(n+k)；k >> n 时反而更慢

桶排序
  计数排序的推广：一个区间一个桶，能排浮点
  复杂度依赖分布：均匀 O(n)，全落一桶 O(n²)
  桶数取 √n 量级
  稳定性继承桶内算法
  三个保护：n<2 早返回、bucketSize>0、索引 clamp
  LeetCode 164 最大间距：n+1 桶 + 鸽巢原理 → O(n)

基数排序
  LSD：从低位到高位，每轮稳定计数排序
  正确性 = 稳定性（低位信息靠稳定性被高位携带）
  负数：offset = -min（JS 的 % 对负数返回负数）
  位数循环：Math.floor(maxVal / exp) > 0
  不用 Math.max(...arr)（>10 万元素栈溢出，实测 12 万抛 RangeError）
  复杂度 O(d(n+k))；基数越大 d 越小，但 count 数组越大
  LSD 排定长，MSD 排变长字符串
```
