## 4.0 为什么它们能突破 O(n log n)

### 4.0.1 比较排序的下界

n 个元素有 `n!` 种排列，一次比较只产生 1 bit 信息。把比较过程画成决策树，叶子数必须 ≥ `n!`，所以树高 ≥ `log₂(n!) = Θ(n log n)`。

**这个下界只对「只靠比较」的算法成立。**

### 4.0.2 非比较排序的绕开方式

| 算法 | 绕开比较的方式 | 付出的代价 |
|---|---|---|
| **计数** | 用**值本身当数组下标**，统计出现次数 | 需要值域 `k` 有限，空间 O(k) |
| **桶** | 用**值映射到桶编号**，桶内再排序 | 需要数据**均匀分布**，否则退化 |
| **基数** | 按**每一位**分别分配收集，不比较大小 | 需要**定长**（或可提取位），多轮 O(d) |

**共同点**：把「比较」换成「用值算出一个位置」——下标、桶号或位号。

### 4.0.3 什么时候不能用

```
数据是任意精度浮点数（非 IEEE 754 定长编码）？
  └─ 计数/基数 → ❌（值域与位数不固定）
  └─ 桶 → ⚠️ 可以，但依赖分布

数据是字符串？
  └─ 计数 → ❌
  └─ 基数 → ✅ 定长按字符位；变长用 MSD

数据值域极大（比如 0 ~ 10^9）但只有 10^5 个元素？
  └─ 计数 → ❌（要开 10^9 的数组，内存爆）
  └─ 快排/归并 → ✅ 反而更省
```

**判断口诀**：n 大、k 小（或 d 小）才用线性排序；`k >> n` 时 O(k) 空间会超过收益。

## 4.1 计数排序

### 4.1 一句话结论

统计每个值出现了几次，再按值从小到大写回结果。时间 `O(n + k)`（k 是值域大小），空间 `O(n + k)`（count 数组 O(k) + 结果数组 O(n)），**前缀和 + 逆序回填时稳定**。适合**整数且值域小**的场景。

### 4.1.1 直接输出值的版本（不稳定）

```js
function countingSortSimple(arr, max) {
  const count = new Array(max + 1).fill(0);
  for (const x of arr) count[x]++;          // 1. 计数

  const res = [];
  for (let v = 0; v <= max; v++) {          // 2. 按值从小到大输出
    while (count[v]-- > 0) res.push(v);
  }
  return res;
}
```

三处限制：

| 问题 | 说明 |
|---|---|
| ① **不稳定** | 只写回「值」，丢失卫星数据；同值记录的原始顺序无法保留 |
| ② **不支持负数** | `count[-3]` 是 `undefined`，`undefined++` 得到 `NaN`（实测 `[-3, 1, 2]` 返回 `[1, 2]`） |
| ③ **必须预知 `max`** | 传错了就漏数据或数组越界 |

只排纯数字、且值域已知时可用；需要稳定、负数或卫星数据时用下一版。

### 4.1.2 稳定版（前缀和 + 逆序回填）

```js
function countingSort(arr, min, max) {
  const range = max - min + 1;
  const count = new Array(range).fill(0);

  // 1. 计数（用 x - min 处理负数）
  for (const x of arr) count[x - min]++;

  // 2. 前缀和：count[i] 变成「值 <= i+min 的元素个数」
  for (let i = 1; i < range; i++) count[i] += count[i - 1];

  // 3. 逆序回填（★ 逆序是稳定性的关键）
  const res = new Array(arr.length);
  for (let i = arr.length - 1; i >= 0; i--) {
    const idx = arr[i] - min;
    res[--count[idx]] = arr[i];
  }
  return res;
}
```

`count[idx]` 是「值 ≤ `arr[i]` 的元素个数」，也是 `arr[i]` 在结果中的「末尾下标 + 1」，所以 `--count[idx]` 就是它的落点。

正序回填时，第一个遇到的元素被放到最后，同值元素的顺序会被反转；逆序回填让最后遇到的元素占末尾、先遇到的留在前面，同值元素保持原序。

逐步推演 `[3, 1, 3, 2]`（min=1, max=3）：

```
计数:      count = [1, 1, 2]        （值 1 出现 1 次，值 2 出现 1 次，值 3 出现 2 次）
前缀和:    count = [1, 2, 4]        （≤1 的有 1 个，≤2 的有 2 个，≤3 的有 4 个）

逆序回填:
i=3, arr[3]=2, idx=1: --count[1]=1 → res[1]=2    count=[1,1,4]
i=2, arr[2]=3, idx=2: --count[2]=3 → res[3]=3    count=[1,1,3]
i=1, arr[1]=1, idx=0: --count[0]=0 → res[0]=1    count=[0,1,3]
i=0, arr[0]=3, idx=2: --count[2]=2 → res[2]=3    count=[0,1,2]

结果: [1, 2, 3, 3] ✅
```

两个 `3` 在结果中仍是先 index 0 后 index 2，稳定性成立。10,000 个 `[-1e5, 1e5]` 随机整数与 `sort` 对拍一致；2,000 条同值记录逆序回填后 id 保持升序。

### 4.1.3 支持负数的版本

关键是引入 `offset = -min`，把所有值平移到 ≥ 0：

```js
function countingSortAuto(arr) {
  const n = arr.length;
  if (n < 2) return arr.slice();

  let min = arr[0], max = arr[0];
  for (const x of arr) { if (x < min) min = x; if (x > max) max = x; }

  const range = max - min + 1;
  // ⚠️ 保护：值域太大时放弃，退回比较排序
  if (range > 1e7) return arr.slice().sort((a, b) => a - b);

  const count = new Array(range).fill(0);
  for (const x of arr) count[x - min]++;
  for (let i = 1; i < range; i++) count[i] += count[i - 1];

  const res = new Array(n);
  for (let i = n - 1; i >= 0; i--) {
    res[--count[arr[i] - min]] = arr[i];
  }
  return res;
}
```

`range` 直接决定 count 数组长度。实测：

```
[-1e9, 1e9]                          → range = 2,000,000,001
new Array(1e8).fill(0)               → heapUsed +3819.8MB（Node 22.12）
new Array(2,000,000,001).fill(0)     → --max-old-space-size=256 下 exit 134，堆内存耗尽
```

所以加上 `range > 1e7` 的上限，超过就退回 `sort`。

### 4.1.4 复杂度

| 项目 | 复杂度 | 说明 |
|---|---|---|
| 时间 | **O(n + k)** | n 次计数 + k 次前缀和 + n 次回填 |
| 空间 | **O(n + k)** | count 数组 O(k) + 结果数组 O(n) |
| 稳定 | ✅ | 逆序回填 |

当 `k = O(n)` 时，总复杂度是 **O(n)**，这才是「线性排序」的含义。

### 4.1.5 应用场景

| 场景 | 为什么适合 |
|---|---|
| **成绩排序（0~100）** | k = 101，极小 |
| **年龄排序（0~150）** | k = 151 |
| **字符频率统计** | k = 26 / 128 / 65536 |
| **基数排序的子过程** | 每位只有 10 个值，k = 10 |
| **「找到第一个缺失的正整数」** | 用值当索引，O(n) |
| **H 指数（LeetCode 274）** | 值域是 0~n，天然适合计数 |

**非排序用法：计数数组当哈希表**

```js
// 判断两个字符串是否为字母异位词：O(n)
function isAnagram(s, t) {
  if (s.length !== t.length) return false;
  const count = new Array(26).fill(0);
  for (let i = 0; i < s.length; i++) {
    count[s.charCodeAt(i) - 97]++;
    count[t.charCodeAt(i) - 97]--;
  }
  return count.every(c => c === 0);
}
```

### 4.1.6 常见坑

| 坑 | 后果 | 修正 |
|---|---|---|
| 用 `count[x]` 不减去 min | 负数变 `NaN`，或数组巨大 | `count[x - min]` |
| 正序回填 | **不稳定** | 从 `n-1` 倒序 |
| 忘了前缀和 | `res[--count[idx]]` 位置全错 | 必须先累加 |
| 只写计数和输出（4.1.1 版） | 不能用于基数排序 | 用前缀和版 |
| 用 `Math.max(...arr)` 求 max | 大数组触发 spread 参数上限，栈溢出 | 用 `for` 循环或 `reduce` |

实测 `Math.max(...new Array(n).fill(1))`：

```
n=100000 → ok
n=120000 → RangeError: Maximum call stack size exceeded
n=200000 → RangeError: Maximum call stack size exceeded
```

正确写法：

```js
let max = -Infinity;
for (const x of arr) if (x > max) max = x;
```

### 4.1.7 答题要点

- 三步：计数 → 前缀和 → 逆序回填；时间 O(n+k)，空间 O(n+k)。
- 稳定性来自逆序回填；正序回填会把同值元素顺序反转。
- 负数先减 `min`；`range` 过大（实测 `[-1e9, 1e9]` 为 2,000,000,001）退回比较排序。
- 只适合整数小值域；`k` 与 `n` 同阶时才是线性。

### 4.1.8 追问表

| 追问 | 回答要点 |
|---|---|
| 正序回填会怎样？ | 同值元素顺序反转，不稳定 |
| k 很大时怎么办？ | 退回比较排序，或用基数排序分位处理 |
| 支持负数吗？ | 支持，加 `offset = -min` 平移 |
| 和 HashMap 计数有什么区别？ | 数组寻址 O(1)、无哈希开销，但要求 key 是紧凑整数 |
| 计数排序能做基数排序的子过程吗？ | 只有稳定版可以；LSD 基数排序依赖稳定性 |

## 4.2 桶排序

### 4.2 一句话结论

按值域划分若干区间，元素进对应桶，桶内单独排序，最后按桶序拼接。均匀分布时平均 `O(n + k)`；最坏退化为一次整体排序：桶内 TimSort 为 O(n log n)，插入排序为 O(n²)。**稳定性继承桶内排序算法。**

### 4.2.1 和计数排序的关系

```
计数排序：一个值 = 一个桶（桶数 = 值域大小 k）
桶排序：  一个区间 = 一个桶（桶数自定义）
```

计数排序是「桶大小为 1、桶内无需排序」的桶排序；桶排序按区间分桶，所以能处理浮点数。

### 4.2.2 实现（稳健版）

```js
function bucketSort(arr, bucketSize) {
  const n = arr.length;
  if (n < 2) return arr.slice();

  // 1. 求值域（用循环，避免 Math.max(...arr) 的栈溢出）
  let min = arr[0], max = arr[0];
  for (const x of arr) {
    if (x < min) min = x;
    if (x > max) max = x;
  }
  if (min === max) return arr.slice();       // 全部相同，省掉一次分桶排序

  // 2. 定桶大小：默认让桶数量 ≈ √n
  const size = bucketSize > 0
    ? bucketSize
    : Math.max(1, Math.ceil((max - min + 1) / Math.ceil(Math.sqrt(n))));

  const count = Math.floor((max - min) / size) + 1;
  const buckets = Array.from({ length: count }, () => []);

  // 3. 分桶
  for (const x of arr) {
    buckets[Math.floor((x - min) / size)].push(x);
  }

  // 4. 桶内排序 + 拼接
  const res = [];
  for (const b of buckets) {
    if (b.length === 0) continue;
    b.sort((a, c) => a - c);        // V8 的 sort 是 TimSort，稳定
    for (const x of b) res.push(x);
  }
  return res;
}
```

两处判断：

| 写法 | 作用 / 不加会怎样 |
|---|---|
| `if (min === max) return` | 全相同元素时仍能排序（`size=1`、`count=1`），提前返回只是省掉一次单桶排序 |
| `bucketSize > 0` | 传 0 时 `(max - min) / 0 = Infinity`，`Array.from({ length: Infinity })` 抛 `RangeError: Invalid array length` |

索引不需要 clamp：`count = floor((max-min)/size)+1`，而 `x ≤ max`，所以 `floor((x-min)/size) ≤ count-1`。

默认 `size` 公式按整数区间设计（`(max-min+1)`、最小为 1）；对 `[0, 1)` 这类浮点小区间会只开 1 个桶，需要按 √n 分桶时显式传 `bucketSize`。

### 4.2.3 逐步推演 `[0.78, 0.17, 0.39, 0.26, 0.72, 0.94, 0.21, 0.12, 0.23, 0.68]`

`min=0.12`、`max=0.94`、n=10。显式传 `bucketSize = (0.94-0.12)/5 = 0.164`，`count = floor(0.82/0.164)+1 = 6`（多出的一个桶来自整数公式的 +1）：

```
桶0 [0.12, 0.284): 0.17, 0.26, 0.21, 0.12, 0.23
桶1 [0.284, 0.448): 0.39
桶2 [0.448, 0.612): （空）
桶3 [0.612, 0.776): 0.72, 0.68
桶4 [0.776, 0.94):  0.78
桶5 [0.94, 1.104):  0.94

桶内排序后拼接:
[0.12, 0.17, 0.21, 0.23, 0.26, 0.39, 0.68, 0.72, 0.78, 0.94] ✅
```

桶0 有 5 个元素，是分布不均的开始；如果全部落进一个桶，桶内排序就退化为整体排序。

### 4.2.4 复杂度：平均 O(n) 的条件

假设 n 个元素、k 个桶、数据**均匀分布**。每桶约 `n/k` 个元素，桶内比较排序代价 `O((n/k) log(n/k))`，k 个桶合计：

```
k × O((n/k) log(n/k)) = O(n log(n/k))
```

`k ≈ n` 时每桶约 1 个元素，桶内排序退化为常数，总代价 O(n)。桶太多会产生大量空桶（额外的 O(k) 空间和遍历开销），工程上取 `k ≈ √n`。

| 情况 | 复杂度 | 条件 |
|---|---|---|
| 最好 | **O(n)** | 均匀分布，每桶约 1 个元素 |
| 平均 | O(n + k) | 均匀分布 |
| 最坏 | **O(n²)**（插入排序）/ **O(n log n)**（TimSort） | 全部落一个桶 |
| 空间 | O(n + k) | 桶数组 + 元素引用 |

### 4.2.5 稳定性

取决于桶内排序算法：

- 插入排序、归并排序、`Array.prototype.sort`（V8 为 TimSort）→ 稳定
- 快排 → 不稳定

前提是分桶时按原数组顺序 `push`，且拼接时按桶编号升序。

### 4.2.6 应用场景

| 场景 | 说明 |
|---|---|
| **浮点数排序** | 计数排序做不到（值域无限），桶排序可以 |
| **均匀分布的随机数** | 最理想的输入 |
| **外部排序的「分块」阶段** | 大文件按范围切块，每块单独排序 |
| **数据倾斜分析** | 桶内元素数量本身就是分布直方图 |
| **按区间分组的需求** | 比如按价格区间分档，天然就是分桶 |
| **「最大间距」类题目** | LeetCode 164 用桶排序 + 鸽巢原理做到 O(n) |

**LeetCode 164「最大间距」**：

1. n 个数、值域 `[min, max]`，开 n+1 个桶，桶宽 `(max-min)/n`
2. 由鸽巢原理，**必有一个桶为空**，最大间距一定跨越空桶
3. 只需记录每个桶的 min/max，比较相邻非空桶的 `后桶min - 前桶max`

### 4.2.7 常见坑

| 坑 | 后果 | 修正 |
|---|---|---|
| 空数组调 `Math.min(...[])` | 得到 `Infinity`，后续全是 `NaN` | 先判断 `n < 2` |
| `bucketSize = 0` | 去掉 `> 0` 判断后 `size = 0`，桶数为 `Infinity`，`Array.from` 抛 `RangeError` | 先判断 `bucketSize > 0` |
| 默认 `size` 用于浮点小区间 | `Math.max(1, ...)` 让 `[0, 1)` 这类区间只开 1 个桶 | 显式传 `bucketSize` |

### 4.2.8 答题要点

- 四步：求 min/max → 定桶宽和桶数 → 按 `(x-min)/size` 分桶 → 桶内排序后拼接。
- 均匀分布时每桶约 n/k 个，总代价 O(n log(n/k))；k≈n 时为 O(n)。
- 最坏全落一个桶，退化为一次整体排序；桶数常取 √n 量级。
- 能排浮点；稳定性继承桶内排序，分桶和拼接都要保序。

### 4.2.9 追问表

| 追问 | 回答要点 |
|---|---|
| 桶数量怎么定？ | 约 √n，或让每桶元素数为常数 |
| 为什么桶排序能排浮点数？ | 按区间分桶，不需要值当离散下标 |
| 数据全相同会怎样？ | 全落一个桶；实现上直接返回，省一次排序 |
| 桶排序能用于外部排序吗？ | 能，按范围分块写磁盘，块内排序后顺序拼接 |
| 默认实现排 `[0,1)` 浮点为什么只有一个桶？ | `size` 公式按整数区间设计且最小为 1；显式传 `bucketSize` |

## 4.3 基数排序

### 4.3 一句话结论

按「位」排序：从最低位开始，每一位做一次稳定的计数排序，做完最高位整个数组就有序了。时间 `O(d(n + k))`（d 是位数，k 是进制，十进制时 k=10），空间 `O(n + k)`，**稳定**。适合**定长整数、定长字符串**。

### 4.3.1 核心思想：为什么从低位开始也行

关键在于每一轮的**稳定性**。以 `[21, 11]` 为例：

- 个位都是 1，稳定排序后仍是 `[21, 11]`
- 再按十位排序：`1 < 2` → `[11, 21]`
- 如果个位排序不稳定，可能先把 `[21, 11]` 变成 `[11, 21]`，第二轮再按十位得到 `[21, 11]`，结果错

高位排序时，低位已经排好的顺序作为「同高位元素之间的次序」被保留下来。某一轮不稳定，低位做的功就会被后一轮破坏。

### 4.3.2 LSD vs MSD

| | **LSD**（Least Significant Digit） | **MSD**（Most Significant Digit） |
|---|---|---|
| 顺序 | 从最低位到最高位 | 从最高位到最低位 |
| 实现 | 迭代，d 轮 | 递归（每个桶内递归下一轮） |
| 是否需要稳定 | **必须** | 不需要（因为不跨桶） |
| 适用 | 定长数据（整数、定长字符串） | 变长字符串（字典序） |
| 中途能否得到有序 | 不能，必须做完 d 轮 | 能，高位相同时才需要往下递归 |
| 典型实现 | 本册的版本 | 字符串排序、后缀数组 |

### 4.3.3 实现

```js
function radixSort(arr) {
  const n = arr.length;
  if (n < 2) return arr.slice();

  // 1. 求值域（用循环，不用 Math.max(...arr)）
  let min = arr[0], max = arr[0];
  for (const x of arr) {
    if (x < min) min = x;
    if (x > max) max = x;
  }

  // 2. 负数偏移：把所有数平移到 >= 0（JS 的 % 对负数返回负数）
  const offset = min < 0 ? -min : 0;
  let a = new Array(n);
  for (let i = 0; i < n; i++) a[i] = arr[i] + offset;
  const maxVal = max + offset;

  // 3. 从低位到高位，每轮做一次稳定的计数排序
  for (let exp = 1; Math.floor(maxVal / exp) > 0; exp *= 10) {
    a = countingByDigit(a, exp);
  }

  // 4. 还原偏移
  const res = new Array(n);
  for (let i = 0; i < n; i++) res[i] = a[i] - offset;
  return res;
}

// 按第 exp 位做稳定计数排序（k = 10）
function countingByDigit(a, exp) {
  const n = a.length;
  const count = new Array(10).fill(0);

  for (let i = 0; i < n; i++) {
    count[Math.floor(a[i] / exp) % 10]++;
  }
  for (let i = 1; i < 10; i++) count[i] += count[i - 1];

  const out = new Array(n);
  for (let i = n - 1; i >= 0; i--) {         // ★ 逆序回填 → 稳定
    const d = Math.floor(a[i] / exp) % 10;
    out[--count[d]] = a[i];
  }
  return out;
}
```

负数先整体加 `offset = -min`；JS 的 `%` 保留符号，不偏移会得到负下标。

循环条件是 `Math.floor(maxVal / exp) > 0`：

```
maxVal = 802
exp=1    → 802 > 0    处理个位
exp=10   → 80 > 0     处理十位
exp=100  → 8 > 0      处理百位
exp=1000 → 0，停止
```

不取 `Math.floor` 时 `802/1000 = 0.802 > 0` 仍成立，会多跑一轮空转。

### 4.3.4 逐步推演 `[170, 45, 75, 90, 802, 24, 2, 66]`

```
第 1 轮（exp=1，个位）:
  个位: 170→0  45→5  75→5  90→0  802→2  24→4  2→2  66→6
  桶0: [170, 90]   桶2: [802, 2]   桶4: [24]   桶5: [45, 75]   桶6: [66]
  结果: [170, 90, 802, 2, 24, 45, 75, 66]

第 2 轮（exp=10，十位）:
  十位: 170→7  90→9  802→0  2→0  24→2  45→4  75→7  66→6
  桶0: [802, 2]  桶2: [24]  桶4: [45]  桶6: [66]  桶7: [170, 75]  桶9: [90]
  结果: [802, 2, 24, 45, 66, 170, 75, 90]

第 3 轮（exp=100，百位）:
  百位: 802→8  2→0  24→0  45→0  66→0  170→1  75→0  90→0
  桶0: [2, 24, 45, 66, 75, 90]  桶1: [170]  桶8: [802]
  结果: [2, 24, 45, 66, 75, 90, 170, 802] ✅
```

第 2 轮桶 0 的 `[802, 2]` 保持第 1 轮的顺序（个位都是 2）；第 3 轮百位区分开，802 落到最后。10,000 个 `[-1e5, 1e5]` 随机整数与 `sort` 对拍一致，2,000 条记录中同值元素的原始顺序保持不变。

### 4.3.5 复杂度

| 项目 | 复杂度 | 说明 |
|---|---|---|
| 时间 | **O(d(n + k))** | d 轮，每轮一次计数排序 O(n + k) |
| 空间 | **O(n + k)** | 每轮需要 out 数组 O(n) + count O(k) |
| 稳定 | ✅ | 逆序回填保证 |

**十进制整数**：`k = 10`、`d = log₁₀(max)`。

- `max = 10⁶` → `d = 7` → `O(7n)` ≈ **线性**
- `max = 2³²` → `d = 10` → `O(10n)` ≈ 线性

**计算机实现里通常用更大的基数**（比如 2¹⁶ = 65536，k 大但 d 小）：

| 基数 | d（32 位整数） | 每轮代价 | 总代价 |
|---|---|---|---|
| 10 | 10 | n + 10 | 10n + 100 |
| 256 | 4 | n + 256 | 4n + 1024 |
| **2¹⁶ = 65536** | **2** | n + 65536 | **2n + 131072** |

**基数选择是「轮数」和「每轮常数」的权衡**：位宽小、d 大 → 轮数多；位宽大、k 大 → count 数组大但轮数少。实战中常取 8 位或 16 位。

### 4.3.6 用基数排序排字符串

**定长字符串**：把每个字符当作一位，从最后一个字符开始做 LSD。

```js
// 定长字符串数组排序（所有字符串长度相同，比如都是 6 位的编码）
function radixSortStrings(arr, len) {
  let a = arr.slice();
  for (let pos = len - 1; pos >= 0; pos--) {     // 从最后一个字符往前
    a = countingByChar(a, pos);
  }
  return a;
}
function countingByChar(a, pos) {
  const n = a.length;
  const count = new Array(128).fill(0);          // ASCII
  for (const s of a) count[s.charCodeAt(pos)]++;
  for (let i = 1; i < 128; i++) count[i] += count[i - 1];
  const out = new Array(n);
  for (let i = n - 1; i >= 0; i--) {             // 逆序回填
    out[--count[a[i].charCodeAt(pos)]] = a[i];
  }
  return out;
}
```

**变长字符串**用定长 LSD 需要先补齐（空位视为最小字符），否则 `ab` 与 `abc` 无法对齐；通常改用 **MSD**：先按首字符分桶，再对每个桶递归处理下一位。

### 4.3.7 应用场景

| 场景 | 说明 |
|---|---|
| **大整数排序** | 超过 2³² 但在 2⁵³ 内的数，按 16 位分段；更大用 BigInt 分段 |
| **定长字符串/编码** | 身份证号、订单号、车牌号 |
| **IP 地址排序** | 转成 32 位整数后基数排序，O(n) |
| **浮点数排序** | 先把浮点数的位模式转成可比较的整数，再基数排序 |
| **后缀数组构造** | 倍增算法 + 基数排序，O(n log n) |
| **数据库的多列排序** | 从最后一列开始做稳定排序，等价于多级排序 |

**浮点数怎么用基数排序**：IEEE 754 双精度是定长 64 位，可以按位模式转成有序整数：

```js
function floatToSortableBigInt(x) {
  const view = new DataView(new ArrayBuffer(8));
  view.setFloat64(0, x);
  const u = view.getBigUint64(0);
  // 非负数翻转符号位；负数全部位取反
  return u & (1n << 63n) ? ~u : u | (1n << 63n);
}
```

必须用 `BigInt`（或拆高低 32 位），`Number` 的位运算会截断到 32 位，所有输入都得到同一个 key。上面的映射对 `[-3.5, -1, -0.5, 0, 0.5, 1, 2.5]` 的排序结果与数值比较一致。任意精度浮点（非 IEEE 754 定长编码）不适用。

### 4.3.8 常见坑

| 坑 | 后果 | 修正 |
|---|---|---|
| 用 `Math.max(...arr)` | 大数组 spread 栈溢出 | 用循环遍历 |
| 不处理负数 | `-5 % 10 = -5` → 负下标 → `undefined.push` 崩 | 用 `offset = -min` 平移 |
| 每轮用不稳定排序 | 低位做的功被高位破坏，结果错 | 必须用稳定的计数排序 |
| 循环条件写 `digit <= max` | max=100 时 `digit` 到 100 就停，漏了最高位 | `Math.floor(maxVal / exp) > 0` |
| 忘了 `Math.floor` | 多跑一轮空转 | 加 `Math.floor` |
| 最低位从 `exp=10` 开始 | 个位没排，结果错 | 从 `exp=1` 开始 |
| 用 LSD 排变长字符串 | 长度不对齐，结果错 | 补齐或用 MSD |
| 以为基数排序不需要额外空间 | 每轮都要 out 数组 O(n) | 空间 O(n + k) |

### 4.3.9 答题要点

- LSD：从低位到高位，每轮一次稳定计数排序；O(d(n+k))，空间 O(n+k)。
- 正确性依赖稳定性；低位信息靠稳定性被高位携带。
- 负数先加 offset；位数循环用 `Math.floor(maxVal / exp) > 0`。
- 定长用 LSD，变长用 MSD；基数越大 d 越小，但 count 数组越大。

### 4.3.10 追问表

| 追问 | 回答要点 |
|---|---|
| 和计数排序什么关系？ | 基数是「多轮小值域的计数排序」 |
| 支持负数吗？ | 需要先平移到非负（JS 的 `%` 对负数返回负数） |
| 怎么排浮点数？ | 把 IEEE 754 位模式转成可比较的 64 位整数，再基数排序 |
| LSD 和 MSD 区别？ | LSD 从低位迭代、要稳定、适合定长；MSD 从高位递归、适合变长字符串 |
| 基数取多大合适？ | 权衡轮数和 count 数组大小，常用 8 位或 16 位 |
| 什么时候不该用基数排序？ | 数据量小、值域小（不如计数）、变长数据要额外处理 |

## 4.4 三者横向对比

### 4.4.1 总表

| | 计数排序 | 桶排序 | 基数排序 |
|---|---|---|---|
| 时间 | O(n + k) | 平均 O(n + k)，最坏 O(n²) | O(d(n + k)) |
| 空间 | O(n + k) | O(n + k) | O(n + k) |
| 稳定 | ✅（前缀和版） | 取决于桶内排序 | ✅ |
| 核心操作 | 值 → 下标 | 值 → 桶编号 | 位 → 桶编号 |
| 关键前提 | 值域 k 小 | **分布均匀** | 位数 d 小（定长） |
| 能否排浮点 | ❌ | ✅ | ✅（要转位模式） |
| 能否排字符串 | ❌ | ❌ | ✅（定长） |
| 最脆弱的地方 | k 太大 → 爆内存 | 分布不均 → 退化 | 中途用了不稳定排序 |

### 4.4.2 选型决策树

```
要排序的是什么？
├─ 整数，值域小（k ≈ n）
│    └─ 计数排序（O(n)，最简单）
├─ 整数，值域大（k >> n）
│    ├─ 定长（≤ 2⁵³ 安全整数，或按 16 位分段的 BigInt）→ 基数排序
│    └─ 任意精度且不便分段 → 快排/归并
├─ 浮点数
│    ├─ 分布均匀 → 桶排序
│    └─ 分布未知 → 快排，或转位模式后基数排序
├─ 定长字符串 → 基数排序（LSD）
├─ 变长字符串 → 基数排序（MSD）或归并
└─ 对象/复杂数据 → 归并（稳定）或快排（快）
```

### 4.4.3 一句话记住

| 算法 | 一句话 |
|---|---|
| **计数** | 值域小就数一数，最省事 |
| **桶** | 分布均匀就分区间，能排浮点 |
| **基数** | 位数少就按位来，稳定是命门 |

## 4.5 本册速记卡

```
为什么能突破 Ω(n log n)
  不比较，用「值」算出位置；代价是需要结构假设（值域/分布/定长）
  n 大、k 小（或 d 小）才用线性排序

计数排序
  三步：计数 → 前缀和 → 逆序回填
  count[i] = 「值 ≤ i 的元素个数」= 「值为 i 的末尾下标 + 1」
  逆序回填是稳定性来源；负数先减 min
  range > 1e7 退回 sort；O(n+k)，k 与 n 同阶才是线性

桶排序
  一个区间一个桶，能排浮点；均匀 O(n)，全落一桶退化为整体排序
  桶数取 √n 量级；稳定性继承桶内算法
  默认 size 按整数区间设计，浮点小区间要显式传 bucketSize
  LeetCode 164 最大间距：n+1 桶 + 鸽巢原理 → O(n)

基数排序
  LSD：从低位到高位，每轮稳定计数排序；O(d(n+k))
  正确性 = 稳定性（低位信息靠稳定性被高位携带）
  负数：offset = -min（JS 的 % 对负数返回负数）
  位数循环：Math.floor(maxVal / exp) > 0
  定长用 LSD，变长用 MSD；基数越大 d 越小，count 数组越大
```
