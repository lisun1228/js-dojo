## 8.1 洗牌算法

### 8.1 核心结论

**Fisher-Yates（Knuth Shuffle）**：从最后一个位置开始倒着走，每次从 `[0, i]` 里**等概率**挑一个和 `arr[i]` 交换。时间 O(n)、空间 O(1)、n! 种排列等概率。
最常见的错误写法是 `arr.sort(() => Math.random() - 0.5)`：看似洗牌，实际分布严重不均。

### 8.1.1 实现

```js
function shuffle(arr) {
  for (let i = arr.length - 1; i > 0; i--) {
    const j = Math.floor(Math.random() * (i + 1));   // j ∈ [0, i]
    [arr[i], arr[j]] = [arr[j], arr[i]];
  }
  return arr;
}
```

| 细节 | 说明 |
|---|---|
| `i > 0` 而非 `i >= 0` | `i = 0` 时 `j` 只能是 0，自己和自己交换无意义 |
| `Math.random() * (i + 1)` | 要包含 `i` 本身，所以是 `i+1` |
| `Math.floor` | `Math.random()` 返回 `[0, 1)`，乘完要向下取整 |
| 原地交换 | 不能 `arr[j] = arr[i]`（会丢值），用临时变量或解构 |

从后往前的含义：末尾是「已确定的位置」，`[0, i]` 是「尚未确定的范围」；每次把剩余元素中随机的一个放到当前位置。正向写逻辑等价，见 8.1.6。

### 8.1.2 逐步推演 `[1, 2, 3, 4]`

```
i=3: j ∈ [0,3]，假设 j=1 → swap(arr[3], arr[1]) → [1, 4, 3, 2]
                              现在 arr[3]=2 已确定
i=2: j ∈ [0,2]，假设 j=0 → swap(arr[2], arr[0]) → [3, 4, 1, 2]
                              arr[2]=1 已确定
i=1: j ∈ [0,1]，假设 j=1 → swap(arr[1], arr[1]) → [3, 4, 1, 2]
                              arr[1]=4 已确定
i=0: 停止，arr[0]=3 自动确定
结果: [3, 4, 1, 2]
```

每一步 `arr[i]` 放入的元素，都从「尚未确定的所有元素」中等概率选取；后续步骤不会改动已确定的位置。

### 8.1.3 正确性证明

要证：每个排列出现的概率都是 `1/n!`。

第 i 步有 `i + 1` 种选择（`j ∈ [0, i]`），选择序列总数为：

```
n × (n-1) × (n-2) × ... × 2 × 1 = n!
```

每条选择序列等概率（第 i 步为 `1/(i+1)`，连乘得 `1/n!`）。这 `n!` 条选择序列与 `n!` 个排列一一对应：

- 选择序列 → 排列：正向执行，唯一确定。
- 排列 → 选择序列：从末尾反推，最后位置的元素必是第 1 步选中的，倒数第二位置是第 2 步选中的，依此类推。

双射成立，故每个排列的概率都是 `1/n!`。

### 8.1.4 错误写法一：sort 随机比较器

```js
// ❌ 分布不均匀
const shuffled = arr.slice().sort(() => Math.random() - 0.5);
```

`Array.prototype.sort` 要求比较器一致：若 `a < b` 且 `b < c`，必须 `a < c`。`() => Math.random() - 0.5` 每次调用返回不同值，不满足传递性，排序结果取决于引擎内部的比较顺序。

Node v22（V8 12.4）实测：

| 观测 | 实测 | 均匀分布应有 |
|---|---|---|
| n=5，10 万次，恒等排列出现次数 | 9113（9.11%） | 833（0.83%） |
| n=5，120 种排列频次范围 | 172–9113 | 833 |
| n=3，20 万次，恒等排列占比 | 37.5% | 16.7% |
| n=20，10 万次，原第 0 个元素仍在位置 0 | 11.7% | 5% |

n=5 时恒等排列概率是均匀值的 11 倍；n=20 时首元素留在首位的概率是均匀值的 2.3 倍。排序算法如何调用比较器由引擎实现决定，同一段代码在不同引擎、不同长度下分布不同。

对照 Fisher-Yates（n=5、10 万次）：120 种排列频次 772–898（期望 833），χ² = 99.1（df = 119），与均匀分布不矛盾。

### 8.1.5 错误写法二：全范围交换

```js
// ❌ 错误！也不均匀
function badShuffle(arr) {
  for (let i = 0; i < arr.length; i++) {
    const j = Math.floor(Math.random() * arr.length);   // j ∈ [0, n-1]
    [arr[i], arr[j]] = [arr[j], arr[i]];
  }
  return arr;
}
```

与 Fisher-Yates 的差别只在 `j` 的范围从 `[0, i]` 变成 `[0, n-1]`。

- 选择序列总数：`n × n × ... × n = nⁿ`
- 排列总数：`n!`
- `nⁿ` 不能被 `n!` 整除（n ≥ 3），必然有些排列概率更高

n = 3 穷举 27 条路径：

| 排列 | 概率 |
|---|---|
| `[1,2,3]` | 4/27 |
| `[1,3,2]` | 5/27 |
| `[2,1,3]` | 5/27 |
| `[2,3,1]` | 5/27 |
| `[3,1,2]` | 4/27 |
| `[3,2,1]` | 4/27 |

期望是 4.5/27，实际是 4 或 5，偏差 11%。n = 5 模拟 10 万次，单格最大偏差 22%。原因是同一元素可能被交换多次，各位置受到的影响不对称。

### 8.1.6 四种写法对比

| 写法 | 均匀 | 复杂度 |
|---|---|---|
| Fisher-Yates（`j ∈ [0,i]`，倒序） | 是 | O(n) |
| 正向版（`j ∈ [i, n-1]`，正序） | 是 | O(n) |
| `sort(() => Math.random() - 0.5)` | 否 | O(n log n) |
| 全范围交换（`j ∈ [0,n-1]`） | 否 | O(n) |

正向版：

```js
function shuffleForward(arr) {
  for (let i = 0; i < arr.length - 1; i++) {
    const j = i + Math.floor(Math.random() * (arr.length - i));   // j ∈ [i, n-1]
    [arr[i], arr[j]] = [arr[j], arr[i]];
  }
  return arr;
}
```

正向版与倒序版等价：`[0, i-1]` 已确定，从 `[i, n-1]` 中随机选一个放到 `i`。每步选择数仍是 `n, n-1, ..., 2`，共 `n!` 条路径，同样构成双射。

### 8.1.7 部分洗牌：只取前 k 个

需求：从 n 个元素中**等概率随机取 k 个**（顺序也随机），不洗整个数组。

```js
function sampleK(arr, k) {
  const a = arr.slice();       // 不改原数组
  const n = a.length;
  const cnt = Math.min(k, n);
  for (let i = 0; i < cnt; i++) {
    const j = i + Math.floor(Math.random() * (n - i));   // j ∈ [i, n-1]
    [a[i], a[j]] = [a[j], a[i]];
  }
  return a.slice(0, cnt);
}
```

抽样阶段只做 k 次交换；`slice()` 复制原数组是 O(n)。总时间为 O(n)（复制）+ O(k)（交换）；若允许原地修改，额外时间才是 O(k)。`Math.min(k, n)` 处理 k > n。

用途：抽奖（从百万用户里抽 100 个）、随机推荐、随机分组。

### 8.1.8 可复现的随机（种子随机）

`Math.random()` 无法设种子。测试要复现或需要「同一种子生成同一牌局」时，自己实现 PRNG：

```js
// mulberry32：32 位种子
function mulberry32(seed) {
  return function () {
    seed |= 0;
    seed = (seed + 0x6D2B79F5) | 0;
    let t = Math.imul(seed ^ (seed >>> 15), 1 | seed);
    t = (t + Math.imul(t ^ (t >>> 7), 61 | t)) ^ t;
    return ((t ^ (t >>> 14)) >>> 0) / 4294967296;
  };
}

function shuffleSeeded(arr, seed) {
  const rand = mulberry32(seed);
  for (let i = arr.length - 1; i > 0; i--) {
    const j = Math.floor(rand() * (i + 1));
    [arr[i], arr[j]] = [arr[j], arr[i]];
  }
  return arr;
}
```

同一个 seed 得到同一序列，换 seed 得到不同序列。mulberry32、xorshift、PCG 都是「确定性算法 + 种子」；它们不是密码学安全的。

### 8.1.9 蓄水池抽样

需求：从**长度未知**的数据流中等概率抽取 k 个元素，只能遍历一次、不能存全部。

```js
function reservoirSample(stream, k) {
  const res = [];
  let i = 0;
  for (const x of stream) {
    if (i < k) {
      res.push(x);                              // 前 k 个直接放入
    } else {
      const j = Math.floor(Math.random() * (i + 1));   // j ∈ [0, i]
      if (j < k) res[j] = x;                    // 以 k/(i+1) 的概率替换
    }
    i++;
  }
  return res;
}
```

归纳证明：处理到第 i 个元素时，池中每个元素被选中的概率都是 `k/i`。

- 前 k 个：`1 = k/k`。
- 处理第 `i+1` 个：它被选中的概率是 `k/(i+1)`；池中元素被保留的概率是 `1 - k/(i+1) × 1/k = i/(i+1)`，最终概率为 `(k/i) × i/(i+1) = k/(i+1)`。

n=100、k=10、10 万次模拟：每个元素的入选率在 0.0974–0.1017 之间，理论值 0.1。

用途：日志采样、大数据流抽样、随机取一条记录（k=1）、从不知道长度的链表中随机取一个节点。

### 8.1.10 常见坑

| 坑 | 后果 | 修正 |
|---|---|---|
| `Math.random() * i` 少了 `+1` | 永远选不到 `i` 本身；n=2 时退化为固定交换 | `* (i + 1)` |
| 直接修改入参 | 调用方的数组被打乱 | 先 `slice()` 或明确说明 |
| 用 `Math.random()` 做安全场景 | 不是密码学安全的 | 用 `crypto.getRandomValues()` / `randomInt` |

`Math.random()` 的算法由引擎决定，不是密码学安全的 PRNG（V8 使用 xorshift128 系 PRNG，128 位内部状态），输出序列可被预测，不能用于生成密码、token、验证码、抽奖或加密密钥。

```js
// 浏览器
const buf = new Uint32Array(1);
crypto.getRandomValues(buf);
const r = buf[0] / 2 ** 32;

// Node
const { randomInt } = require('node:crypto');
const r = randomInt(0, n);          // [0, n)
```

### 8.1.11 答题要点

- 算法：`i` 从 `n-1` 到 1，`j ∈ [0, i]` 等概率，交换；O(n) 时间、O(1) 空间。
- 正确性：n! 条等概率选择序列与 n! 个排列双射，且可反向唯一还原，故每个排列 1/n!。
- 错法一：`sort` 随机比较器违反传递性；V8 实测 n=5 恒等排列 9.11%，均匀应为 0.83%。
- 错法二：`j ∈ [0, n-1]`，nⁿ 不能被 n! 整除；n=3 为 4/27 或 5/27。
- 延伸：部分洗牌做 k 次交换；未知长度用蓄水池；安全场景用 `crypto`。

### 8.1.12 追问表

| 追问 | 回答要点 |
|---|---|
| 为什么从后往前？ | 已确定的位置在末尾，`[0,i]` 是未确定范围；正向版等价 |
| 为什么 `j` 是 `[0, i]` 不是 `[0, n-1]`？ | 全范围导致 nⁿ 条路径无法均分 n! |
| `sort` 随机比较器为什么错？ | 比较器不一致，违反传递性，分布随引擎实现变化 |
| Fisher-Yates 的复杂度？ | O(n) 时间、O(1) 空间 |
| 怎么证明均匀？ | n! 条等概率路径与 n! 个排列双射 |
| 只要前 k 个怎么办？ | 正向版跑 k 步；k 次交换，复制原数组另算 O(n) |
| 不知道长度怎么办？ | 蓄水池抽样，第 i 个以 k/(i+1) 概率替换 |
| `Math.random()` 安全吗？ | 不安全，非密码学安全；用 `crypto.getRandomValues` / `randomInt` |
| 怎么做可复现洗牌？ | 自己实现 PRNG（mulberry32 等），用种子 |
| 洗牌和随机排序的区别？ | 「随机排序」通常指错误的 sort 写法；洗牌是 Fisher-Yates |

## 8.2 最大的钻石

这是最优停止理论的经典问题（秘书问题 / Secretary Problem）。面试中属于概率题：先把模糊问题形式化，再给出可证明的策略。

### 8.2 核心结论

先看前 37%（n/e）个，一个都不选，只记住其中最大的；之后遇到比它更大的立刻选。拿到最大钻石的概率约为 `1/e ≈ 36.8%`，在「只能选一次、不能回头、n 已知、顺序随机」的约束下最优。

### 8.2.1 问题形式化

标准秘书问题的五个前提：

| 前提 | 含义 | 去掉会怎样 |
|---|---|---|
| ① n 已知 | 知道总共有多少层/多少个候选 | 不知道 n 需要在线策略，37% 不适用 |
| ② 随机顺序 | 钻石大小的排列是均匀随机的 | 如果顺序有规律（如逐层变大），问题退化 |
| ③ 只能选一次 | 选定后不能改 | 允许改则看完再选，100% 成功 |
| ④ 不能回头 | 错过的不能再选 | 允许回头 = 允许改，同上 |
| ⑤ 只能比较 | 只能判断「比之前的大/小」，不知绝对值 | 知道分布可用贝叶斯方法 |

任一前提不成立，37% 都不再直接适用，变体见 8.2.7。

### 8.2.2 为什么 100% 做不到

不能回头且必须当场决定时，任何策略都可能选早：第 3 层选了很大的钻石，第 7 层可能更大。目标只能是最大化成功概率。

### 8.2.3 策略：先观察，后选择

1. 前 `m` 层只看不选，记录这 m 层里最大的钻石，记为 `M`。
2. 从第 `m+1` 层开始，遇到第一个严格大于 `M` 的就选它。
3. 到最后一层仍未遇到，则选最后一颗（或按题目允许空手）。

前 m 层用于建立基准，之后用于识别突破。m 太小基准不可靠，容易选早；m 太大观察太久，真正的最大值可能已在观察期错过。这是探索与利用的权衡。

### 8.2.4 推导：为什么是 1/e

设 `x = m/n`。全局最大值在第 `i` 个位置（`i > m`）的概率为 `1/n`；要成功，还需前 `i-1` 个中的最大值落在前 `m` 个里，概率为 `m/(i-1)`。

```
P(x) = Σ_{i=m+1}^{n} (1/n) × m/(i-1)
     = (m/n) × Σ_{i=m+1}^{n} 1/(i-1)
     = x × Σ_{k=m}^{n-1} 1/k
     ≈ x × ∫_{x}^{1} dt/t
     = x × ln(1/x)
```

令 `f(x) = -x·ln x`，`f'(x) = -ln x - 1 = 0`，得 `x = 1/e ≈ 0.3679`；代回 `P(1/e) = (1/e)·ln e = 1/e ≈ 0.3679`。

n 很大时，最优观察比例和成功率都与 n 无关，同为 `1/e`。

### 8.2.5 具体数值（n 较小时）

37% 是 n → ∞ 的极限。按 `P(m) = (m/n)Σ_{k=m}^{n-1}1/k` 精确计算：

| n | 最优 m | 最优成功率 |
|---|---|---|
| 3 | 1 | 50.0% |
| 4 | 1 | 45.8% |
| 5 | 2 | 43.3% |
| 10 | 3 | 39.9% |
| 20 | 7 | 38.4% |
| 100 | 37 | 37.1% |
| 1000 | 368 | 36.8% |
| ∞ | n/e | 36.79% |

n=3 时 m=1、成功率 50%；n 小时最优 m 要单独算，不能直接用 n/e。

### 8.2.6 必须「严格大于」

阈值用严格大于，避免把与观察期最大值相等的候选取走。连续分布下打平概率为 0，两种写法差别可忽略；离散取值时必须严格大于。

### 8.2.7 三个常见变体

- **允许回头**：看完再选最大的，成功率 100%；「不能回头」是本题的核心约束。
- **不知道 n**：37% 无法计算，改用基于时间的策略：先观察固定时长 T，之后遇到更大的就选。
- **可选 k 个、命中前 k 即成功**：可以更早开始选；k 越大，最优观察期越短、成功率越高（n=5000 模拟：k=2/3/5 的最优成功率约为 0.68/0.84/0.93）。具体阈值随成功定义变化，需要单独推导。

### 8.2.8 现实中的应用

| 场景 | 说明 |
|---|---|
| 招聘 | 面试一批候选人，何时停止面试直接发 offer |
| 租房/买房 | 看多少套房后开始下手 |
| 停车场选车位 | 开到第几个车位就该停 |
| 卖房定价 | 收到多少个 offer 后该接受 |
| 在线算法 | 在线匹配、竞价、资源分配 |

现实问题通常不满足「n 已知 + 随机顺序 + 不能回头」，37% 只能作为启发式：先花约三分之一的时间了解行情，之后遇到明显更好的再出手。

### 8.2.9 答题要点

- 先形式化：n 已知、顺序随机、只能选一次、不能回头、只能比较；允许回头则 100%。
- 策略：前 m 个只看不选、记最大值，之后选第一个严格更大的。
- 推导：`P(x) ≈ x·ln(1/x)`，`x = 1/e` 时最大，成功率 `1/e ≈ 36.8%`，与 n 无关。
- n 小查精确值（n=3：m=1，50%）；现实中当启发式。

### 8.2.10 追问表

| 追问 | 回答要点 |
|---|---|
| 为什么不能 100%？ | 不能回头 + 必须当场决定，永远可能选早 |
| 37% 是怎么来的？ | `P ≈ x·ln(1/x)`，求导得 `x = 1/e` |
| 和 n 有关吗？ | 无关；n 很大时比例和成功率都是 1/e |
| n 很小怎么办？ | 单独算，n=3 时 m=1、成功率 50% |
| 为什么必须严格大于？ | 避免取走与观察期最大值相等的候选 |
| 允许回头呢？ | 看完再选，100% |
| 不知道 n 呢？ | 37% 不适用，用基于时间的在线策略 |
| 选前 k 个呢？ | 观察期缩短，成功率随 k 上升，阈值需单独推导 |
| 现实中怎么用？ | 当启发式：花 1/3 时间摸行情，之后遇到明显更好的就出手 |

## 8.3 顺带补充：三个常一起问的概率题

### 8.3.1 生日悖论：23 个人里有两个同生日的概率超过 50%

常见错误是把它理解成「某个人与其他人同生日」（约 23/365 ≈ 6%）；题目问的是「**任意两人**同生日」。

正解：先算所有人生日互不相同的概率。

```
P(全不重复) = (365/365) × (364/365) × ... × (365-22)/365
            ≈ 0.4927

P(至少一对重复) = 1 - 0.4927 ≈ 0.5073
```

n 个人有 `C(n,2) = n(n-1)/2` 对，23 人对应 253 对，碰撞概率由这些对叠加。

记忆点：23 → 50.7%，57 → 99.0%，367 → 100%（鸽巢原理）。

### 8.3.2 三门问题（Monty Hall）：换门有 2/3 概率赢

设定：3 扇门，1 辆车 2 只羊。第一次选 1 号门；主持人知道答案，打开另一扇有羊的门（如 3 号），问是否换。

答案：换，赢的概率 2/3；不换，1/3。

第一次选中的概率是 `1/3`（不换就固定在这个概率）；没选中的 `2/3` 全部集中到主持人未打开的那扇门。

```
初始:  P(1号是车) = 1/3    P(2或3号是车) = 2/3
主持人打开 3 号（有羊）:
        P(1号是车) = 1/3    P(2号是车) = 2/3
       ────────────────────────────────────
       不换 → 1/3          换 → 2/3
```

前提：主持人知道答案，且一定打开一扇有羊的门。若主持人随机开门（可能开出车），换与不换概率相同。

推广到 100 扇门：选 1 号，主持人打开 98 扇有羊的门，只剩 1 号和另一扇；另一扇是车的概率是 99/100。

### 8.3.3 用 `rand5()` 实现 `rand7()`

需求：`rand5()` 等概率返回 1~5，实现等概率返回 1~7 的 `rand7()`。

错误写法 `rand5() + rand5() - 1`：范围 1~9，分布呈三角形，中间值概率高。

正确做法：拒绝采样。

```js
function rand7() {
  while (true) {
    // 构造 1~25 的均匀分布（两个独立的 5 进制位）
    const num = (rand5() - 1) * 5 + rand5();   // 1~25
    if (num <= 21) return ((num - 1) % 7) + 1; // 1~21 均分给 7 个数，每个 3 种
  }
  // 22~25 拒绝，重新采样
}
```

`(rand5()-1)*5 + rand5()` 在 1~25 上均匀。`21 = 3×7`，取 1~21 映射到 7 个结果，每个结果有 3 种来源，概率 `3/25`；22~25 拒绝重来。

期望调用次数：每轮成功率 `21/25`，期望轮数 `25/21`，每轮 2 次 `rand5`，共 `2 × 25/21 ≈ 2.381` 次。

100 万次实测：7 个结果的频次为 142568–143225（期望 142857），χ² = 2.31（df = 6）；平均每次输出调用 `rand5` 2.3799 次。

通用套路：把 k 次 `randM()` 组合成 `M^k` 的均匀分布，取其中能被 N 整除的最大前缀，剩余拒绝——这就是拒绝采样。

## 8.4 本册速记卡

```
洗牌（Fisher-Yates）
  i 从 n-1 到 1，j ∈ [0, i]，swap；O(n) / O(1)
  正确性：n! 条等概率路径 ↔ n! 个排列（双射，可反向唯一推出）
  错法1：sort 随机比较器 —— 比较器不一致；V8 n=5 恒等排列 9.11%
  错法2：j ∈ [0, n-1] —— nⁿ 不能整除 n!；n=3 为 4/27 或 5/27
  部分洗牌：k 次交换，复制原数组另算 O(n)
  未知长度：蓄水池抽样，第 i 个以 k/(i+1) 概率替换
  Math.random 非密码学安全（V8 xorshift128 系）；安全场景用 crypto
  可复现：PRNG（mulberry32）+ 种子

最大的钻石（秘书问题）
  前提：n 已知 / 随机顺序 / 只能选一次 / 不能回头 / 只能比较
  策略：看前 n/e 记最大值，之后遇第一个严格更大的就选
  推导：P ≈ x·ln(1/x) → x = 1/e → P = 1/e ≈ 36.8%
  与 n 无关；n 小时单独算（n=3 → m=1，50%）
  变体：可回头 → 100%；不知 n → 时间策略；选 k 个 → 观察期更短

三连带题
  生日：23 人 50.7%，57 人 99.0%，367 人 100%；关键是 C(n,2) 对
  三门：换门 2/3；前提是主持人知情且必开羊门
  rand5→rand7：拒绝采样，(r5-1)*5+r5 ∈ 1~25，取 ≤21，期望 2.381 次调用
```
