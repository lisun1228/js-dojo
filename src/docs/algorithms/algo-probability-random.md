## 8.1 洗牌算法（原题 5）

### 一句话结论

**Fisher-Yates（Knuth Shuffle）**：从最后一个位置开始倒着走，每次从 `[0, i]` 里**等概率**挑一个和 `arr[i]` 交换。时间 O(n)、空间 O(1)、**n! 种结果等概率**。
**最常见的错误写法是 `arr.sort(() => Math.random() - 0.5)`**，它看起来像洗牌，实际分布严重不均。

### 8.1.1 实现

```js
function shuffle(arr) {
  for (let i = arr.length - 1; i > 0; i--) {
    const j = Math.floor(Math.random() * (i + 1));   // j ∈ [0, i]
    [arr[i], arr[j]] = [arr[j], arr[i]];
  }
  return arr;
}
```

**三行核心，但处处是细节**：

| 细节 | 说明 |
|---|---|
| `i > 0` 而非 `i >= 0` | `i = 0` 时 `j` 只能是 0，自己和自己交换，无意义 |
| `Math.random() * (i + 1)` | 要包含 `i` 本身，所以是 `i+1` 而不是 `i` |
| `Math.floor` | `Math.random()` 返回 `[0, 1)`，乘完要向下取整 |
| **必须原地交换** | 不能 `arr[j] = arr[i]`（会丢值），必须用临时变量或解构 |

**为什么要从后往前？** 因为「已确定的位置」在末尾，`[0, i]` 是「还没确定的范围」。如果从前往后写，逻辑是等价的（见 8.1.5），但从后往前更直观：**每次把「剩下的元素里随机一个」放到当前位置**。

### 8.1.2 逐步推演 `[1, 2, 3, 4]`

```
i=3: j ∈ [0,3]，假设 j=1 → swap(arr[3], arr[1]) → [1, 4, 3, 2]
                              现在 arr[3]=2 已确定
i=2: j ∈ [0,2]，假设 j=0 → swap(arr[2], arr[0]) → [3, 4, 1, 2]
                              arr[2]=1 已确定
i=1: j ∈ [0,1]，假设 j=1 → swap(arr[1], arr[1]) → [3, 4, 1, 2]
                              arr[1]=4 已确定
i=0: 停止，arr[0]=3 自动确定
结果: [3, 4, 1, 2]
```

**关键观察**：每一步 `arr[i]` 被放进去的元素，是从「还没被确定的所有元素」里等概率选的。这样「第 i 个位置放谁」在每一步都是均匀的，且**后续步骤不会改变已经确定的位置**。

### 8.1.3 正确性证明（面试要求会讲）

**要证明**：每个排列出现的概率都是 `1/n!`。

**证明思路（双射计数法）**：

第 i 步有 `i + 1` 种选择（`j ∈ [0, i]`），所以整个算法的「随机选择序列」总共有：

```
n × (n-1) × (n-2) × ... × 2 × 1 = n!
```

种，**且每种等概率**（因为每步都是均匀随机，概率 `1/(i+1)`，乘起来就是 `1/n!`）。

**关键一步**：这 `n!` 种选择序列和 `n!` 种排列之间是**一一对应**的。

- 给定一个选择序列 → 唯一确定一个排列（正向执行）
- 给定一个排列 → 唯一确定一个选择序列（**从后往前推**：最后位置的元素必然是第 1 步选中的，倒数第二位置是第 2 步选中的……）

既然是双射，且每个选择序列概率都是 `1/n!`，那么**每个排列的概率也都是 `1/n!`** ✅

> 面试话术：「总共 n! 种等概率的选择序列，而每个排列恰好对应一种选择序列，所以每个排列的概率是 1/n!。关键是反向唯一性——给定最终排列，能唯一反推出每一步选的是谁。」

### 8.1.4 错误写法一：`sort(() => Math.random() - 0.5)`

**这是最流行的错误答案，几乎每篇「洗牌」博客都出现过。**

```js
// ❌ 错误！分布不均匀
const shuffled = arr.slice().sort(() => Math.random() - 0.5);
```

**为什么错？**

`Array.prototype.sort` 要求比较器是**一致的（consistent）**：对任意 `a, b, c`，如果 `a < b` 且 `b < c`，则必须 `a < c`。

而 `() => Math.random() - 0.5` **每次调用都返回不同的随机值**，根本不满足传递性——同一个 `a` 和 `b` 比较两次可能一次返回正、一次返回负。

**结果**：排序算法的行为完全依赖「它内部怎么比较」。不同引擎、不同长度，结果不同。

**具体表现**：

| 现象 | 说明 |
|---|---|
| **元素倾向于留在原位** | 大量实验显示，原位置元素的「不动率」显著高于 `1/n` |
| 数组很小时偏差不明显 | 比较次数少，偏差被稀释；**但 n 稍大就明显**，不能因此说它「小数组时是对的」 |
| 长度越大偏差越大 | 归并/TimSort 的比较模式完全不对称，某些排列的概率可以高出数倍 |
| **不同引擎结果不同** | 同一个数组在 Chrome 和 Safari 洗出来的分布不一样，**没有任何可移植性** |

**验证代码**（可以自己在控制台跑）：

```js
function testBias(n, times = 100000) {
  const posCount = Array.from({ length: n }, () => new Array(n).fill(0));

  for (let t = 0; t < times; t++) {
    const arr = Array.from({ length: n }, (_, i) => i);
    arr.sort(() => Math.random() - 0.5);
    arr.forEach((v, i) => posCount[v][i]++);
  }

  // 每个元素在每个位置的期望次数是 times / n
  const expected = times / n;
  let maxDeviation = 0;
  for (let v = 0; v < n; v++) {
    for (let i = 0; i < n; i++) {
      maxDeviation = Math.max(maxDeviation, Math.abs(posCount[v][i] - expected) / expected);
    }
  }
  return { expected, maxDeviation };   // n=5 时偏差约 0.02，n=20 时偏差可达 0.3+
}
```

> **面试话术**：「`sort` 加随机比较器是错的。因为比较器不一致——每次调用返回不同的随机值，违反传递性，排序结果完全依赖引擎内部的比较顺序。实测元素留在原位的概率明显偏高，而且不同引擎不一样。这个写法在小数组上可能碰巧均匀，但那是巧合，不能依赖。」

### 8.1.5 错误写法二：全范围交换

```js
// ❌ 错误！也不均匀
function badShuffle(arr) {
  for (let i = 0; i < arr.length; i++) {
    const j = Math.floor(Math.random() * arr.length);   // j ∈ [0, n-1]，全范围
    [arr[i], arr[j]] = [arr[j], arr[i]];
  }
  return arr;
}
```

**看起来和 Fisher-Yates 差不多**，只是 `j` 的范围从 `[0, i]` 变成了 `[0, n-1]`。

**为什么错？**

- 随机选择序列总数：`n × n × ... × n = nⁿ`
- 排列总数：`n!`
- **`nⁿ` 不能被 `n!` 整除**（除 n ≤ 2 外）

既然 `nⁿ` 个等概率结果无法均分给 `n!` 个排列，**必然有些排列概率更高**。

**具体看 n = 3**：`3³ = 27`，`3! = 6`，`27 / 6 = 4.5` —— 不是整数，所以不可能均匀。

**n = 3 的实际概率分布**（穷举 27 条路径）：

| 排列 | 概率 |
|---|---|
| `[1,2,3]` | 4/27 |
| `[1,3,2]` | 5/27 |
| `[2,1,3]` | 5/27 |
| `[2,3,1]` | 4/27 |
| `[3,1,2]` | 5/27 |
| `[3,2,1]` | 4/27 |

**期望应该是 4.5/27，但实际是 4 或 5** —— 偏差 11%。

**直观理解**：全范围交换会导致「同一个元素可能被交换多次」，且不同位置的交换次数不同（位置 0 前没有元素可以「换进来」，但位置 n-1 有机会被后面的交换影响）。**这种不对称就是偏差的来源。**

### 8.1.6 三种写法对比

| 写法 | 均匀？ | 复杂度 | 评价 |
|---|---|---|---|
| **Fisher-Yates**（`j ∈ [0,i]`，倒序） | ✅ | O(n) | **标准答案** |
| 正向版（`j ∈ [i, n-1]`，正序） | ✅ | O(n) | 等价，见下 |
| `sort(() => Math.random() - 0.5)` | ❌ | O(n log n) | 分布不均 + 更慢 |
| 全范围交换（`j ∈ [0,n-1]`） | ❌ | O(n) | 偏差 10% 以上 |

**正向版（等价正确）**：

```js
function shuffleForward(arr) {
  for (let i = 0; i < arr.length - 1; i++) {
    const j = i + Math.floor(Math.random() * (arr.length - i));   // j ∈ [i, n-1]
    [arr[i], arr[j]] = [arr[j], arr[i]];
  }
  return arr;
}
```

**为什么也正确？** 可以理解为「倒着做的镜像」：`[0, i-1]` 已确定，从 `[i, n-1]` 里随机选一个放到 `i`。每步的选择数仍是 `n, n-1, ..., 2`，总数 `n!`，同样是双射。

> **这个版本其实更有用**，因为它的前 k 步就能得到「前 k 个随机元素」，天然支持「部分洗牌」。

### 8.1.7 部分洗牌：只取前 k 个

**需求**：从 n 个元素中**等概率随机取 k 个**（且顺序也随机），不需要洗整个数组。

```js
function sampleK(arr, k) {
  const a = arr.slice();       // 不改原数组
  const n = a.length;
  const cnt = Math.min(k, n);
  for (let i = 0; i < cnt; i++) {
    const j = i + Math.floor(Math.random() * (n - i));   // j ∈ [i, n-1]
    [a[i], a[j]] = [a[j], a[i]];
  }
  return a.slice(0, cnt);
}
```

**复杂度**：O(k) 而不是 O(n)——**这是它的核心价值**。当 n = 10⁸、k = 10 时，差别是千万倍。

**应用**：
- 抽奖（从百万用户里抽 100 个）
- 随机推荐（从候选池里取 20 个）
- 随机分组

### 8.1.8 可复现的随机（种子随机）

**需求**：测试要可复现、或要做「同一个种子生成同一个牌局」（游戏、A/B 实验）。

`Math.random()` 无法设种子。要实现，得自己写一个 PRNG（伪随机数生成器）。

```js
// mulberry32：32 位种子，质量够用，代码极短
function mulberry32(seed) {
  return function () {
    seed |= 0;
    seed = (seed + 0x6D2B79F5) | 0;
    let t = Math.imul(seed ^ (seed >>> 15), 1 | seed);
    t = (t + Math.imul(t ^ (t >>> 7), 61 | t)) ^ t;
    return ((t ^ (t >>> 14)) >>> 0) / 4294967296;
  };
}

function shuffleSeeded(arr, seed) {
  const rand = mulberry32(seed);
  for (let i = arr.length - 1; i > 0; i--) {
    const j = Math.floor(rand() * (i + 1));
    [arr[i], arr[j]] = [arr[j], arr[i]];
  }
  return arr;
}

// 同一个 seed 永远得到同一个结果
shuffleSeeded([1,2,3,4,5], 42);   // 每次都是同一个排列
```

> **面试话术**：「`Math.random()` 不能设种子，所以测试里要可复现就得自己实现 PRNG。常用的有 mulberry32、xorshift，或者标准的 PCG。它们都是「确定性算法 + 种子」，输出看起来随机但可重现。」

### 8.1.9 一个相关的经典题：蓄水池抽样

**需求**：从一个**长度未知**的数据流中，等概率抽取 k 个元素（只能遍历一次、不能存全部）。

```js
function reservoirSample(stream, k) {
  const res = [];
  let i = 0;
  for (const x of stream) {
    if (i < k) {
      res.push(x);                              // 前 k 个直接放入
    } else {
      const j = Math.floor(Math.random() * (i + 1));   // j ∈ [0, i]
      if (j < k) res[j] = x;                    // 以 k/(i+1) 的概率替换
    }
    i++;
  }
  return res;
}
```

**为什么正确？** 归纳证明：处理到第 i 个元素时，蓄水池里每个元素被选中的概率都是 `k/i`。

- 基础：前 k 个，概率 `1 = k/k` ✅
- 归纳：处理第 `i+1` 个时，它被选中的概率是 `k/(i+1)`；原来池里的元素被保留的概率是 `1 - k/(i+1) × 1/k = 1 - 1/(i+1) = i/(i+1)`，所以它最终在池里的概率是 `(k/i) × i/(i+1) = k/(i+1)` ✅

**应用**：日志采样、大数据流抽样、随机抽取一条记录（k=1 的特例）、**从链表中随机取一个节点**（不知道长度）。

> **蓄水池抽样和洗牌是同一族问题**：都是「保证每个元素被选中的概率相等」，区别是洗牌知道 n、蓄水池不知道。

### 8.1.10 常见坑

| 坑 | 后果 | 修正 |
|---|---|---|
| `j ∈ [0, n-1]` 全范围 | 分布不均（偏差 10%+） | `j ∈ [0, i]` |
| `sort(() => Math.random() - 0.5)` | 分布不均 + O(n log n) | 用 Fisher-Yates |
| `Math.random() * i` 少了 `+1` | 永远选不到 `i` 本身，最后一个元素位置固定 | `* (i + 1)` |
| 忘记 `Math.floor` | `j` 是小数，`arr[j]` 是 `undefined` | 加 `Math.floor` |
| 用 `arr[j] = arr[i]` 不用临时变量 | 值被覆盖，数据丢失 | 解构或临时变量 |
| 循环写 `i >= 0` | 多一次无意义交换 | `i > 0` |
| 修改了入参却以为没改 | 调用方的数组被打乱 | 先 `slice()` 或明确说明 |
| 用 `Math.random()` 做安全场景 | **不是密码学安全的** | 用 `crypto.getRandomValues()` |

**关于最后一个坑（安全性）**：

`Math.random()` 的实现是 **xorshift128+**（V8），**可预测**——给定少量输出就能反推出内部状态。所以**绝对不能用于**：
- 生成密码、token、验证码
- 抽奖（可被预测）
- 加密密钥

**正确做法**：

```js
// 浏览器
const buf = new Uint32Array(1);
crypto.getRandomValues(buf);
const r = buf[0] / 2 ** 32;

// Node
const { randomInt } = require('node:crypto');
const r = randomInt(0, n);          // [0, n)
```

### 8.1.11 答题模板

**30 秒版**

> Fisher-Yates 洗牌：从最后一个位置倒着走，每次从 `[0, i]` 里等概率选一个和 `arr[i]` 交换。时间 O(n)，空间 O(1)。
> 正确性上，总共 n! 种等概率的选择序列，而每个排列恰好对应一种序列，所以每个排列概率都是 1/n!。
> 常见的错误写法是 `sort(() => Math.random() - 0.5)`，比较器不一致、违反传递性，结果依赖引擎实现，分布不均；还有一种是 `j` 取全范围 `[0, n-1]`，因为 nⁿ 不能被 n! 整除，也必然不均。

**2 分钟版（加分层）**

> 洗牌的核心要求是「每个排列等概率」，也就是 n! 种结果各 1/n!。
> Fisher-Yates 的做法是每次固定一个位置：从末尾开始，从还没确定的 `[0, i]` 里随机挑一个换到 i。这样第 i 个位置放谁在每一步都是均匀的，而且后续不会动它。
> 正确性证明用双射计数：每步选择数是 i+1，总路径数 n!，且每条路径等概率；关键是给定最终排列能唯一反推出每条路径的选择（从最后一个位置倒推），所以是双射，每个排列概率 1/n!。
> 两个常见错误。第一个是 `sort` 加随机比较器，比较器不一致，违反传递性，排序结果完全取决于引擎内部怎么比较，实测元素留在原位的概率明显偏高，而且不同引擎不一样——小数组可能碰巧均匀，但那是巧合。第二个是 j 取 `[0, n-1]` 全范围，nⁿ 条路径不能均分给 n! 个排列，n=3 时概率是 4/27 或 5/27 而不是 4.5/27。
> 延伸出去有两点。一是部分洗牌：如果只要前 k 个，用正向版只跑 k 步，O(k) 而不是 O(n)。二是如果数据是流式的、不知道长度，用蓄水池抽样，处理第 i 个元素时以 k/(i+1) 的概率替换池中随机一个。另外要注意 `Math.random` 不是密码学安全的，抽奖、token 这种场景要用 `crypto.getRandomValues`。

### 8.1.12 追问表

| 追问 | 回答要点 |
|---|---|
| 为什么从后往前？ | 已确定的位置在末尾，`[0,i]` 是未确定范围；正向版等价 |
| 为什么 `j` 是 `[0, i]` 不是 `[0, n-1]`？ | 全范围会导致 nⁿ 条路径无法均分 n! |
| `sort` 随机比较器为什么错？ | 比较器不一致，违反传递性，依赖引擎实现 |
| Fisher-Yates 的复杂度？ | O(n) 时间、O(1) 空间 |
| 怎么证明均匀？ | n! 条等概率路径 ↔ n! 个排列的双射 |
| 只要前 k 个怎么办？ | 正向版跑 k 步，O(k) |
| 不知道长度怎么办？ | 蓄水池抽样，第 i 个以 k/(i+1) 概率替换 |

| 洗牌和随机排序的区别？ | 「随机排序」通常指错误的 sort 写法；洗牌是 Fisher-Yates |
| 能否用 `arr.sort(() => 0.5 - Math.random())`？ | 同样错，只是符号反了，问题一样 |

## 8.2 最大的钻石（原题 1）

> ⚠️ **这不是算法题，是「最优停止理论」的经典问题（秘书问题 / Secretary Problem）**。
> 面试里它属于**智力题 / 概率题**，考的是「你能不能把模糊问题形式化，再给出可证明的策略」——**而不是背 37% 这个数字**。

### 一句话结论

**「先看前 37%（n/e）个，一个都不选，只记住其中最大的；之后遇到比它更大的就立刻选。」** 这个策略拿到最大钻石的概率约为 `1/e ≈ 36.8%`，且**在「只能选一次、不能回头、不知道后面还有多大」的约束下是数学上最优的**。

### 8.2.1 先把问题形式化（这一步最重要）

原题描述很模糊，面试时必须先澄清约束。**标准秘书问题的五个前提**：

| 前提 | 含义 | 去掉会怎样 |
|---|---|---|
| ① **n 已知** | 知道总共有多少层/多少个候选 | 不知道 n 需要在线策略，37% 不适用 |
| ② **随机顺序** | 钻石大小的排列是均匀随机的 | 如果顺序有规律（比如逐层变大），问题退化 |
| ③ **只能选一次** | 选定后不能改 | 允许改的话，看完再选，100% 成功 |
| ④ **不能回头** | 错过的不能再选 | 允许回头 = 允许改，同上 |
| ⑤ **只能比较，不知绝对值** | 只能判断「比之前的大/小」 | 如果知道分布，可以用贝叶斯方法 |

**面试话术**：「这个问题有几个隐含前提需要确认：能不能回头？知道总层数吗？目标是『一定拿到最大的』还是『最大化拿到最大的概率』？如果是前者，做不到；如果是后者，这就是经典的秘书问题，最优解是 37% 法则。」

**这一段「澄清」比后面的推导更能体现思维水平。**

### 8.2.2 为什么 100% 做不到

**只要「不能回头」且「必须当场决定」，就不可能 100% 拿到最大。**

反例：你在第 3 层看到一个很大的钻石，你选了它。但第 7 层有一个更大的——你永远不知道。**任何策略都可能在「选早了」上失败。**

所以目标只能是「**最大化成功的概率**」。

### 8.2.3 策略：先观察，后选择

**策略描述**：

1. 前 `m` 层**只看不选**，记录这 m 层里最大的那颗的大小，记为 `M`
2. 从第 `m+1` 层开始，遇到**第一个比 M 大的**就选它
3. 如果到最后一层都没遇到比 M 大的，就选最后一颗（或者接受失败，取决于题目是否允许空手）

**为什么这个策略合理？**

- 前 m 层用来「**建立基准**」：你需要知道「大概什么水平算大」，否则第一层就选，等于瞎猜
- 后面用来「**识别突破**」：比基准大的第一个，很可能是全局最大的

**这是个典型的「探索 vs 利用」（explore vs exploit）权衡**：
- m 太小 → 基准不可靠，容易选早
- m 太大 → 观察太久，真正的最大值可能已经在观察期错过了

### 8.2.4 推导：为什么是 1/e

设 `x = m/n`（观察期占总数的比例），我们要最大化成功率 `P(x)`。

**关键分析**：假设全局最大钻石在第 `i` 个位置（`i > m`，否则一定错过）。要成功，需要两个条件同时成立：

1. **最大值在第 i 个位置**：概率 `1/n`
2. **前 m 个里的最大值 < 第 i 个**：这等价于「前 `i-1` 个里的最大值出现在前 m 个里」。因为前 `i-1` 个是随机排列，最大值落在前 m 个的概率是 `m/(i-1)`

所以：

```
P(x) = Σ_{i=m+1}^{n} (1/n) × m/(i-1)
     = (m/n) × Σ_{i=m+1}^{n} 1/(i-1)
     = x × Σ_{k=m}^{n-1} 1/k
```

**用积分近似**（n 很大时，`Σ 1/k ≈ ∫ dx/x`）：

```
P(x) ≈ x × ∫_{x}^{1} dt/t = x × [ln t]_{x}^{1} = x × (0 - ln x) = x·ln(1/x)
```

**求最大值**：令 `f(x) = x·ln(1/x) = -x·ln x`

```
f'(x) = -ln x - 1 = 0
→ ln x = -1
→ x = 1/e ≈ 0.3679
```

**代回**：

```
P(1/e) = (1/e) × ln(e) = 1/e ≈ 0.3679
```

**结论**：跳过前 `n/e ≈ 36.8%` 的候选，成功率约 **36.8%**。

**这个结果的美妙之处**：无论 n 是 10 还是 10 亿，**最优比例都是 37%**，且成功概率都是 37%。这是一个「尺度无关」的常数。

> 面试话术：「设观察期比例是 x。最大钻石在第 i 个位置的概率是 1/n；要成功，还需要前 i-1 个里的最大值落在观察期内，概率是 m/(i-1)。求和得到 P ≈ x·ln(1/x)，求导得 x = 1/e，代回得 P = 1/e ≈ 37%。所以是『看 37%、选后面第一个更大的』，成功率 37%。」

### 8.2.5 具体数值（n 较小时）

37% 是 n → ∞ 的极限。n 小时最优 m 略有偏差：

| n | 最优 m | 最优成功率 |
|---|---|---|
| 3 | 1 | 50.0% |
| 4 | 1 | 45.8% |
| 5 | 2 | 43.3% |
| 10 | 3 | 39.9% |
| 20 | 7 | 38.4% |
| 100 | 37 | 37.1% |
| 1000 | 368 | 36.8% |
| ∞ | n/e | 36.79% |

**注意 n = 3 时成功率高达 50%**——因为样本太少，「运气」占比更大。这也说明 37% 是**渐近最优**，n 小时要单独算。

### 8.2.6 一个容易搞错的细节：必须是「严格大于」

策略里的条件必须是「**比观察期的最大值严格更大**」，不能是「大于等于」。

**为什么？**

如果允许等于，那你可能在第 `m+1` 个就选中一个「和观察期最大值一样大」的，而真正的最大值在后面。**严格大于能过滤掉「打平」的候选**，提高成功率。

（对于连续分布，打平概率为 0，区别不大；但对于离散的钻石大小，这个细节会影响结果。）

### 8.2.7 四个常见变体

**变体 1：允许回头（可以选之前看过的）**

那答案就是「看完所有，选最大的」，**成功率 100%**。所以「不能回头」是这个问题的**核心约束**，去掉就没有难度了。

**变体 2：允许「空手而归」**

如果策略允许「宁可不要也不选错的」，最优策略会稍微调整（阈值略高），成功率略升（因为「选错」的成本变成 0）。

**变体 3：不知道 n（在线版本）**

如果连总共有多少层都不知道，37% 无法计算。这时要用「**基于时间的策略**」：观察固定时长 T，之后遇到更大的就选。T 的最优值依赖对总时长的先验估计。

**变体 4：要选前 k 个（多个名额）**

如果允许选 k 个（比如「拿到前 3 大的任一即可」），阈值变成约 `(1/k)^(1/k)`：

| k | 观察比例 |
|---|---|
| 1 | 36.8% |
| 2 | 60.7% |
| 3 | 70.5% |
| 5 | 80.4% |

**直觉**：名额越多，越不需要「精确」，可以更晚开始选（观察更久）。

### 8.2.8 现实中的应用

| 场景 | 说明 |
|---|---|
| **招聘** | 面试一批候选人，何时停止面试直接发 offer |
| **租房/买房** | 看多少套房后开始下手 |
| **停车场选车位** | 开到第几个车位就该停 |
| **卖房定价** | 收到多少个 offer 后该接受 |
| **算法中的「在线算法」** | 在线匹配、竞价、资源分配 |
| **A/B 测试的停止时机** | 何时停止实验 |

**但要提醒**：现实问题通常不满足「n 已知 + 随机顺序 + 不能回头」这三个前提，所以 37% 只能作为**启发式参考**，不能当铁律。

> 面试如果问「现实中你会怎么用」，答：「37% 是个有用的启发——先花约三分之一的时间了解市场行情，之后遇到明显更好的就出手。但现实里 n 往往不确定、顺序不随机、而且通常允许一定程度的回头，所以我只会把它当参考，不会严格照做。」

### 8.2.9 答题模板

**30 秒版**

> 这是经典的秘书问题。前提是：知道总数、顺序随机、只能选一次、不能回头。在这个约束下，最优策略是先看前 37% 不选，只记住其中的最大值，之后遇到第一个更大的就选。
> 成功率约 1/e ≈ 37%，且在 n 很大时这个比例与 n 无关。
> 推导上，设观察比例 x，成功率约 x·ln(1/x)，求导得 x = 1/e。
> 但要注意：如果允许回头，或者知道钻石大小的分布，答案就完全不同了。

**2 分钟版（加分层）**

> 先澄清约束，因为这题的关键全在假设上。如果允许回头，那看完再选，100% 成功，问题就没意思了。所以核心前提是「只能选一次、不能回头、必须当场决定、n 已知、顺序随机」。
> 在这个前提下，100% 做不到——你永远可能在「选早了」上失败，所以目标只能是最大化概率。
> 策略是「先探索、后利用」：前 m 层只看不选，建立基准；之后遇到第一个超过基准的就选。m 太小基准不可靠，m 太大可能错过最大值，所以存在最优的 m。
> 设 x = m/n。最大钻石在第 i 个位置的概率是 1/n；要成功还需要前 i-1 个里的最大值落在观察期内，概率是 m/(i-1)。求和得到 P ≈ x·ln(1/x)，求导令其为 0 得 x = 1/e，代回得成功率 1/e ≈ 37%。
> 有个漂亮的结论：这个比例和 n 无关。n 是 10 还是 10 亿，都是看 37%、成功率 37%。n 较小时最优 m 会略偏，比如 n=3 时 m=1、成功率 50%。
> 现实应用里要提醒一点：招聘、租房这类场景往往不满足「n 已知 + 顺序随机 + 不能回头」，所以 37% 只能当启发式——先花约三分之一时间摸行情，之后遇到明显更好的就出手。

## 8.3 顺带补充：三个常一起问的概率题

这三题不在原题单里，但「概率题」环节经常连着问。

### 8.3.1 生日悖论：23 个人里有两个同生日的概率超过 50%

**直觉为什么错**：人容易想「23/365 ≈ 6%」，但那是「有人和我同生日」的概率。题目问的是「**任意两人**同生日」。

**正解**：算**不存在**重复的概率，再用 1 减。

```
P(全不重复) = (365/365) × (364/365) × ... × (365-22)/365
            = 365! / (365-23)! / 365²³
            ≈ 0.4927

P(至少一对重复) = 1 - 0.4927 ≈ 0.5073
```

**关键**：n 个人有 `C(n,2) = n(n-1)/2` 对，23 人就是 **253 对**。253 对里任意一对撞上的概率叠加起来就过半了。

**记忆点**：**23 → 50%，57 → 99%，367 → 100%（鸽巢原理）**。

### 8.3.2 三门问题（Monty Hall）：换门有 2/3 概率赢

**设定**：3 扇门，1 辆车 2 只羊。你选 1 号门，主持人**知道答案**，打开另一扇有羊的门（比如 3 号），问你换不换。

**答案**：**换，赢的概率 2/3；不换，1/3。**

**最清晰的解释**：你第一次选中的概率是 `1/3`（不换就固定在这个概率）。**没选中的概率是 `2/3`**，而这 `2/3` 现在全部集中在「剩下那扇没被打开的门」上（因为主持人一定打开有羊的门，且他不会打开你选的那扇、也不会打开有车的）。

```
初始:  P(1号是车) = 1/3    P(2或3号是车) = 2/3
主持人打开 3 号（有羊）:
        P(1号是车) = 1/3    P(2号是车) = 2/3
       ────────────────────────────────────
       不换 → 1/3          换 → 2/3
```

**关键前提**：**主持人知道答案，且一定会打开一扇有羊的门**。如果主持人随机开门（可能开出车），那换不换都一样。

**推广到 100 扇门**：你选 1 号，主持人打开 98 扇有羊的门，只剩你选的 1 号和另一扇。这时「另一扇是车」的概率是 99/100，**换显然更优**。这个版本比 3 门版更容易让人想通。

### 8.3.3 用 `rand5()` 实现 `rand7()`

**需求**：只有 `rand5()`（等概率返回 1~5），实现 `rand7()`（等概率返回 1~7）。

**错误答案**：`rand5() + rand5() - 1`（范围 1~9，且分布不均，中间值概率高）。

**正确答案：拒绝采样**

```js
function rand7() {
  while (true) {
    // 构造 1~25 的均匀分布（两个独立的 5 进制位）
    const num = (rand5() - 1) * 5 + rand5();   // 1~25
    if (num <= 21) return ((num - 1) % 7) + 1; // 1~21 均分给 7 个数，每个 3 种
  }
  // 22~25 拒绝，重新采样
}
```

**为什么可行**：`(rand5()-1)*5 + rand5()` 产生 1~25 的**均匀**分布。取 1~21（21 = 3×7，能整除），每个结果映射到 7 个数之一，概率 `3/25`。剩下 4 个（22~25）拒绝重来。

**期望调用次数**：每轮成功率 `21/25 = 0.84`，期望轮数 `1/0.84 ≈ 1.19`，每轮 2 次 `rand5`，所以**期望约 2.38 次调用**。

**通用套路**：`randM()` 实现 `randN()`，就是「构造一个 ≥ N 的均匀分布，取能整除 N 的部分，剩下拒绝」。**这叫拒绝采样（rejection sampling）**。
