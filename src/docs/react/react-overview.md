## 0.4 原题单答案里必须修正的 8 处

题单的答案大多是"关键词备忘录"，能提醒你考什么，但直接背会踩坑。下面 8 处是**照原话说会被追问打穿**的地方，各分册里都有展开：

| 原题 | 原答案 | 问题 | 正确说法 |
|---|---|---|---|
| 1 | 「虚拟 DOM 用 JS 对象描述 UI……好处：性能优化」 | 暗示「虚拟 DOM 比真实 DOM 快」 | 虚拟 DOM 比**全量重渲染**快，但比**手写最优 DOM 操作**慢。它的核心价值是声明式抽象与跨平台，性能是"保证下限" |
| 3 | 「原生事件和 setTimeout 中是同步的」 | 只在 React 17 及以前成立 | React 18 `createRoot` 下**全部自动批处理**，包括 setTimeout / Promise / 原生事件 |
| 6 | 「useEffect：异步渲染后执行；useLayoutEffect：同步渲染前执行」 | 时机描述错位 | 两者都在 **DOM 已更新之后**。useLayoutEffect 在 commit 的 layout 阶段同步执行（绘制前）；useEffect 在绘制后异步执行 |
| 20 | 「Concurrent Mode」 | 术语已废弃 | React 18 起没有「Concurrent Mode」这个开关，并发是 `createRoot` 下**默认开启**的特性集合 |
| 22 | 「配合 Suspense for Data Fetching」 | 容易误导 | 数据请求场景官方已转向框架层（Next/Remix）与 `use()`；Suspense 最稳定的用法仍是**代码分割** |
| 4 | 「先比类型，不同直接替换」 | 只说对了单节点 | 多节点要讲**两轮遍历 + map 索引 + lastPlacedIndex**，这才是 Diff 的考点 |
| 19 | 「把渲染拆成可中断的单元」 | 只答了"是什么"，没答"为什么" | 必须补：为什么 Stack Reconciler 不可中断（递归无法保存进度）、Fiber 用链表 + 双缓存实现断点续跑 |
| 31 | 「改造 dispatch，在 action 到达 reducer 前做日志」 | 没答出实现 | 中间件是 `({getState, dispatch}) => next => action => {}` 的柯里化链，由 `compose` 串起，`next` 指向下一个中间件或 store.dispatch |

## 0.7 怎么用这套文档

1. **第一遍**：只读每节的「一句话答案」和「要点顺序」，建立 36 个点的骨架（约 40 分钟）。
2. **第二遍**：读「核心原理」，P0 的七题必须能合上文档画出 Fiber 链表、diff 两轮遍历、commit 三阶段。
3. **第三遍**：用「口述参考」录音，卡壳的地方回看对应小节；每册末尾的自测题用来查漏。
4. **面试前**：只看每册开头的「本册速查」表和 0.4 的修正表。
