## 0.3 TS 面试的答题方法论

### 0.3.1 三段式：怎么写 → 编译成什么 → 什么时候会漏

**以「枚举」为例**：

| 段 | 内容 | 时长 |
|---|---|---|
| **① 怎么写** | `enum Direction { Up = 1, Down }`，数字枚举自动递增，也支持字符串枚举 | 15 秒 |
| **② 编译成什么** | **会生成运行时代码**：一个 IIFE 返回对象，并且**数字枚举有双向映射**（`Direction[1] === 'Up'`） | 25 秒 |
| **③ 什么时候会漏** | `const enum` 默认被内联、不产生运行时对象，但 `isolatedModules` 下访问 `declare const enum`（ambient）会报 TS2748；enum 不能被 tree-shaking；**现代更推荐 `as const` 对象 + 联合类型** | 40 秒 |

### 0.3.2 一个万能补充句式

``` 
「这一点在 TS 里是编译期的，运行时其实 ______。」
```

几乎每一道 TS 概念题都能用这句话收尾。举几个例子：

| 题目 | 补充句式 |
|---|---|
| 访问修饰符 `private` | 「`private` 只在**编译期**检查，编译后的 JS 里这个属性照样能访问，用 `#x` 才是真正的运行时私有」 |
| `interface` | 「`interface` 编译后**完全消失**，一行代码都不剩」 |
| 类型断言 `as` | 「`as` **不做任何运行时检查**，它就是告诉编译器『闭嘴』，断言错了运行时直接崩」 |
| 泛型 | 「泛型只存在于编译期，编译后 `<T>` 会被**擦除**，运行时拿不到 `T` 是什么」 |
| `enum` | 「enum 会**生成运行时代码**：数字枚举是 IIFE + 双向映射；namespace、装饰器、参数属性同理，并非所有类型语法都被擦除」 |

### 0.3.3 四个扣分点

| 扣分点 | 错误说法 | 正确说法 |
|---|---|---|
| **以为 TS 会做运行时类型检查** | 「TS 会检查传进来的类型对不对」 | **完全不会**。TS 只做编译期检查，运行时类型全被擦除。接口传错类型、JSON 解析出的数据、`as` 断言错了，**运行时都不会报错** |
| **以为 `private` 是安全的** | 「`private` 属性外部访问不了」 | 只在编译期报错，**运行时能访问**；`#x` 才是真私有 |
| **把 `any` 和 `unknown` 当成一样** | 「都是任意类型」 | `any` 会**传染**（参与运算后结果还是 any，等于关掉检查）；`unknown` 必须先收窄 |
| **以为 `interface` 和 `type` 只差语法** | 「随便用哪个都行」 | `interface` 能**声明合并**、有**类型缓存**（性能）、能被 `implements`；`type` 能表达联合/元组/条件类型 |

### 0.3.4 面试官在听什么

| 层次 | 表现 | 评价 |
|---|---|---|
| L1 | 能说出语法（`interface` 用 `extends` 扩展） | 及格 |
| L2 | 能说出差异（`interface` 能合并，`type` 不能） | 大多数人的水平 |
| L3 | 能说出**编译产物**（enum 双向映射、namespace 是 IIFE） | 优秀 |
| L4 | 能说出**边界与失效场景**（`as` 不检查、`private` 是假的、泛型被擦除） | 很优秀 |
| L5 | 能说出**工程决策**（为什么这个项目不用 enum 而用 `as const`；为什么开 `isolatedModules`） | 顶尖 |

## 0.4 一张图装下 TS 知识体系

```
┌───────────────────────────────────────────────────────────────┐
│  第 0 层：TS 到底是什么                                          │
│  JS 超集 / 类型擦除 / 编译期检查 / 结构化类型 / 不保证运行时安全    │
└───────────────────────────┬───────────────────────────────────┘
                            │
        ┌───────────────────┼───────────────────┐
        ▼                   ▼                   ▼
┌───────────────┐   ┌───────────────┐   ┌───────────────┐
│ 第 1 层        │   │ 第 2 层        │   │ 第 3 层        │
│ 类型系统基础    │   │ 类型抽象能力    │   │ 工程与运行时    │
├───────────────┤   ├───────────────┤   ├───────────────┤
│ 原始类型       │   │ 泛型           │   │ tsconfig       │
│ 联合 / 交叉    │   │ 条件类型        │   │ sourcemap      │
│ 字面量类型     │   │ 映射类型        │   │ .d.ts / declare│
│ 元组           │   │ keyof / typeof │   │ namespace      │
│ any/unknown    │   │ 方法重载        │   │ 装饰器          │
│ never/void     │   │ interface/type │   │ enum 的运行时代码│
│ 类型收窄       │   │ 类与 OOP       │   │ 模块解析        │
│ 类型断言       │   │ mixin          │   │                │
└───────────────┘   └───────────────┘   └───────────────┘
```

**这张图的用法**：面试被问任何一个 TS 问题，先定位它在哪一层，然后**往「编译产物」和「工程决策」两个方向延伸**。

比如被问「泛型」：
- 第 2 层：类型参数化，`<T>`
- 往编译产物延伸：**编译后被擦除，运行时拿不到 T**
- 往工程决策延伸：什么时候用泛型 vs 联合类型 vs `unknown` + 收窄

## 0.5 题单的 11 个问题（含 3 个代码 bug）

### 0.5.1 三个真实的代码 bug（必须改）

| # | 题号 | Bug | 后果 |
|---|---|---|---|
| 1 | **12 myAll** | **空数组永远不 resolve** | `myAll([])` 返回的 Promise **永久 pending**，因为 `forEach` 不执行、`count` 永远不等于 `length`（0）。正确做法是先判断 `length === 0` 直接 resolve |
| 2 | **16 reverseWord** | `split(/\s+/)` 遇前导空格会产生**空字符串元素** | `' hello world'.split(/\s+/)` → `['', 'hello', 'world']`，反转后变成 `'world hello '`（末尾多一个空格）。必须先 `trim()` |
| 3 | **11 product** | 参数类型是 `any[][]`，**完全丢掉类型信息** | 返回值是 `any[][]`，等于没有类型。可以用**泛型 + 元组映射**做到精确推导（本册 10 给了实现） |

| # | 题号 | 缺什么 | 修正位置 |
