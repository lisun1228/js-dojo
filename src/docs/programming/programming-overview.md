## 0.4 手写题到底在考什么（评分表）

面试官看你写代码时，心里有一张表。知道这张表长什么样，你就知道该往哪使劲：

| 维度 | 权重 | 具体在看什么 | 常见失分 |
|---|---|---|---|
| **边界意识** | ⭐⭐⭐⭐⭐ | 空数组、null、undefined、单元素、重复元素 | 只测了「正常情况」就停手 |
| **正确性** | ⭐⭐⭐⭐⭐ | 主流程对不对 | 循环引用、返回值丢失 |
| **口述能力** | ⭐⭐⭐⭐ | 边写边解释「为什么这么写」 | 闷头写，一句话不说 |
| **复杂度意识** | ⭐⭐⭐ | 主动说出时间/空间复杂度 | 等面试官问才说 |
| **演进能力** | ⭐⭐⭐ | 写完基础版能主动补强 | 写完就停 |
| **命名与结构** | ⭐⭐ | 变量名有含义、函数拆得开 | `a`、`b`、`tmp`、`res1` |

**关键洞察**：`⭐⭐⭐⭐⭐` 那两项加起来比「代码能不能跑」更重要。因为**能背出这段代码的人太多了，能主动说「这里空数组会死锁」的人很少**。

下面每一册的每道题，都会明确标出「**这道题的加分点在哪**」。

## 0.5 编程题答题四步法

### 第 1 步：先接住题，别急着敲键盘（10 秒）

面试官说「写个防抖」，你不要立刻开始敲。先说一句：

> 「好，防抖我按这四块来：**语义是什么、核心实现、边界处理、能不能扩展**。我先写核心版，然后补边界。」

这一句话的作用：**告诉面试官你有结构**。有结构的人在评分表上直接高一档。

### 第 2 步：写核心版，同时说出「为什么」（1-3 分钟）

边写边说，不要沉默。比如写防抖：

```js
function debounce(fn, delay) {
  let timer = null;              // ← 说：「用闭包保存 timer，这是整个实现的核心」
  return function (...args) {    // ← 说：「返回新函数，每次调用重置计时器」
    clearTimeout(timer);
    timer = setTimeout(() => fn.apply(this, args), delay);
    //                            ↑ 说：「用箭头函数保住外层 this，用 apply 透传参数」
  };
}
```

**每写一行关键代码，说一句它的作用**。沉默 30 秒以上，面试官会以为你卡住了。

### 第 3 步：主动补边界（这是区分度最高的一步）

写完核心版，**不要等面试官问**，自己说：

> 「核心逻辑好了，我补几个边界：**空输入、连续调用、this 指向、返回值**。另外实际项目里还需要 `cancel` 和 `immediate` 两个开关。」

然后补代码。这一步做不做，直接决定你是「背过」还是「懂了」。

### 第 4 步：主动给复杂度 + 演进方向

> 「时间复杂度是 O(1)，空间 O(1)。如果要支持**返回值**，得改成一个返回 Promise 的版本；如果要支持**取消**，就得把 timer 和取消函数一起暴露出去。」

## 0.6 三道题就能区分「背过」和「懂」

| 你说的 | 面试官听到的 |
|---|---|
| 「防抖就是延迟执行」 | 背过 |
| 「防抖是延迟执行，节流是固定频率执行」 | 背过，且知道两者的区别 |
| 「防抖延迟执行、节流固定频率。**但这两个实现的共同问题是尾调用会丢**——防抖在 delay 内一直触发就永远不执行，节流的时间戳版最后一次点击不响应。实际项目里 lodash 的版本要配 `trailing: true`」 | 真懂 |

**记住这个句式**：

> 「这个实现能跑，但它有 \_\_\_ 的限制。生产环境里通常用 \_\_\_ 来解决，代价是 \_\_\_。」

这个句式可以套用到本册**每一道题**上，是手写题里性价比最高的一句话。

## 0.8 每道题的自测用例（照着测，别只测正常情况）

写完之后，**主动跑一遍这张表**，这就是「边界意识」的具体表现。

### 通用边界清单

```
□ 空输入：[] / {} / '' / null / undefined
□ 单元素：[1] / {a:1}
□ 重复元素：[1,1,1]
□ 类型混入：[1,'1',null,undefined,NaN,{},[]]
□ 特殊值：NaN / -0 / Infinity / Symbol / 大整数
□ 返回值：函数有没有返回东西？返回的对不对？
□ this：通过 obj.method() 调用时 this 对吗？
□ 异常路径：回调里 throw 会怎样？
□ 二次调用：连调两次状态还对吗？
□ 资源释放：定时器 / 监听器 / 缓存会不会泄漏？
```

### 分题速查

| 题 | 必测用例 |
|---|---|
| 防抖 | 连打 10 次 → 1 次；间隔 > delay 连打 → 每次都执行；`cancel()` 生效 |
| 节流 | 高频连打 → 频率 = 1/interval；**最后一次是否响应** |
| curry | 无默认参数函数；**带默认参数函数**（`fn.length` 会变小）；`fn.length === 0` |
| compose | `compose()` 空参；单函数；多参数函数放最右 |
| reduce | 空数组无初始值（应抛 TypeError）；`[,,3]` 稀疏；显式传 `undefined` |
| call/apply | ctx 上有同名属性；ctx 是原始值；apply 不传 args |
| bind | `new bound()`；`instanceof` 关系；多次 bind 只认第一个 |
| new | 构造函数返回对象；返回 `Object.create(null)`；`new` 一个非函数 |
| instanceof | 原始值；`null`；跨 iframe（构造函数不同） |
| Promise | 已 settled 后 then；then 里 throw；then 返回 promise；resolve 自己 |
| all | **空数组**；非数组 iterable；某项已 reject；resolve 位置错乱 |
| race | 空数组（永久 pending，符合规范）；同步值 |
| retry | 首次就成功；全部失败（总次数 = times+1）；fn 同步抛错 |
| 并发限制 | 任务数 < limit；任务同步抛错；结果顺序 |
| 深拷贝 | Date/RegExp/Map/Set/Symbol/函数/类实例/循环引用/`Object.create(null)` |
| 去重 | `NaN`；`0` 与 `-0`；对象引用；`'1'` 与 `1` |
| flat | 多级嵌套；稀疏数组；带 depth 参数 |
| 千分位 | 负数；**4 位以上小数**；`1e21`；字符串输入；`0` |
| URL | 重复 key；`+`；`#`；空值 `?a=`；无值 `?a`；中文编码 |
| 括号 | 含字母；空串；只有左括号；只有右括号；交叉 `([)]` |
| LRU | 容量 1；重复 get 刷新顺序；put 已存在的 key |
| EventBus | once + on 混合；emit 中 off；off 不传 cb；回调抛错 |
| setInterval | 回调内 stop；间隔是否累积漂移 |
