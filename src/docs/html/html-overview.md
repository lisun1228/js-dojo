## 0.3 题单的 12 个问题（我做了修正）

除重复外，部分原答案本身也有事实错误。

| # | 题号 | 原答案的问题 | 严重度 | 正确说法 | 修正位置 |
|---|---|---|---|---|---|
| 1 | 13 | 把 `img` 标成「行内块」 | **高** | `img` 是 **inline 级 replaced element**，默认 `display: inline`。它看起来像 inline-block，是因为它有**内在尺寸**（intrinsic size），不是 `display` 变了 | 02 册 2.3 |
| 2 | 37 | 「src 加载完才继续」 | **高** | 只有 **`<script src>` 会阻塞解析**。`<img src>`、`<iframe src>` **不阻塞** HTML 解析（img 只影响 `load` 事件和渲染） | 04 册 4.9 |
| 3 | 33 | 「盒模型 = content + padding + border + margin」 | **高** | `margin` 不参与 `width`/`height` 的尺寸计算，它是盒子边界之外的间距。盒模型讲的是 `width` 是否包含 padding + border | 08 册 8.5 |
| 4 | 45 | 「`javascript:;` 等价于 `javascript:void(0)`」 | 中 | 两者都能阻止跳转；`href="#"` 会跳到页顶并新增一条历史记录，`javascript:` 形式不会 | 03 册 3.4 |
| 5 | 17 | 「HTML5 离线缓存 … 本地缓存是 HTTP 缓存」 | 中 | AppCache 的对照物不是 HTTP 缓存，而是 **Service Worker**。HTTP 缓存是「被动命中」，AppCache/SW 是「主动控制」 | 06 册 6.3 |
| 6 | 8 | 「async 下载完立即执行（可能阻塞）」 | 中 | 阻塞发生在**执行**阶段，不是下载阶段。准确说法：**async 下载不阻塞、执行阻塞解析** | 05 册 5.2 |
| 7 | 4 / 27 | 状态码只列 9 个，且「304 缓存」表述含糊 | 中 | 304 是**协商缓存命中**（不是「缓存」这个动作）；且缺 **204/206/303/307/308/429/502/503/504** | 08 册 8.11 |
| 8 | 5 | 「语义化标签利于 SEO」 | 中 | 语义化对排名的**直接权重很低**。它真正的作用是：可访问性、代码可维护性、以及让爬虫更好理解**内容结构** | 02 册 2.4 |
| 9 | 41 / 46 | 「HTML 中一样」 | 低 | 准确说：HTML5 **允许** `<br />` 这种尾部斜杠（向后兼容），但 `<br></br>` **不合法**；XHTML 则**必须**自闭合 | 01 册 1.5 |
| 10 | 7 | 「localStorage 5MB」 | 低 | 5MB 是普遍值：Chrome、Safari 约 5MB，Firefox 约 10MB。Cookie 是 **4KB 左右（含 name/value/属性）** | 06 册 6.2 |
| 11 | 6 / 54 | 只提「怪异模式盒模型不一致」 | 中 | 普通元素的盒模型在怪异模式下不变；真实差异是百分比高度、行内元素行高、表格单元格高度。还缺三种模式（**标准 / 准标准 / 怪异**）与 `document.compatMode`（只能区分标准与怪异） | 01 册 1.3 |
| 12 | 全单 | 混入 CSS / 网络 / 工程化 / 框架题 | 中 | 这不是「HTML 题单」，是「前端基础混合题单」 | 08 册开头 |

## 0.4 HTML 题的答题方法论

HTML 题的基础答案高度同质，区分点集中在**「为什么」和「边界」**上。

### 0.4.1 三段式：是什么 → 为什么 → 边界/坑

以「DOCTYPE」为例：

| 段 | 内容 | 时长 |
|---|---|---|
| **① 是什么** | `<!DOCTYPE html>` 是文档类型声明，写在 `<html>` 之前，告诉浏览器用标准模式渲染 | 10 秒 |
| **② 为什么** | 1990 年代浏览器各自为政，W3C 用 DTD 区分「按规范渲染」和「兼容老页面渲染」。HTML5 之后 DTD 没用了，但 doctype 被保留成**一个纯粹的「模式开关」** | 30 秒 |
| **③ 边界/坑** | 去掉它 → 怪异模式：百分比高度按视口解析、行内元素行高计算不同、表格单元格高度包含 padding/border（详见 01 册 1.3）；`document.compatMode` 返回 `BackCompat` | 40 秒 |

### 0.4.2 HTML 题的三个特有加分点

| 加分点 | 说明 | 例子 |
|---|---|---|
| **无障碍（a11y）** | 任何「标签/属性」类问题，都可以补一句「这对屏幕阅读器意味着什么」 | alt、label、`aria-*`、`role`、键盘可达 |
| **性能指标化** | 把「优化性能」落到具体指标：这个改动影响 LCP / CLS / INP 里的哪一个 | `img` 不写宽高 → CLS；`loading=lazy` 用在首屏 → 拖慢 LCP |
| **规范出处** | 能说出「这是 HTML 规范的 void element」「这是 WHATWG living standard 里定义的」 | 空元素、content model |

### 0.4.3 四个扣分点

| 扣分点 | 错误说法 | 正确说法 |
|---|---|---|
| **把 display 当 HTML 分类** | 「div 是块级元素，span 是行内元素，这是 HTML 规定的」 | HTML 规范分的是 **content model**（flow / phrasing / sectioning…），`display` 是 **CSS 的默认值**，可以被改掉 |
| **把「不阻塞」说成「同步/异步加载」** | 「defer 是异步，async 是同步」 | 两者**下载都是异步的**，区别在**执行时机和顺序** |
| **把 SEO 归功于语义化标签** | 「用了 header/nav 所以 SEO 好」 | 排序靠内容质量 + 外链 + 性能 + 结构化数据；语义化只帮**理解**，不直接提升**排名** |
| **`alt` 和 `title` 混用** | 「alt 是悬停提示」 | `alt` 是**替代文本**（图片挂了/读屏器读它）；`title` 是**补充说明**（悬停提示），且触摸设备没有 hover |

### 0.4.4 面试官在听什么

| 层次 | 表现 |
|---|---|
| L1 | 能说出标签名和属性名 |
| L2 | 能说出默认行为和常见用法 |
| L3 | 能说出**为什么这么设计**（为什么 script 要阻塞、为什么 doctype 要保留） |
| L4 | 能说出**边界和坑**（什么情况下失效、什么组合会出问题） |
| L5 | 能串到**性能和线上问题**（CLS、白屏、首屏变慢） |

L4 的区分点是「坑」，L5 的区分点是「指标」。
