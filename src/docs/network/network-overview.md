## 0.3 网络题的答题方法论

网络题天然分层：答题时先说清自己在讲哪一层，再往下展开。

### 0.3.1 三段式：是什么 → 为什么 → 工程实践

**以「三次握手」为例**：

| 段 | 内容 | 时长 |
|---|---|---|
| **① 是什么** | 三次握手的三个报文：SYN → SYN+ACK → ACK，顺带说序号变化 | 20 秒 |
| **② 为什么** | 为什么是 3 次不是 2 次也不是 4 次：确认双方收发能力 + 同步 ISN + 防历史连接 | 40 秒 |
| **③ 工程实践** | SYN Flood 与 SYN Cookie、半连接队列、SYN 重传次数、连接复用 | 40 秒 |

只答 ① 覆盖的是表面流程；② 说明设计原因；③ 给出现象与边界。常见问题是只背了 ①，被追问「为什么」就无法展开。

### 0.3.2 一个万能补充句式

几乎每道网络题都可以按这个句式补一层工程表现：

> 「这个问题在线上表现为 ______，根因是 ______，修复方式是 ______。」

举几个例子：

| 题目 | 补充句式 |
|---|---|
| 三次握手 | 「线上表现是 SYN Flood 攻击打满半连接队列，服务端表现为连接超时；防护手段是 SYN Cookie 和调大队列」 |
| HTTP 缓存 | 「线上表现是发版后用户还看到旧页面，根因是 `index.html` 被强缓存了，所以入口 HTML 必须 `no-cache`」 |
| 跨域 | 「线上表现是预检请求 403，根因是网关没处理 OPTIONS，或者 `Allow-Origin` 写成了 `*` 但带了 cookie」 |
| HTTPS | 「线上表现是安卓低版本 App 报证书错误，根因是根证书链缺了中间证书」 |

### 0.3.3 四个扣分点

| 扣分点 | 例子 | 正确说法 |
|---|---|---|
| **把 SOP 当成「禁止发请求」** | 「跨域就是请求发不出去」 | SOP 限制的是**读响应**，简单请求已经发出去了，只是响应被浏览器拦下 |
| **混淆「HTTP 队头阻塞」和「TCP 队头阻塞」** | 「HTTP/2 解决了队头阻塞」 | HTTP/2 只解决了 **HTTP 层**的；**TCP 层**的反而更严重了（一个丢包卡住所有 stream） |
| **把「非对称加密数据」当正确答案** | 「HTTPS 用非对称加密传数据」 | 非对称只用来**协商/验证**，数据全程用对称加密（性能差几个数量级） |
| **缓存指令混用** | 「no-cache 就是不缓存」 | `no-cache` 是**可以缓存但每次要验证**；`no-store` 才是完全不缓存 |

### 0.3.4 面试官在听什么

| 层次 | 表现 | 评价 |
|---|---|---|
| L1 | 能说出名词（「三次握手」「强缓存」） | 及格线 |
| L2 | 能说出流程（三个报文、两个头部） | 大多数人的水平 |
| L3 | 能说出**为什么这样设计**（为什么 3 次、为什么 ETag 优先） | 优秀 |
| L4 | 能说出**边界和失效场景**（什么时候会退化、什么情况下不能用） | 很优秀 |
| L5 | 能说出**线上排障经验**（现象 → 定位 → 根因 → 修复） | 顶尖 |

## 0.4 一张图装下整个网络知识体系

```
┌─────────────────────────────────────────────────────────────────┐
│  你的问题：在浏览器输入 URL，按下回车，发生了什么？                  │
└─────────────────────────────────────────────────────────────────┘
                              │
        ┌─────────────────────┼─────────────────────┐
        ▼                     ▼                     ▼
   ┌─────────┐          ┌──────────┐          ┌──────────┐
   │ 找得到吗 │          │ 连得上吗  │          │ 看得懂吗  │
   │  DNS    │          │ TCP/TLS  │          │ HTTP/渲染 │
   └─────────┘          └──────────┘          └──────────┘
        │                     │                     │
   ├─ 浏览器缓存          ├─ 三次握手            ├─ 请求报文
   ├─ hosts              ├─ 四次挥手            ├─ 响应报文
   ├─ 本地 DNS（递归）    ├─ 滑动窗口            ├─ 状态码
   ├─ 根/顶级/权威（迭代） ├─ 拥塞控制            ├─ 头部（缓存/跨域/Cookie）
   └─ CDN 调度            └─ TLS 握手+证书       ├─ 缓存判定
                                                  ├─ 解析 DOM/CSSOM
                                                  └─ 布局/绘制/合成
```

任何网络问题先定位到「找得到 / 连得上 / 看得懂」中的哪一段，再往下展开。

三段的典型故障：

| 段 | 故障现象 | 排查方向 |
|---|---|---|
| **找得到** | `DNS_PROBE_FINISHED_NXDOMAIN`、首次访问慢、部分地区打不开 | DNS 解析、CDN 调度、TTL |
| **连得上** | `ERR_CONNECTION_TIMED_OUT`、`ERR_CONNECTION_RESET`、TLS 报错 | 防火墙、握手失败、证书过期 |
| **看得懂** | 403、304、CORS 报错、页面白屏 | 状态码、缓存头、跨域头、JS 报错 |
