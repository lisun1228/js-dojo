# 网络 · 01 分层模型与数据封装（题 45）

> 本册覆盖：OSI 七层模型（原题 45）
> 题单只给了七个层名，没给协议、没给设备、没说为什么实际用 TCP/IP 四层。
> **这题本身是「送分题」，但它是理解所有网络问题的坐标系**——后面每一册的内容都能定位到某一层。

---

## 1.1 一句话结论

网络通信被拆成**若干层**，每层只解决一类问题、只和上下相邻层打交道。**OSI 是七层的理论模型（教学/描述用），TCP/IP 是四层的工程实现（真正跑在互联网上的），面试时通常说「五层」**（把 TCP/IP 的网络接口层拆成数据链路层 + 物理层），既好讲又对齐现实。

## 1.2 OSI 七层 vs TCP/IP 四层 vs 五层

### 1.2.1 三张表对照

| # | OSI 七层 | TCP/IP 四层 | 五层（教学常用） | 干的事 | PDU | 典型协议 | 设备 |
|---|---|---|---|---|---|---|---|
| 7 | **应用层** | 应用层 | 应用层 | 为应用提供网络服务 | 报文 | HTTP、HTTPS、DNS、FTP、SMTP、SSH、WebSocket | — |
| 6 | **表示层** | 应用层 | 应用层 | 编码转换、压缩、加密 | — | TLS/SSL、JPEG、gzip、UTF-8 | — |
| 5 | **会话层** | 应用层 | 应用层 | 建立/管理/终止会话 | — | RPC、Socket 会话、NetBIOS | — |
| 4 | **传输层** | 传输层 | 传输层 | 端到端（进程到进程）传输 | **段**（TCP）/ 数据报（UDP） | TCP、UDP、QUIC | — |
| 3 | **网络层** | 网络层 | 网络层 | 主机到主机、路由寻址 | **包** | IP、ICMP、ARP*、NAT、OSPF、BGP | 路由器、三层交换机 |
| 2 | **数据链路层** | 网络接口层 | 数据链路层 | 相邻节点间传输、成帧、差错检测 | **帧** | 以太网、Wi-Fi、PPP、VLAN | 交换机、网桥、网卡 |
| 1 | **物理层** | 网络接口层 | 物理层 | 比特流在介质上传输 | **比特** | 双绞线、光纤、无线电 | 集线器、中继器、网线 |

\* ARP 的归属有争议：它工作在「链路层与网络层之间」，教材多归到网络层，也有人说链路层。面试时说「**介于网络层和链路层之间**」最稳。

### 1.2.2 为什么 OSI 七层没被采用，实际用 TCP/IP 四层

**OSI 失败的原因**（这段答出来很加分）：

| 原因 | 说明 |
|---|---|
| **标准先于实现** | OSI 是先制定标准再找人实现，等标准定完（1984 年）TCP/IP 已经跑了好几年（ARPANET 1969 起） |
| **分层太细** | 会话层、表示层在实际实现中很难划清边界，最后都被并进应用层 |
| **实现太复杂** | OSI 的协议规范动辄上千页，厂商实现成本极高 |
| **政治与商业博弈** | 各国/各厂商都想在标准里塞自己的东西，导致标准臃肿 |

**TCP/IP 成功的原因**：**「先跑起来，再定标准」**（rough consensus and running code）。它只分四层，够用、简单、免费（BSD 实现）。

> 面试话术：「OSI 是理论模型，七层分得漂亮但不实用——会话层和表示层在实际代码里没法独立实现。TCP/IP 是工程实现，四层够用就跑起来了。所以现在**用 OSI 的术语描述问题，用 TCP/IP 的协议栈干活**。面试说五层是最稳的：应用、传输、网络、链路、物理。」

### 1.2.3 为什么分层（这是「为什么」层面的问题）

| 好处 | 说明 | 例子 |
|---|---|---|
| **解耦** | 每层只依赖下一层的接口，不关心内部实现 | 换 WiFi 为 4G，HTTP 代码一行不用改 |
| **独立演进** | 某一层的升级不影响其他层 | HTTP/2 → HTTP/3 换掉了传输层（TCP→QUIC），应用层代码几乎不动 |
| **故障定位** | 出问题先定位到层，再往下查 | 「能 ping 通但网页打不开」→ 网络层 OK，问题在传输层之上 |
| **标准化** | 每层可以独立实现、独立优化 | 网卡厂商不需要懂 HTTP |

**面试时一定要举「HTTP/3 换传输层」这个例子**——它是「分层价值」最有力的证明：**五十年没动的传输层，被替换掉了，而应用层几乎无感**。

## 1.3 各层协议全家桶

### 1.3.1 应用层（前端最关心的一层）

| 协议 | 端口 | 传输层 | 用途 |
|---|---|---|---|
| **HTTP** | 80 | TCP | 超文本传输 |
| **HTTPS** | 443 | TCP（HTTP/3 是 UDP） | HTTP + TLS |
| **HTTP/3** | 443 | **UDP（QUIC）** | 下一代 HTTP |
| **WebSocket** | 80 / 443 | TCP | 全双工 |
| **DNS** | 53 | **UDP**（大响应/区域传送用 TCP） | 域名解析 |
| **FTP** | 20 / 21 | TCP | 文件传输（明文，已淘汰） |
| **SMTP / IMAP / POP3** | 25 / 143 / 110 | TCP | 邮件 |
| **SSH** | 22 | TCP | 远程登录 |
| **MQTT** | 1883 / 8883 | TCP | IoT 消息 |
| **gRPC** | — | TCP（HTTP/2） | RPC |

### 1.3.2 传输层

| 协议 | 特点 | 头部大小 |
|---|---|---|
| **TCP** | 面向连接、可靠、有序、字节流、有流控拥塞控制 | 20 字节起（含选项最多 60） |
| **UDP** | 无连接、不可靠、保留消息边界、无流控 | **8 字节** |
| **QUIC** | 基于 UDP，自己在用户态实现可靠传输 + 多路复用 + TLS 1.3 | — |

### 1.3.3 网络层

| 协议 | 用途 |
|---|---|
| **IP**（IPv4 / IPv6） | 寻址 + 路由，**尽力而为（best effort）** |
| **ICMP** | 差错报告与探测（`ping` 用的就是 ICMP Echo） |
| **ARP** | IPv4 地址 → MAC 地址（IPv6 用 NDP） |
| **NAT** | 内网地址 ↔ 公网地址转换（缓解 IPv4 枯竭） |
| **OSPF / BGP** | 路由协议（域内 / 域间） |

### 1.3.4 数据链路层 / 物理层

| 协议/技术 | 说明 |
|---|---|
| **以太网（Ethernet）** | 最常见的局域网技术，帧头 14 字节 + FCS 4 字节 |
| **Wi-Fi（802.11）** | 无线局域网 |
| **PPP** | 拨号/点对点 |
| **VLAN（802.1Q）** | 在以太网帧里插 4 字节标签做隔离 |
| **双绞线 / 光纤 / 无线电** | 物理介质 |

## 1.4 封装与解封装（这题最值得展开的部分）

### 1.4.1 一次 HTTP 请求的封装过程

```
应用层  ┌──────────────────────────────────────────┐
        │  HTTP 报文                                │
        │  GET /index.html HTTP/1.1                │
        │  Host: example.com                       │
        │  ...                                     │
        └──────────────────────────────────────────┘
                          ↓ 交给传输层
传输层  ┌────────────┬─────────────────────────────┐
        │ TCP 头 20B │  HTTP 报文                    │  ← 加源端口/目的端口/序号/ACK/窗口
        └────────────┴─────────────────────────────┘
                          ↓ 交给网络层
网络层  ┌───────────┬────────────┬──────────────────┐
        │ IP 头 20B │ TCP 头 20B │  HTTP 报文        │  ← 加源 IP/目的 IP/TTL/协议号
        └───────────┴────────────┴──────────────────┘
                          ↓ 交给链路层
链路层  ┌────────┬───────────┬────────────┬─────────┬─────┐
        │ 以太网 │  IP 头 20B │ TCP 头 20B │ HTTP    │ FCS │  ← 加源 MAC/目的 MAC/类型
        │ 头 14B │            │            │ 报文    │ 4B  │
        └────────┴───────────┴────────────┴─────────┴─────┘
                          ↓ 交给物理层
物理层  ┌──────────────────────────────────────────────┐
        │  0101010101010101...（比特流）                 │
        └──────────────────────────────────────────────┘
```

**关键点：每一层都在「上一层交下来的整块数据」前面加自己的头**，这叫**封装（encapsulation）**。接收方逐层剥掉自己那层的头，叫**解封装（decapsulation）**。

### 1.4.2 各层头部字节数（面试常问「一个 TCP 包最多能装多少数据」）

| 层 | 头部大小 | 说明 |
|---|---|---|
| 以太网帧头 | **14 字节** | 目的 MAC(6) + 源 MAC(6) + 类型(2) |
| 以太网帧尾 FCS | 4 字节 | 帧校验序列 |
| IPv4 头 | **20 字节**（最小） | 含选项时最多 60 |
| IPv6 头 | 40 字节 | 固定长度（选项放扩展头） |
| TCP 头 | **20 字节**（最小） | 含选项时最多 60 |
| UDP 头 | **8 字节** | 源端口(2)+目的端口(2)+长度(2)+校验和(2) |

### 1.4.3 MTU 与 MSS（这道计算题很常考）

**MTU（Maximum Transmission Unit）**：链路层一次能传的最大帧负载，以太网默认 **1500 字节**。

**MSS（Maximum Segment Size）**：TCP 一次能传的最大数据量。

```
MSS = MTU - IP 头 - TCP 头
    = 1500 - 20 - 20
    = 1460 字节
```

**所以「一个 TCP 段最多装 1460 字节的应用数据」**。这也是为什么大文件传输会被切成很多个 1460 字节的段。

**如果 IP 包超过 MTU 会怎样？**

| 情况 | 行为 |
|---|---|
| **IPv4** | 路由器可以**分片**（fragmentation），接收方重组。分片效率低、丢一片就全废 |
| **IPv6** | 路由器**不分片**，超了直接丢并回 ICMPv6 "Packet Too Big"，由发送方调整 |
| **设置了 DF 标志（Don't Fragment）** | 不分片，超了丢弃 + 回 ICMP "Fragmentation Needed"，这就是 **PMTUD（路径 MTU 发现）** 的机制 |

> **工程上的经典坑**：VPN / 隧道场景下 MTU 变小（比如 IPsec 多 50~70 字节），如果 PMTUD 被防火墙挡了 ICMP，就会出现「小请求正常、大请求卡死」的诡异现象——**TCP 握手成功但传大数据就挂**。

### 1.4.4 解封装：接收方逐层剥离

```
物理层收到比特流 → 组成帧
  ↓ 链路层：检查目的 MAC 是不是我，是就剥掉以太网头，看类型字段（0x0800 = IPv4）
  ↓ 网络层：检查目的 IP 是不是我（或需要转发），剥掉 IP 头，看协议字段（6 = TCP）
  ↓ 传输层：检查目的端口，剥掉 TCP 头，按序号重组
  ↓ 应用层：把字节流交给监听该端口的进程（比如 nginx）
```

**每一层的「检查」就是一次过滤**：
- 链路层看 MAC → 不是我的就丢（除非是广播/组播）
- 网络层看 IP → 不是我的就转发（路由器）或丢弃
- 传输层看端口 → 找到对应进程
- **应用层没有「检查」**，直接交给程序

## 1.5 一次请求的层间流转（客户端 ↔ 服务端）

以 `https://example.com/index.html` 为例，**看每一层各自做了什么**：

| 阶段 | 客户端各层 | 服务端各层 |
|---|---|---|
| **准备** | 应用层：解析 URL、查缓存、调 DNS<br>传输层：分配临时端口（如 54321） | — |
| **DNS** | 应用层：DNS 查询（UDP 53）<br>传输层：UDP<br>网络层：IP（目的 = 本地 DNS） | DNS 服务器同理 |
| **建连** | 传输层：三次握手（SYN，源端口 54321 → 目的 443）<br>网络层：IP 路由<br>链路层：ARP 找网关 MAC | 传输层：SYN 队列 → accept 队列 |
| **TLS** | 应用层（TLS）：ClientHello … Finished | 应用层（TLS）：ServerHello + 证书 … Finished |
| **请求** | 应用层：HTTP 请求 → TLS 加密 → TCP 分段<br>网络层：加 IP 头<br>链路层：加帧头 → 物理层发比特 | 链路层收帧 → 网络层核 IP → 传输层按端口给 nginx → TLS 解密 → HTTP 解析 |
| **响应** | 逆向解封装 | 应用层：生成响应 → 逐层封装 |
| **渲染** | 应用层之上：DOM/CSSOM/渲染树/布局/绘制 | — |

> 这张表的用法：**面试被问「输入 URL 发生了什么」时，就按这张表从上往下讲**，每一层的动作说清，结构感非常强。详见 02 册。

## 1.6 常见坑

| 坑 | 正确说法 |
|---|---|
| **把 TLS 说成「传输层协议」** | TLS 严格说在**会话层/表示层**（OSI 第 5/6 层），实践中被当作「传输层之上的安全层」。说「介于应用层和传输层之间」最稳 |
| **把 ARP 说成「网络层协议」** | 它**介于链路层和网络层之间**，用 MAC 广播查 IP。教材多归网络层，但不是标准网络层协议 |
| **以为路由器工作在网络层就只处理 IP** | 现代路由器也看传输层端口（NAT、防火墙、QoS） |
| **以为交换机只在二层** | 三层交换机也能路由（看 IP） |
| **说「HTTP 是应用层协议所以和 TCP 无关」** | HTTP/1.1 和 2 跑在 TCP 上，HTTP/3 跑在 UDP(QUIC) 上，**应用层的性能瓶颈经常在传输层** |
| **把 OSI 七层当实际实现** | 实际是 TCP/IP 四层，OSI 只是描述工具 |
| **忽略 MSS 和 MTU 区别** | MTU 是链路层的帧负载上限，MSS 是 TCP 的数据上限，`MSS = MTU - 40` |
| **以为 UDP 不分片** | UDP 也会被 IP 分片（而且 UDP 没有 MSS 协商，更容易分片） |

## 1.7 答题模板

### 30 秒版

> OSI 是七层：物理、数据链路、网络、传输、会话、表示、应用。实际互联网用的是 TCP/IP 四层，把会话层和表示层并进了应用层。
> 面试一般说五层：应用层（HTTP/DNS）、传输层（TCP/UDP）、网络层（IP/ICMP）、数据链路层（以太网）、物理层。
> 分层的价值是解耦——每层只依赖下一层接口。最典型的例子是 HTTP/3 把传输层从 TCP 换成 QUIC(UDP)，应用层代码几乎不用改。

### 2 分钟版（加分层）

> 我先说三套模型的对应关系。OSI 七层是理论模型，TCP/IP 四层是工程实现，教学中常用的五层是把 TCP/IP 的「网络接口层」拆成数据链路层和物理层。对应关系是：OSI 的会话层、表示层、应用层合并成 TCP/IP 的应用层；下面三层一一对应。
> 每层的职责：应用层提供网络服务，比如 HTTP、DNS；传输层做端到端（进程到进程）传输，负责端口寻址和可靠性，TCP/UDP 在这里；网络层做主机到主机、路由寻址，IP 在这里；链路层做相邻节点间传输，以太网帧在这里；物理层传比特。
> 一个 HTTP 请求发出去的过程就是逐层封装：应用层产生 HTTP 报文，传输层加 TCP 头（20 字节，含源目的端口和序号），网络层加 IP 头（20 字节，含源目的 IP），链路层加以太网头（14 字节，含源目的 MAC）。所以以太网 MTU 1500 减去 IP 和 TCP 头，MSS 是 1460 字节——也就是一个 TCP 段最多装 1460 字节应用数据。
> 为什么要分层？三个好处：解耦（换 WiFi 为 4G 上层不用改）、独立演进（HTTP/3 换掉传输层）、故障定位（能 ping 通但网页打不开 → 网络层 OK，问题在上面）。
> 最后补一句 OSI 为什么没落地：它标准先于实现、分层太细（会话层和表示层在代码里没法独立实现），而 TCP/IP 是「先跑起来再定标准」，所以赢了。

### 追问表

| 追问 | 回答要点 |
|---|---|
| OSI 和 TCP/IP 怎么对应？ | 上三层合并为应用层，下四层一一对应 |
| 为什么实际用四层不用七层？ | 标准先于实现、分层太细无法独立实现、实现太复杂 |
| ARP 属于哪层？ | 介于网络层和链路层之间（教材多归网络层） |
| TLS 属于哪层？ | 会话层/表示层，实践中视为「传输层之上」 |
| 交换机 / 路由器 / 网关各在哪层？ | 交换机二层（也能三层）、路由器三层、网关可到七层（应用网关） |
| MTU 和 MSS 的关系？ | `MSS = MTU - IP头 - TCP头`，以太网下是 1460 |
| 超过 MTU 会怎样？ | IPv4 可分片（性能差），IPv6 由发送方调整，DF 标志下触发 PMTUD |
| 为什么要分层？ | 解耦、独立演进、故障定位、标准化 |
| PDU 是什么？ | 协议数据单元：应用层报文、传输层段、网络层包、链路层帧、物理层比特 |
| `ping` 用的是哪层？ | 网络层的 ICMP，不经过传输层（所以不能 ping 端口） |

```
三套模型
  OSI 7：物 链 网 传 会 表 应
  TCP/IP 4：网络接口 网 传 应
  教学 5：物 链 网 传 应   ← 面试说这个最稳

每层关键
  应用：HTTP(80) HTTPS(443) DNS(53/UDP) WS
  传输：TCP(20B头) UDP(8B头) QUIC(UDP)

  MTU 1500 → MSS 1460（1500-20-20）
  IPv4 可路由分片，IPv6 不分片

分层价值
  解耦 / 独立演进（HTTP/3 换掉 TCP）/ 故障定位 / 标准化
```
